## 第二轮：首轮没有列出的行为问题

1. **BC-11、BC-18：双缓冲的写后读仍读旧帧。** Core 恢复写 direction 后读 published direction 算 normal；辅助 ManualController 写新速度后由基类读旧速度移动。检查每个读写实际 slot，增加坡道恢复正交性和首个加速 step 的独立断言。正常 tick 的发布测试不能替代恢复路径。
2. **BC-12、BC-13、BC-19：转换丢语义或保留第二份位置状态。** 单一 facing 丢失跨反向接缝的尾端方向；反向曲线 save 委托原曲线；minorDeltaS 在移动、反向、保存中含义不一。沿完整数据链核对每端方向和唯一位置事实，不只做字段 round-trip。
3. **BC-14、BC-15：快照及保存容器的边界不完整。** List 别名可改变已有速度 metadata 快照；不同 plugin slot 的保存 ID 可冲突覆盖。检查嵌套值、copy/serializer 路径及不同身份空间，不能以外层 map 已复制或 slot 不同证明安全。
4. **BC-16：外部 getter 在第一次索引写入后抛错。** 注册后失败对象不在调用方 rollback 列表。列出全部外部可执行代码和写入点，先捕获输入，再提交内部状态；注销使用注册时保存的信息。
5. **BC-17：端点各自合法，中点插值 NaN。** 相反切线/法向量插值为零。检查算法的区间前提，不能用端点校验代替插值可用性，也不能声称正常建轨器已生成该输入。
6. **BC-20：测试让旧算法继续显得有用。** 对比生产真正调用的积分/几何实现与测试目标；将有效行为断言迁到生产路径，而非按测试数量或方法名保留旧实现。

## 第三至六轮：只找运行 bug 会遗漏的工程问题

- **BC-21–24、28–29、31–32：** 注册签名静默忽略、泛型伪安全转换、矛盾结果状态、两个准备阶段混在一个 nullable 模型、无生产者错误分支、重复验证、内部合并异常被归咎于插件、同一对象不可变字段自比较。检查类型状态与实际生产者/消费者，再判断抽象和防御是否有效。
- **BC-25–27、33、35、37–49：** 已迁移状态仍藏在 trait、无消费者的 after-commit 队列、测试命令策略进入 Core 基类、领域类型与包 owner 不匹配、旧 DTO/writer/DI scope 无生产读者。完整工程审查要查依赖方向、公开合同、构建和文档，不能把用户举出的 infrastructure/trait 示例当作范围上限。
- **BC-30、BC-10 补充：** comparator 反复做完整动力学预演；基础 frame/roll 工具归高层 Factory/Solver，重复公式的单位和输入可变性不同。优先消除真实重复计算与错误依赖，不凭文件长度提架构改造。
- **BC-50：** 构造失败清理已经逐项尝试，load 失败清理却仍被 renderer destroy 异常截断，最终 world 注销不执行。对称入口必须逐一检查；普通 destroy 的停机合同不同，不能统一为吞错继续。
- **BC-51：** helper 存在不代表每个调用方正确关闭 world；unregister 不是 close，单独关闭 executor 也不是关闭 world。沿资源创建者、移交者和最终退出路径核对，不能仅搜到 use/finally 就判完成。

## 下一次复审仍发现的边界

- **R01、R02：** 可写 Future 泄漏内部完成权；旧 rail 引用按 UUID 删除新实例。只审成功路径或 ID 相等会漏掉权能与准确对象身份。
- **R03、E02：** 主模块签名迁移漏掉开发插件；源码无 import 不证明编译依赖可删，还要检查公开 ABI 和直接消费者。
- **R04–R07：** 缺省与非法 roll 混同、正无穷进入闭环遍历、同步事件注册接受 suspend handler、BA 容差转换产生负值并逃出 typed result。逐层检查入口接受域与下层前提是否一致。
- **R08–R09：** 自动超高零速误走最大值分支；纵断面重建重新累计弦长，破坏原水平解析距离。组合路径与中间重建同样要保持单位和几何定义，不能只验证原始构造器。
- **E03、D03–D04：** 只读向量/集合仍借用 mutable 输入；恢复只检查轨道存在却漏真实长度；公开生命周期结果不代表全部资源已清理。检查完整值约束、所有构造入口和真实完成条件。
- **F01：** halt 之后还要核资源准入、旧许可进入和定义提交，同时允许诊断、释放和卸载。不按异常类型简单决定局部/全局影响，也不把“停止下一 tick”当作阻止所有新写入。

## 更早的复核补漏与组合案例

- **CR-036：** 原关闭保护挡住最终 world frame，却未保护先前的 controller buffers/train frames/mailbox。真实回归观察到 train epoch 2、world epoch 1。审查每个发布入口和同锁 exact ticket 校验；扩展 hook 留锁外，不能靠锁外 if 消除竞态。
- **CR-037/038：** 环线重复轨道形成嵌套保留区间，按起点排序不保证终点单调；上层阻止暂停时扩展，Basic 公共入口仍可扩展。检查数据结构前提与 owner 自身的状态机合同。
- **CR-040/041：** 坡度×曲率、子组隐藏×平台重建等组合条件暴露距离和有效视图错误。动态贡献依赖另列未完，后来成为 BC-04；不要把某一子项修复扩大为完整配置流程通过。

## 不应重新包装成缺陷的历史候选

复审 C02 mailbox 清理并发、C03 曲线热路径别名、C05 扩展/平台异常安全保留限定；当时未证明具体生产故障。全局 revision 不同不等于依赖失效；同一线程 tick 异常不等于对象并行执行；创建 executor 不证明线程已启动。严守静态可构造、实际调用可达、动态复现和现场观察的区别。
