# 通用模型显示与轨道定位 API

## 1. 这份设计要解决什么问题

本文描述当前已实现（`CURRENT`）的主插件通用模型显示能力：按 UUID 查询轨道曲线、不可变模型定义、完整场景应用，
以及负责跨线程显示和清理的公开模型服务。普通模型 YAML 编译边界已经公开，SimpleSignals的生产信号绑定由其自身模型合同维护。

目标是让 SimpleSignals 等附属插件复用主插件的模型系统，而不必把信号机伪装成列车模型。
这里的“主插件”指 `BukkitPlugin`，不是 SimpleATOBukkit。分工如下：

- 主插件负责普通模型 YAML 的严格编译、构造模型部件、调用现有渲染实现，以及在正确线程上更新和删除模型。
- 附属插件负责安全发现并捕获模型包文本、稳定业务身份、摆放位置，以及业务状态应显示什么外观。
- 资源申请、进路判定、限速和灯色不进入这个通用接口。SimpleATO 和 SimpleATOBukkit 不参与这条显示流程。

接口只提供普通模型的定义和操作对象，不公开整个 `ModelManager`、`CompositeModel`、
可变世界对象或调度器实现类。

`RailTargetService` 提供玩家视线选轨和按 UUID 查询曲线；`ModelPresentationService`提供普通模型显示。
玩家专用临时文字由独立的[EditorTextService](editor-markers.md#首批临时文字-api)提供，不扩充普通模型树或改变本服务的既有行为。
主插件内部的 `ModelTreeBuilder.buildModel` 构造并返回 `OrdinaryModel`，
附属插件不直接调用这个内部入口。旧的部件引用/命名空间普通入口已删除，
不保留草稿兼容；车体和转向架继续走各自的配置与专用入口。

## 2. 一次正常显示经过哪些步骤

附属插件通过公开服务完成以下流程，不需要自行操作显示实体：

1. 附属插件在 worker 上安全读取并捕获模型 YAML，调用宿主公开 compiler 解析普通模型、展开引用并检查场景；编辑摆放位置不重读模型。
2. 它按轨道 UUID 查询曲线，再根据轨道上的位置，计算模型的世界坐标和朝向。
3. 它向主插件申请一个 `ModelHandle`。这个对象用于提交显示状态和关闭模型，此时还不创建实体。
4. 第一次提交有效状态后，主插件安排模型实体的创建。以后只提交发生变化的显示状态。
5. 模型被删除、世界被卸载或插件被停用时，关闭 `ModelHandle` 并清理实体。

提交后无需等待画面更新完成。铁路物理和信号计算也不等待 Minecraft 的显示线程。

现有列车仍使用车体、转向架专用入口。它们与新增普通入口复用内部部件构造代码；
驾驶座、转向架偏移和车轮装配仍留在列车入口。底层继续使用已有的 NATIVE 或 ENTITYLIB 渲染实现。

## 3. 定位和更新是如何实现的

### 按轨道位置定位，不重新搜索轨道

查询时已经有世界 UUID 和轨道 UUID，因此直接查找对应轨道，返回其不可变曲线。
不需要扫描附近轨道、重新寻路、重新生成曲线，也不能从没有空间坐标的 `TopologyState` 推测模型位置。

`WorldManager` 在世界加载成功后把它登记到按 UUID 查询的索引；卸载开始时撤回，停止时清空。
原来的 Bukkit 世界对象表仍负责卸载过程，这个索引只服务快速查询。撤回时同时比较世界实例，
旧世界的清理不能删除同 UUID 新世界的索引。索引只在加载/卸载时维护，不每 tick 重建。
找到世界后使用 Core 已有的 `getRail`，它在该世界的读锁内按轨道 ID 查询。

位置统一表示为“沿 A 到 B，从 A 端量起的弧长”，单位是米。调用 `curve.getPointAt(s)` 即可得到
该位置的坐标、切线和法线，沿用 Core 的二分定位和插值算法。模型朝向 BA 时，只改变朝向，
不把保存的位置改成 `轨道长度 - s`。模型保持竖直还是跟随轨道倾斜，由附属插件配置决定。

### 复用部件树，不引入列车行为

附属插件可以直接构造公开定义；对于 YAML 包，主插件的公开 compiler 接收已捕获的文本，解析部件引用并检查循环引用，返回已经展开的不可变容器/物品树。
普通模型不需要 `CarDefinition`、`Car`、驾驶座控制端或转向架装配信息。

当前内部 `buildModel` 将容器映射到既有 `DummyModel`、物品叶子映射到 `DisplayModel`，复用
`ModelState` 变换和 `CompositeModel` 显示层次。它使用明确的渲染后端和目标 Bukkit 世界，
不让普通定义经过列车配置解析或附加驾驶座/碰撞行为。列车的配置递归、动画播放、车体/转向架入口不变。
这个内部入口不自行调度；涉及实体的构造和更新仍必须由调用方在正确的目标线程执行。

创建操作对象时，`OrdinarySceneIndex` 按动画名与场景名建立部件路径/关键帧索引，不需要创建实体。
`OrdinaryModel` 复用这份索引，把路径对应到实际部件；提交时先校验完整场景 Map，
确定每个部件最多命中一帧，再对旧、新命中部件的并集设置帧或恢复基础状态。
根位置和选择均未改变时直接返回；有变化时调用既有组合模型更新。场景变化会强制刷新部件变换，
不能因为根旋转未改变就遗漏灯罩等局部位置的更新。
普通场景直接持有精确的公开帧，不调用列车的别名解析或时间轴播放，也不登记动画 tick。

### 来不及显示的旧状态可以被替换

每个模型最多保留一个已安排或正在执行的更新任务，以及一份最新待显示状态。
新提交替换尚未处理的状态；当前任务完成后，再处理当时最新的状态。不会积累一串历史画面逐个回放。

如果位置、旋转和动画场景都没变，就不调用实体更新。模型关闭后，旧任务即使才被执行，也不能重新创建实体。
显示时先显示子部件、再显示根对象；隐藏时顺序相反。重复关闭不会重复清理。

`submit` 只校验并保存值。首次唤醒先进入异步调度，再交给目标位置或实体线程，
避免已有调度器“当前就在目标线程便直接执行”的行为让提交者承担实体构造。
状态锁只保护最新值、显示序号和关闭标志；不在这个锁内生成、更新或删除实体。
模型根位置改变时，先在旧位置完成删除，再在新位置重建；不假定同步实体传送可以跨 Folia 区域。
玩家可见范围复用 `RenderChunkManager` 的附近对象索引；玩家显示/隐藏操作仍交给玩家所属线程，
不为普通模型增加逐 tick 的全玩家扫描。

## 4. 公开接口与数据

已实现的公开接口属于既有 `RailTargetService`：

```java
Optional<PrimeCurve> findCurve(UUID worldId, UUID railId);
```

显示服务及操作对象：

```java
interface ModelPresentationService {
    ModelHandle create(Plugin owner, UUID worldId, String objectId,
                       ModelDefinition definition);
    CompletionStage<Void> closeOwner(Plugin owner);
}
interface ModelHandle extends AutoCloseable {
    void submit(ModelPresentation presentation);
    void close();
}
record ModelPresentation(long revision, ModelPose transform,
                         Map<String, String> animationScenes) {}
```

`findCurve` 返回不可变曲线。轨道不存在时返回 `Optional.empty()`；世界未加载或未注册时抛出
`IllegalStateException`，与现有世界查询的行为一致。保留下来的旧曲线仍可读取，但不能据此认定
重新加载后的世界仍有这条轨道。实现必须使用线程安全的查询入口，不能直接跨线程读写轨道集合，
也不能让物理计算停下来等待 Bukkit。
卸载开始后发起的新查询会失败；已经取得旧世界引用的查询可以完成并返回旧的不可变曲线。
这不是延长旧世界的运行授权，也不保证轨道在返回后仍存在。

`ModelHandle` 是操作一个模型的对象：`submit` 提交最新状态，`close` 关闭模型。
`create` 只创建这个操作对象；第一次有效提交才安排创建实体。`submit` 返回不代表画面已经更新完成。
`closeOwner` 关闭该插件的全部模型，并返回清理完成结果；其中也包括此前单独调用 `close()`、
但实体尚未删除的模型。调用方必须先停止创建/提交模型，不能一边卸载一边新增模型。
服务不会因此永久封禁一个仍启用的插件，也不引入启用周期 token。
创建时按插件实例、已加载世界实例和 `objectId` 识别模型，拒绝同一身份下仍活动的重复对象。
关闭后的同名替换取得新操作对象；旧对象的清理只能移除旧对象，不能误删新对象。

创建模型时的两个参数需要明确：

- `objectId` 是附属插件内部的稳定名称，便于定位错误；不能用同名对象绕过关闭和替换规则。
- `ModelDefinition` 是解析完成的部件树、模型资源引用和动画定义，不是文件路径、YAML 文本，
  也不包含仍会被修改的 Bukkit `ItemStack`。下文是当前值类型，不另造一套重复的列车配置加载系统。

### YAML compiler 与已经展开的部件树

`ModelPresentationService` 仍只接收已经展开的 `ModelDefinition`。附属插件可以直接构造它，也可以把已经安全读取的
`ModelAssetYamlSource` 集合交给 `ModelAssetYamlCompiler`。compiler 不接收文件路径、读取回调、世界对象或任意脚本，
因此可在 worker 执行，显示时也不会重新查配置。它严格解析普通 YAML、展开引用、拒绝循环并校验默认/命名场景，
返回不可变 `CompiledModelAsset`（定义、default、variants 与宿主中立摆放 metadata）。

`SHARED_PARTS` 模式供既有 `manifest.yml/models/parts` 包使用；import 只解析提供的 shared-part sources。
`MODELS` 模式供统一包使用；import 解析同一 compilation 内另一 model ID，只把目标 parts 树作为 identity-pose
`Group` 子树导入，目标的 default、variants 和 placement 不继承。两种模式都完整解析并校验所有输入；首批不支持
跨包 model import。调用方先做安全路径/符号链接检查，再传入稳定 source name 以取得精确诊断。

值类型位于 `work.art1st.javarailways.bukkit.api.model`。下面列出当前构造参数；所有列表在入口复制为只读集合，
数值、名字、时间和资源键由构造器校验。这不是 YAML 或存档格式：

```text
ModelDefinition(List<ModelPart> parts)
ModelPart.Group(ModelPose pose, List<ModelPart> children, List<ModelAnimation> animations)
ModelPart.Item(ModelPose pose, ModelScale scale, ItemAppearance appearance, List<ModelAnimation> animations)
ModelPose(double x, double y, double z, double rotationX, double rotationY, double rotationZ, double rotationW)
ModelScale(double x, double y, double z)
ItemAppearance(Material material, String itemModelKey, Integer customModelData, ItemAppearance.Brightness brightness)
ItemAppearance.Brightness(int block, int sky)
ModelAnimation(String name, List<ModelAnimation.Frame> frames)
ModelAnimation.Frame(double atSeconds, String scene, ModelPose pose, ModelScale scale, ItemAppearance appearance)
```

`ModelPose` 的位置/增量使用米，旋转采用四元数 x/y/z/w；基础姿态使用 `ModelPose.IDENTITY`。
所有分量必须有限，四元数平方长度与 1 的绝对误差不超过 `1e-9`；不静默归一化。
`ModelScale.UNIT` 表示单位缩放。帧的 pose 是在基础位移/旋转上叠加的值，scale 是物品缩放系数。
构造参数需要显式给出，不为 null 姿态或列表自动补配置默认值。
外观使用明确的现代 Bukkit 物品 Material，也允许 AIR 表示空物品；拒绝旧版材质和非物品材质。
AIR 没有可显示的物品组件；即使定义给出模型键或 CMD，也仍为空物品，不承诺这些覆盖留在空 ItemStack 中。
资源键、整数 CMD、亮度可以为 null。亮度分量必须在 0..15，
null 表示自然光。帧 appearance 为 null 时使用物品基础外观；帧 scene 为 null 时不声明场景标记。

这里不包含车体、驾驶座、控制端、转向架、车轮或车辆脚本。容器和物品都是普通模型节点，
不需要为了普通模型再创建一套列车对象。需要让某个物品和其他部件一起运动时，
把它们放在同一个容器下；物品是叶子，容器负责共同的位移和旋转。
公开数据只使用标量、不可变值类型和只读集合；不能把可变 JOML 向量、`ItemStack` 或配置对象直接保存进去。
集合在值类型入口复制一次；同一份不可变定义可以供多个模型复用，不在每次提交场景时重新复制整棵树。

### 变换顺序与缩放范围

保留现有模型的位移和旋转合成方式。现有 `CompactTransform` 会相乘父子缩放，
却不会用父缩放放大子偏移，不能宣称它是一般的仿射树。
公开树只让物品叶子配置缩放，使容器缩放恒为 1，避免把这套不完整的父缩放语义带入新 API：

```text
部件当前位置 = 父位置 + 父旋转 × (基础位移 + 当前帧位移增量)
部件当前旋转 = 父旋转 × 基础旋转 × 当前帧旋转
物品当前缩放 = 基础物品缩放 × 当前帧缩放系数
```

子部件跟随父部件的当前位置与旋转，但不会因为父物品放大而扩大自己的偏移或大小。
缩放允许零以隐藏物品，拒绝负值和非有限数值。容器帧只能改变位移和旋转，不能改变物品外观或缩放。
根姿态复用 `ModelPose`，只包含世界位置和旋转；本批不承诺整体缩放，不把当前忽略根缩放的行为包装成支持。
从已有包的欧拉角转换时由附属插件完成单位和顺序转换，公开树本身不混用度、弧度和四元数。

资源键必须保留完整命名空间；`javarailways:signals/lamp` 不能变成
`minecraft:javarailways:signals/lamp`。数字 CustomModelData 沿用当前渲染能力，转为 float 时必须能精确表达，
否则在准备定义时拒绝，不能悄悄改变所引用的客户端模型。服务器不尝试读取客户端资源包来证明资源存在。

### 场景选择是完整状态，不是增量命令

内部场景应用使用 `动画名 -> 场景名`，允许同名动画分布在不同部件：例如两个灯罩都声明 `lamp`，
提交 `lamp -> green` 就同时选择它们各自的 green 场景。每个命中的动画都必须定义该场景，
不能只更新一部分部件。同名动画必须有相同的场景名集合，但帧时间、变换和外观可以各自不同。
一个部件内的动画重名必须拒绝，不能沿用当前 `toMap` 静默覆盖的行为。
动画名与场景名是非空白字符串，按原字符串精确匹配，不隐式转小写或加入 `o/c` 等旧列车别名。

同一次提交可以选择不同部件上的多个动画；如果某个部件同时命中两个选项，则拒绝整次提交。
这避免结果取决于 Map 遍历顺序，不在首批接口中引入多个动画的混合权重或组合规则。

场景名定位到标记它的关键帧，并持有那一帧的状态，不表示重新播放时间线。帧的时间采用秒，
首帧为 0，后续时间严格递增且为有限数值。帧选择复用当前场景机制；本批不新增循环、缓动或任意播放命令。
现有插值机制是位移/缩放线性插值及旋转 slerp，不能在公开定义里虚构已受支持的 easing/loop 参数。

每次提交描述全部选择：每个部件取本次唯一命中的动画帧；没有命中任何选项的部件恢复基础状态。
如果同一部件还有别的动画未被选择，不再单独对那些动画执行一次复位。空 Map 将所有部件恢复基础状态。
物品外观和亮度也要完整恢复，不只是停止动画或清空动画名称。
帧中的 appearance 省略时取部件基础外观，不继承上一个场景；显式外观中的空资源键、空 CMD 和空亮度
分别表示清除这些覆盖，不能解释为“不修改”。如果仅显示序号更新而位置、旋转和场景选择完全相同，
不重新启动动画或更新实体；位置变化仍需要更新模型。

例如先提交 `lamp -> green`，再提交空 Map，灯的材质、模型资源、CMD、亮度和局部变换都回到基础定义，
不能只让灯的位置复位而继续显示 green 的物品。主插件不解释这些场景对应什么信号含义。

创建时，主插件按动画名建立命中部件与场景的索引；提交时先验证全部选择、确认每个部件最多命中一项，
再计算需要改变的部件状态。非法选择不覆盖上一份有效待显示状态，也不会先更新部分实体。
以上校验与完整复位已经在值构造器和内部 `OrdinaryModel` 实现。非法输入在任何模型状态修改之前拒绝；
后端执行异常则不承诺跨实体事务回滚，后续操作对象负责清理和报告，不影响行车授权。
物品外观变化时根据完整目标值新建 ItemStack，不克隆带有上一种场景组件的物品；因此空模型键/CMD
确实移除覆盖。恢复自然光时 NATIVE 清除亮度值，ENTITYLIB 使用其协议的无覆盖值 -1，而不是固定 (0, 0)。

### 静态模型不沿用列车的三 tick 插值

普通构造为根对象和物品设置零变换插值、零位置/旋转插值，以及零 delay：在目标线程真正处理时直接应用当前场景，
不额外加入平滑过渡。列车专用入口仍保留原来的三 tick，不随新 API 改动。
本批不增加尚无具体需求的公共插值配置字段；零插值也不表示主插件能立即取得目标线程。

`ModelPresentation` 包含：

- `transform`：世界位置（米）和旋转（单位四元数），数据提交后不能再修改。部件缩放仍在模型定义中配置。
  接口不承诺整体缩放，因为现有 `CompositeModel.updateState` 没有将根对象的缩放传给部件。
- `animationScenes`：为每个动画选择一个场景，即 `动画名 -> 场景名`。它复用现有模型机制，
  不是新增一个全局场景系统。每次提交描述完整选择，不是只修改几个条目；按上面的规则广播到匹配部件，
  未命中任何选项的部件完整恢复基础状态，同一部件不能同时选择两个动画。
- `revision`：这个模型内部递增的显示序号，用来丢弃旧更新。不参与物理周期、拓扑版本或存档版本。

## 5. 线程、关闭和世界重载的规则

公开定义是不可变值，可以在工作线程构造和复用。公开 `ModelHandle` 负责状态合并和调度；
内部 `OrdinaryModel.submit` 则直接更新模型，只能在正确目标线程执行，不能公开给附属插件代替 handle。

提交的数据不能在异步处理期间被调用方修改，包括其中的向量、映射和配置。
`create`、`submit`、`close` 只操作模型管理状态，不直接读写 Bukkit 实体或世界，也不等待显示任务结束。
真正的生成、移动、场景切换和删除，由主插件安排到目标位置或实体所属的线程。
在 Folia 中不能统一称它为“主线程”；跨区域更新也必须遵循既有的目标线程调度规则。

关闭模型时丢弃待处理状态。附属插件停用、世界卸载、主插件关闭时，都要关闭相应模型。
同一个 UUID 的世界重新加载后，是新的世界实例，旧 `ModelHandle` 不能继续使用。

**卸载顺序已确定：先卸载附属插件，完成其模型清理，再卸载 JavaRailways 主插件。**
实体删除可能要交给其他区域线程，因此附属插件的 `onDisable` 返回不等于清理完成。
显示服务必须提供非阻塞的清理完成结果；停用主插件的一方先确认该结果成功，再停用主插件。
等待不能阻塞物理线程或 Minecraft 区域线程，也不新增轮询式卸载管理器。
主插件停用后不能依赖它的调度器继续删除实体。绕过顺序的强制停用应报告未完成的清理，
不能将被平台取消的任务当成清理成功；普通模型实体保持不持久化，但这不替代正常清理。

关闭显示模型不等于释放列车占用的资源；插件能否停用仍由既有资源管理规则检查，这里不增加另一套停用协议。
显示失败只记录所属插件和对象的错误，不改变行车授权，也不能让信号计算回调因为显示错误而失败。
本批不改变存档格式，不新增旧数据兼容逻辑。

## 6. 遇到错误时怎么办

输入错误在接受新状态前拒绝；渲染失败清理已创建部分并报告，不承诺跨实体事务回滚。

- **找不到轨道或世界：** 拒绝这次摆放，不能改绑到另一条轨道或另一个世界。
- **坐标、旋转或模型引用不合法：** 拒绝创建或提交，不能留下只创建了一半的模型。
  坐标必须是有限数值，旋转必须是有效的单位四元数。
- **模型已经关闭，或者提交的是旧显示序号：** 忽略更新，不重新创建，也不回放旧状态。
- **目标实体已失效、世界已卸载或渲染实现创建失败：** 清理已创建的部分并记录错误，信号安全输出不变。
- **模型删除失败：** 仍尝试删除其他部件，清理完成结果异常结束。之后再次调用 `closeOwner` 仍能看到这次失败，
  不能因活动列表已不包含该模型而返回成功。显示失败但实体全部清理成功时，只报告显示错误，不阻止正常卸载。
- **缺少已引用的本地定义、场景或资源键非法：** 配置验证时拒绝，不自动用石头或虚构灯色代替。
  作者可以明确选择普通 Material 而不设置自定义模型键或 CMD；这与错误后的静默替代不是一回事。
  服务器只能检查本地定义和资源引用的格式，不能保证客户端已经安装资源包。
- **部件内动画重名、关键帧时间无效或同一部件同时选中两个动画：** 拒绝定义或整次场景提交，
  说明具体部件路径、动画和场景；保留上一次有效待显示状态。未知动画和任一命中部件缺场景同样拒绝。
- **亮度越界、缩放为负或 CMD 转换会失真：** 准备定义时拒绝，不裁剪成另一个有效但错误的值。

## 7. 性能开销在哪里

按轨道 ID 查询的目标是 `O(1)`。按弧长采样沿用 Core 的 `O(log N)` 定位，再做常数次插值，
其中 N 是这条曲线的采样点数。这些操作只用于加载、摆放或相关编辑，不每 tick 重算所有模型的位置。
当前查询有 UUID 索引和轨道表两次按键查找，可能短暂等待该世界的拓扑读锁；不是无锁查询，
但不扫描世界，也不等待 Bukkit 任务或取得跨世界物理锁。

设捕获 YAML 总字节为 B、引用数为 R、实际展开/校验访问的部件数为 P、动画数为 A、帧数为 F，
解析、引用展开、场景索引与构造成本为 `O(B + R + P + A + F)`；递归引用使用 active path 检测环，
每个无参数共享 subtree 只构造一次。
读取文件、解析和展开大量配置应在工作线程完成，不能占用物理线程或 Minecraft 区域线程。
创建时同时建立动画/场景索引；不在每次提交时重读模型包、搜索引用或重新遍历全部帧。

比较一次场景选择需要 `O(S)`，S 是场景映射的条目数；校验还需要访问这些选择命中的动画数 H，成本为 `O(S + H)`。
恢复基础外观的候选是上一次与本次命中部件的并集；真正更新位置时仍需遵循部件层次。
复用当前递归模型更新时，最坏为 `O(P)`，不能据此承诺已经实现局部子树更新或说每次更新都是 `O(1)`。
内部模型只保存一份完整选择和命中帧，不保存历史更新队列。普通场景是持有帧，
不登记逐 tick 动画计算；列车的既有时间轴仍有自己的计算开销。服务调度拥塞可以让画面暂时滞后，
但不能让铁路物理等待。

根位置移动采用删除和重建，成本为 `O(P)`，适合摆放、编辑后的静态模型，不应拿它代替列车移动渲染。
`closeOwner` 在低频卸载时筛选尚未清理完的模型并合并完成结果，查找为 `O(M)`，M 是服务中待清理/活动模型数；
不在每次信号更新时执行，也不持有物理世界锁等待删除。后端对同一个显示对象的显示/隐藏/销毁做短同步，
避免玩家刚开始看到模型时模型已被删除；这把锁不参与 `ModelHandle.submit`。

## 8. 具体使用情形

以下情形说明公开显示服务应保持的行为：

- **首次显示：** 附属插件创建操作对象并提交初始状态；主插件创建多个模型部件，按规定顺序显示。
- **短时间连续变化：** 信号规则连续要求显示 Y、YG、G。如果显示任务尚未处理这些待更新值，
  最后只需显示 G。这只合并画面，不跳过信号系统自身的安全状态处理。
- **外观没有变化：** 限速变化，但位置和场景选择相同，模型不更新。
- **删除后旧任务才执行：** 模型已关闭，旧任务不得使它重新出现。
- **世界重新加载：** 即使 UUID 相同，旧模型也不能更新新世界中的对象。
- **卸载附属插件：** 停止产生新画面，关闭全部模型；即使 `onDisable` 已返回，也要等清理完成结果成功后才能停用主插件。

## 9. 实现时必须验证什么

- 用独立 Java 调用示例编译公开 API，确认附属插件不需要导入主插件实现类，也不把主插件类打进自己的 JAR。
- 用捕获文本分别验证 shared-parts/model import、循环、缺失引用、非法 variant、结果不可变及编译后不访问文件。
- 检查缺失轨道、未加载世界、AB/BA 朝向，以及轨道删除后旧曲线仍可读取；定位不得调用最近点搜索或寻路。
- 检查多部件构造、局部变换、资源引用和场景切换；确保旧外观的场景不残留，现有列车构造仍正常。
- 检查同名动画跨部件广播、部件内重名拒绝、缺场景和动画冲突的整次拒绝，以及空 Map 的完整复位。
  特别断言材质、namespaced 模型资源、CMD、亮度和变换不残留；相同选择不重新启动动画或更新实体。
- 检查容器旋转/位移带动子部件、物品仅作为叶子、容器缩放恒为 1、零物品缩放可用与负值拒绝。
  关键帧采用绝对秒数，CMD 可精确转换；普通模型使用零插值，而列车入口仍保留三 tick。
- 检查只保留最新待显示状态、相同外观不更新、重复关闭、插件停用、世界卸载/重载和部分创建失败的清理。
- 两种渲染实现都要验证目标线程和显示顺序。另在实际 Folia 服务器与资源包上检查可见效果，
  模拟调度器的测试通过不等于玩家实际能看到正确模型。

当前基础回归使用真实 `BukkitRailTargetService`、世界索引和 Core 轨道，验证异步查询、AB/BA、
轨道删除后读取旧曲线、撤回/同 UUID 重载和停止清理。构造回归验证部件层次、局部变换、动画选择，
以及车体与转向架分离、转向架纵向偏移不重复应用，不证明驾驶座事件和控制行为。
`ModelDefinitionTest` 验证各级列表复制、数值与命名校验；`OrdinaryModelTest` 使用真实 builder、
通过正常 Paper Bootstrap 初始化的真实 ItemStack 组件，以及记录显示操作的后端，验证完整外观/变换复位、
同名广播、整次拒绝、调用方 Map 修改隔离和相同状态零实体操作。
`ModelTreeBuilderTest` 另断言车体/转向架根与物品保留三 tick，旧列车模型键行为不变。
`DisplayAppearanceBackendTest` 调用真实 Native adapter 和替身实体，验证完整物品替换与 nullable 亮度；
EntityLib 部分只验证真实 ItemDisplayMeta 的 -1 自然光/0 固定黑暗语义，不证明完整 visual 调用或客户端收包。
测试不通过反射改生命周期标志，也不为测试初始化不可清理的 EntityLib 全局运行环境。
`DefaultModelPresentationServiceTest` 连接真实 service、builder、场景值和 `RenderChunkManager`，
用可控调度器及记录后端验证最新状态、位置变化重调度、关闭完成、同名替换、插件停用、同 UUID 世界重载，
以及部分创建、实体删除和玩家显示调度失败。测试中的两种 affinity 模式只表示是否有实体线程归属，
不能据此称已测试完整 Native/EntityLib 实现。暂停实体构造时，另一线程的 `submit` 和 `close` 必须先返回；
暂停玩家可见列表登记时删除模型，再恢复旧任务，必须没有实体复活或残留可见列表条目。
实际 Folia 服务器与客户端画面仍需单独验证；模拟调度不能证明跨区域显示或停服时的平台行为。

## 10. 已决定的方向和仍需讨论的细节

已决定复用通用部件构造和现有渲染实现，保留列车专用入口；信号含义、包发现和稳定信号身份仍归 SimpleSignals，
普通模型 YAML 语法与编译归 BukkitPlugin 公共边界。
已展开部件树、完整场景选择与基础状态复位已获用户批准，并实现了公开值类型和内部应用。
普通静态模型固定零插值；公共插值配置与时间轴播放留待出现实际需求后审查。
信号包的 JS/一等 signal 格式以及摆放信息如何保存由信号插件规定；通用 compiler 只返回宿主中立 placement metadata。

不要把信号包伪装成车体，也不要要求附属插件直接调用 `BukkitPlugin.INSTANCE.modelManager`。
应公开只负责普通模型的操作对象和定义类型，在主插件内部复用现有构造代码。

列车配置入口仍允许交互、驾驶座和站台碰撞部件，列车的场景方法仍只覆盖给出的条目。
不能直接把列车入口公开，然后声称已经满足普通纯显示和完整复位规则。
新定义只接收上述容器/物品值，复用私有构造和渲染机制；完整外观复位由渲染层正确清除
资源组件与亮度覆盖，不是在附属插件外面叠加一层“恢复旧动画”回调。
本批不迁移列车/车厢包或轨道包，不改变任何存档，不修复旧配置解析和时间轴播放的其他问题，也不添加草稿兼容；
这些专用 package loader 若以后采用公共 compiler，必须另行审查其专有字段与兼容边界。

`api/rail/RailTargetService.java`、`api/internal/JavaRailwaysServiceRegistration.kt`。
