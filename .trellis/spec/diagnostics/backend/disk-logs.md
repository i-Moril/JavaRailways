# 固定来源的磁盘日志查询

## 范围和数据流
Diagnostics 的 `DiskLogReader` 为已登记的文本日志提供只读查询；CURRENT 源码实现，本地与线上验证状态以任务验收记录为准。登记来源的模块拥有路径，HTTP 客户端只提交来源 ID。Bukkit bridge 在 HTTP worker 上查询宿主/附属插件文件；独立 WebUI 使用同一 reader 查询自身日志并代理宿主查询。没有数据库、后台全量索引或世界状态访问。

## 读取与分页机制
每个来源包含当前文件和同目录 `.1` 文件，逻辑上先旧后新。首次查询固定文件身份和当时大小，从末尾向前读；后续游标保留首次大小，不把之后追加的字节混进旧页。文件身份使用文件系统 fileKey 与 creationTime，游标关联来源与查询条件。轮转、替换、缩短或读取期间发现身份变化会返回 `reset=true`，调用者刷新后重新开始，不能把不同文件内容无声拼接。

一次扫描最多 512 KiB，查询按读取窗口执行，不保证一次请求搜索全部历史。正常多行事件按 `[time] LEVEL module=...` 行头对齐边界，保留消息和异常链；单条超长事件及非标准文本使用明确标记的部分片段。下一页继续更早的字节，空匹配页仍可能有 `nextCursor`。UTF-8 页边界不得破坏后续字符或跳过字节。记录按新到旧展示，单条内部栈顺序不变。

## 接口
`DiskLogReader(Map<String, Location>)` 接收不可变来源表；`Location(label, path)` 不接受请求拼接路径。`sources()` 返回 `Source(id,label,available)`；`available` 表示当前或轮转文件有内容。

`read(source, query, cursor)` 返回：
- `source`：来源 ID。
- `entries`：`text/module/level/time/partial`，未识别结构化头时元数据可空，原始文本仍保留。
- `nextCursor`：更早页游标或 null。
- `reset`：旧快照无效，需要刷新。
- `scannedBytes`：本次实际扫描窗口的字节数。
- `retention`：保留窗口说明，不承诺永久历史。

查询文本最多 200 字符，大小写不敏感；游标最长 512 字符，内容包含关联摘要、两个快照大小和位置，非法编码或数值拒绝。摘要用于识别查询快照，不是认证令牌。来源清单负责访问控制，文件路径不出现在来源 DTO 中。

## 生命周期、失败和成本
读取不修改文件、writer 或任何世界状态；每次请求独立打开并关闭 channel，不持有长期 FD。只允许普通文件，最终文件不跟随符号链接；登记路径及父目录由可信配置/部署所有者控制。缺失文件返回可解释的空内容；未知来源或非法参数为输入错误；实际 I/O 失败向上传播，不能伪装成“没有错误”。

扫描及内存成本随有界窗口增长；结果按文本行头解析，不反射类型、不执行日志内容。浏览器必须以文本渲染。写入中的最后一条可能不完整，返回 `partial`；单条超大栈不得以完整记录名义静默截断。错误查询本身失败不递归尝试读取日志，也不在物理线程等待。

## 场景与必测断言
- 原始 Throwable/cause/suppressed 落盘后，普通事件跨分页仍完整关联。
- 仅有旧文件、没有日志、追加后的旧游标、轮转后的旧游标、UTF-8 与超长行、查询无命中但仍有下一页均有明确结果。
- 未登记路径/来源、异常游标、非普通文件、实际读取失败不得作为成功的空页。
- 来源级 I/O 故障与宿主桥接故障须在 WebUI 可见；不能因远端不可用遮蔽健康的本地来源。

## 格式与职责边界
继续读取现有文本文件；新增 thread 等信息不建立开发版本 reader，也不改变世界存档 schema。世界问题是当前内容状态，不是日志索引。错误做法是从日志推导/重建世界问题，或把用户传入路径交给 reader；正确做法是生产者明确上报内容状态，HTTP 只选择预先登记来源。
