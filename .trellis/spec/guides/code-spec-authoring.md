# 可执行契约编写规则

## 适用范围

新增或实质修改模块、跨层 API、基础设施、数值算法、并发模型、缓存、索引或存档格式时，使用本规则。
契约不只是接口清单：它要让不了解实现的人理解模块如何工作，以及重构时必须保留哪些内部原理。

## 必需结构

对上述涉及关键行为的主题，技术规范至少覆盖以下内容：

1. **状态、范围与触发条件**：说明哪些已经实现（`CURRENT`）、只是目标（`TARGET`）或处于迁移中（`TRANSITIONAL`），列出负责模块和不处理的事项；
2. **模块工作方式**：用一次正常操作说明输入从哪里来、哪些状态具有最终决定权、经过什么处理、向上下游输出什么；
3. **内部机制与关键算法**：描述决定正确性或性能的表示、算法步骤和成立前提；
4. **接口、数据结构与单位**：只把已经冻结的字段写成目标签名，概念草图必须显式标注；
5. **必须保持的规则与生命周期**：说明操作所属线程、结果何时对读者可见、版本号或计算周期的用途、缓存何时失效，以及失败后保留什么状态；
6. **校验与失败处理**：说明拒绝条件、错误或结果类型，以及失败时哪些状态允许改变；
7. **性能与退化行为**：说明复杂度、高频执行部分、候选数量上限、数值容差、迭代上限，以及不能正常执行时的安全行为；
8. **具体使用情形**：用正常流程、优化场景、异常与边界场景说明行为，不必照搬 `Good/Base/Bad` 标签；
9. **必需测试与断言点**：覆盖算法边界、失败原子性和性能不变量；
10. **迁移与待决定事项**：区分已经决定的约束和仍待讨论的实现，用具体例子说明哪些做法应避免、应如何处理。

已有规范不必仅为统一标题而机械重写；修改其中的关键机制时，必须补齐相关内容。

## 可读性要求

以上十项是必须覆盖的内容，不是必须原样复制的标题。规范要让读者不翻源码也能理解流程，
不能只是把接口名和英文术语拼在一起。

- 开头先说明解决什么问题、目前是否实现、由哪个模块负责；不要用状态标签代替解释。
- 先讲一次正常操作经过哪些步骤，再讲保证正确性和性能的内部原理。异常处理不要打断主流程。
- 中文正文使用自然中文；保留必要的代码标识符和标准术语，第一次出现时解释含义。
  例如 `ModelHandle` 应说明是“用于提交显示状态和关闭模型的操作对象”。
- 每个约束说清谁在什么情况下做什么。涉及关闭、过期、准备、提交或恢复时，必须指出对象，
  不能只写“检查 lifecycle/revision 后 cleanup”之类缩略句。
- 抽象机制至少给一个具体例子。把正常流程、优化情形、异常和边界写成有内容的标题，
  不用 `Good/Base/Bad` 或 `Wrong/Correct` 代替情形说明。
- 保留精确签名、单位、复杂度、拒绝条件和测试断言；提高可读性不等于删除技术约束。
  已实现、仅有草稿和待决定事项必须始终分开。

例如，“per-handle latest-only dispatch”应写成“每个模型只保留一份最新待显示状态；
显示线程尚未处理的旧状态可以被替换”。代码中的类型和函数名仍按原名保留。

## 什么内部原理必须记录

满足任一条件就必须简述：

- 替换后可能改变业务或安全正确性；
- 决定渐进复杂度、hot-path成本或内存规模；
- 包含数值容差、插值、搜索、迭代上限或退化分支；
- 决定线程可见性、结果的原子替换、失败回滚或异常时禁止放行的行为；
- 使用缓存、索引、派生图，或根据版本变化判断缓存失效；
- 表面相似的实现会产生不同结果，例如“左侧区间”与“最近采样点”。

每个机制至少回答：内部数据怎样表示、算法如何执行、依赖什么前提、复杂度如何、失败或退化时返回什么、
由哪些测试保证行为。不要记录可以自由替换且不影响契约的私有细节，例如普通局部变量名或集合实现。

## 文档归属

- 模块或层级规范负责实现机制和必须保持的规则；
- 任务 `design.md`只说明跨模块流程、关键取舍和迁移顺序，并链接负责该机制的规范；
- `prd.md`只保留目标、需求、验收和非目标；
- `implement.md`只保留批次、依赖、验证和完成状态。

同一算法或错误语义只在owner spec完整定义，其他文档用链接和一句上下文引用，不能复制出多份会漂移的合同。

## 审查清单

- [ ] 新人不读源码能否说明一次正常请求如何经过模块？
- [ ] 能否指出至少一个不能用“看起来等价”的实现替换的算法步骤？
- [ ] 是否写明算法前提、复杂度和退化行为？
- [ ] 已实现、目标草稿与迁移中的内容是否可区分？
- [ ] 任务文档是否链接负责该机制的规范，而不是复制一份？
- [ ] 占位描述是否标成概念草图，而没有伪装成已经确定的 API？
- [ ] 是否用自然语言说明术语、操作对象和正常流程，而不要求读者先理解缩略标签？
