# 保护区域自动生成最短进路

## 范围与状态

已实现并通过独立离线检查。SimpleSignals 负责新保护区域的自动进路表与多通路警告。
只使用已有 Core 拓扑、Basic 公共运营方向、私有进路表和定义事务，不修改宿主 API 或存档形状。
自动生成只发生在新区域第一次完整闭合；修复已有区域继续保留玩家原来的表及设备。

统一区间工具识别为保护区域后才进入本流程。平面交叉只使保护范围必须包含各冲突腿，不增加可行驶连接；两条双向交叉轨道由四个边界围合时，生成各轨道双向直行的四条进路，不能跨线转弯。完整围合方法归[工具合同](section-authoring-wands.md#3-路径与自动补全的内部方法)。

## 一次建造的流程

玩家逐个放置向内的边界，最后一个边界使区域闭合。现有 worker 先识别区域内部，
再读取内部轨道的运营方向，为每个有向入口寻找各出口的最短合法通路。
每个可达入口—出口组合保存一条路径，与区域定义一起提交到现有候选校验及原子编辑事务。
不可达组合不生成进路；所有组合都不可达时明确拒绝本次完成，原存档及此前待补全边界不变。

若某组合有其他合法通路，仍正常保存最短路，在它的入口、出口显示警告。
玩家之后扳动道岔、预览另一路径，再用鼠标替换表内路径；这部分归[录制合同](current-route-recording.md)。
生成的路径不会随着实际道岔切换重新选择，也不申请列车资源；默认进路配置已取消。

## 搜索方法

`ProtectionRouteDiscovery.discover(topology, region, interior, directions)` 接收已经解析的区域内部片段，
输出完整 `ProtectionRouteDefinition` 集合及需要警告的边界 ID 集合。
每个内部片段按允许运营方向建立有向状态，状态保留 rail UUID、canonical AB 范围及行进方向。
轨道末端之间的边只来自 Core 的合法 continuation；普通接头、道岔和平交不会因为空间接近而创造连接。
边界切口位于轨道内部，到达任一出口切口即停止，不能越过出口到区域外绕路。

每个入口运行一次 Dijkstra，轨道片段长度为正权重，从同一搜索结果恢复到各出口的路径。
状态、连接与队列平局按稳定顺序处理，等长通路不会随集合遍历顺序随机改变。
自动 route ID 由区域及入口/出口 ID 稳定生成；不把派生图或警告写入世界存档。

对于一条已选路径，逐一暂时排除它的连接，再检查入口是否仍能到达出口。
只要仍可达，就存在另一条简单通路：不同的简单通路至少缺少所选路径的一条连接。
如果只能沿原路多绕一圈、不能避开任何原连接，不算另一条进路。
检测找到一个替代通路便结束，不枚举全部简单路径，也不把循环走法全部保存。

## 发布、编辑保护与失败

`RuntimeSectionWandBackend` 只构造包含新区域及新表的一个 `SimpleSignalsDefinitionPatch`。
manager 原有的完整候选校验、旧/新编辑影响、时刻表及运行占用保护、文件准备和原子发布继续生效。
任一阶段失败不先保存半个区域，也不留下与进路表不同步的区域。
没有方向合法进路、图不完整、编辑冲突或世界基线已变时保留旧值并说明原因。
替换后仍需通过进路合法性及编辑许可校验，警告不能绕过这些检查。

## 警告显示

多通路使用相关入口/出口上方的琥珀色粒子“！”及玩家文字提示，不标在内部道岔。
新区域完成后显示；区域工具左键已有边界可查看该区域的警告；通路预览也显示相关警告。
曲线位置与标记点在 worker 准备，玩家线程只发送预算内点位，换工具、离线、换世界、卸载或停用后清理。
区域工具警告是一份用户选取时的提示，不是新的信号规则或每 tick 图搜索。
定义或拓扑改变可清理过期提示，玩家重新选择即可更新；这不使其他线路的区间或运行授权失效。
通路预览的 `RegionRouteWarnings` 每份玩家选择只保留一个已准备结果，依据拓扑 root、区域定义和
相关轨道运营方向匹配后复用。单纯切换道岔不改变“是否有其他合法通路”，因此不重复执行多通路搜索。
输入比较及公共方向读取仍随区域大小增长，不把每次预览的全部准备声称为常数时间。
共用显示语义见[铁路编辑标记规范](../../bukkit-plugin/backend/editor-markers.md)。

## 成本与退化

设局部图有 V 个有向片段、E 条连接、B 个边界，所有输出路径总片段数为 P，
实际为检测替代通路尝试排除的连接数为 H。排序、邻接构造及边界匹配另随局部片段、邻接和边界规模增长。
每入口最短路约为 `O(B (V + E) log V)`，恢复输出为 `O(P)`；
替代通路检测最坏为 `O(H (V + E))`，不能把整个算法的成本只报告为 Dijkstra。
H 至多随各输出路径的连接数之和增长，有替代路径时通常提前结束；工作不随所有可能路径组合指数增长。
候选整体编译、JSON 编码及保存还具有既有事务成本，均在 worker；最终提交不新增图搜索或曲线计算。
内存包括局部图、单次搜索数组及输出路径，约 `O(V + E + P)`，不保存全路网的另一份权威图。
真实大规模延迟仍待实测，离线正确性检查不是性能基准。

## 具体情形与验证

- 两条合法路径长 80 米和 110 米：自动保存 80 米，并警告有关入口/出口；玩家可录制 110 米替换。
- 第二支路方向不允许：不作为合法替代通路，不因此出现多通路警告。
- 区域外有更短回接：边界切口截断，不能选用区域外路径。
- 已有区域补侧线后修复：保留原进路 ID、表和信号，不能重置为新一次最短路自动选择。

测试必须覆盖最短/等长稳定选择、合法道岔过渡、AB/BA、方向过滤、不可达、循环仅绕行、
区域外不扩展、警告仅在相关出入口、显示预算与关闭、区域+表原子成功/失败、
修复不覆盖、鼠标替换保留引用，以及重载后真实 Basic planner 采用表内路径。
自动生成本身不要求schema升版；当前未发布格式归索引并保持schema 1，默认进路删除及两端独立规则不建立开发代际。不新增旧格式reader、自动升级或第二套资源管理器。
