# 单线单闭塞的双向控制

## 1. 状态与负责模块

CURRENT，已完成离线验证。SimpleSignals 负责双向匹配与入口检查；Basic 继续负责同一资源的互斥、授权和车尾释放。
本批实现一个物理闭塞、两个真实入口和一个共享主信号结果。工具、测距、两端独立规则及单线多闭塞协调不在本批。

当前修正还覆盖单向闭塞的明确反向拒绝、整条路径的运营方向一致性，以及已知失配时的区间低速模式。
SimpleATO 保留方向存储与自动控制限制的所有权；BukkitPlugin 只提供公开方向读取及生产组合；SimpleSignals 判断闭塞策略。
完整受影响模块门禁已通过；最后独立复核和详细验证记录见[任务实施记录](../../../tasks/09-18-signal-addon-implementation/implement.md)。
用户已明确：降级限速只约束 ATO，手动驾驶保持原样；本批不增加手动限速、自动制动或 ATS，也不删除既有手动安全行为。

## 2. 一列车如何通过

玩家把闭塞标记为双向，仍只保存一条从首端到末端的轨道路径。列车从任一端接近时，
SimpleSignals 把冻结路线与这条路径的正向或反向匹配，生成实际入口的检查声明和路线上的授权下限。
两种方向都申请 `StableInfrastructureResource("simplesignals:fixed-block", blockId)`。
Basic 原子取得完整资源集合；另一列车不能同时持有这个闭塞，即使两车暂时位于不同轨道片段。
车尾离开后使用原有释放队列释放，随后另一方向可以申请。

两端信号机可复用同一主信号结果，另一台使用已有附属设备定义；不重复执行信号规则。
同一灯色不代表两车都取得授权，列车仍必须遵守 Basic 的实际授权。

绑定闭塞时，SimpleSignals 从宿主一次读取这条路径各轨道的运营方向。
方向完全一致的闭塞使用正常入口和资源策略；有效单向闭塞从出口反向申请时明确拒绝。
已知方向失配则保留闭塞定义、改用 ATO 区间限速，不新增该闭塞的正常 token 或入口授权下限。
已有 token 继续正常保留和车尾释放。下游信号读取降级后的有效速度，不把已知降级误当作未知失效的 0。

## 3. 路径反转与匹配方法

闭塞的反向路径由已归一化路径倒序、每段 `facing` 取反得到，canonical AB 的上下界不变。
例如 `rail1 AB → rail2 BA` 的反向是 `rail2 AB → rail1 BA`，不是简单把整条路径标成 BA。
反向路径对所有闭塞在准备阶段生成，用于识别反向经过，不代表允许反向申请。原路径经过既有连续性校验；Core 的拓扑生成器已经拒绝非对称物理连接，
道岔合法连接也来自同一已校验映射，因此不重复验证必然合法的反向连接。运营方向限制仍属于 SimpleATO，不由这里放宽。
它是可丢弃派生值，不增加资源、占用监测区或存档路径副本。

匹配保留既有 rail→block 索引、route metres、交集拼接和完整路线验证。双向闭塞分别匹配两种路径，
每次通过仍须满足完整路径或只在运营路线端点截短，然后才按本次申请范围裁剪。
结果保留本次通过的方向，检查声明从该方向的首段取得 rail/facing，触发位置使用实际入口的 route metres。
从闭塞内部起步仍不生成入口声明；重复经过仍以同一声明 ID 加不同路线位置区分。

资源与检查匹配使用 `detectReverse = true`，再由有效方向策略决定是否允许申请，
不能用“没有生成反向匹配”来表达拒绝。单向定义要求每段轨道仅允许该段 authored facing，双向定义要求每段均允许两向。
例如路径 `A AB → B BA` 配置 A=AB、B=BA 才是合法单向闭塞；未设置轨道方向意味着允许两向，因此不满足单向定义。
任一段失配让整个闭塞降级。方向写入后，通过既有 rail→block 索引只更新相关闭塞；不轮询全世界。

降级限速在路线绑定时生成带起点、终点的不可变路线范围，复用现有检查绑定和完整限制快照传给控制器。
进入前使用既有制动曲线，到入口后保持该上限，车头越过该次经过的出口后结束；内部起步立即有该上限。
反向经过、重复经过和停车折返均使用各自冻结路线上的范围。不得依赖已经过的入口声明继续处于激活状态，
也不为区间退出新建逐 tick 回调或第二套车尾投影。车尾释放资源是独立流程，不由速度范围的结束触发。

## 4. 数据与接口

`FixedBlockDefinition` 新增 `bidirectional: Boolean = false`，同名字段位于原有 `fixedBlocks` 对象内。
省略或 false 表示单向闭塞：方向一致时明确拒绝反向申请；true 表示双向闭塞，仍须核对沿途运营方向。
既有 ID、revision、traversals、资源类型与声明身份不改变。
`CompiledFixedBlock.reverseTraversals` 保存已验证的反向路径，`entryTraversals` 保存一个或两个真实入口；
`FixedBlockRouteWindow.reversed: Boolean = false` 标识本次经过的方向，只用于派生入口，不写入存档。
两端使用相同提前时间、限速和外观结果；下游规则配置仍是该主信号的一份明确规则，不自动推断另一份方向规则。
资源申请继续使用现有 `ContributedRouteResource` 和 Basic 授权接口；SimpleATO 增加中立方向值与有终点的速度范围，不认识闭塞类型。

`InfrastructureResourceService.operatingDirections(worldId, topology, railIds)` 返回
`RailOperatingDirections(topology, directions)`；map 中每个请求轨道都有条目，null 表示允许两向，非 null 表示仅允许对应方向。
SimpleATO 的中央方向写入点将实际变化的 rail UUID 交给既有信号更新流程。
不把方向存储搬到 Basic、不复制全世界映射，也不另建服务注册层。检查绑定补充路线起止范围与速度，
`InspectionDeclarationBinding.speedRanges` 与 `InspectionUpdateInput.speedRanges` 使用不可变
`InspectionSpeedRange(declarationId, restriction)`；`RouteSpeedRestriction.endRouteDistanceMeters` 为可选终点。
稳定声明 ID 接收失效通知，每次经过的 restriction ID 区分其速度范围；入口经过后范围仍存在，限制适配器按车头终点过滤。
这些是瞬态跨模块值，不是新的存档格式。

插件启动配置 `disabled-block-speed-kmh` 默认 `20.0`，要求有限正数，启动时一次换算成 m/s 后注入 runtime。
本批不提供热重载。方向失配不是自定义灯色；已知降级状态具有该有效速度，自己的模型可使用既有 `default`。

## 5. 版本、线程和释放

开启或关闭双向属于定义修改，必须提高闭塞 revision，并经过原有候选编译、编辑许可和保存事务。
反向几何和编辑影响在工作线程准备，不在物理 tick、规则更新或平台线程重建。
停车折返保留已占用的同一 block token，返程匹配提供新路线上的释放位置；不得先释放再重新争抢。
停在闭塞内部不释放 token，车头通过出口也不单独触发释放。

运营方向仍由 SimpleATO 唯一持有；相关轨道一次读取必须来自同一存储状态。
变化通知不在存储锁内执行信号代码，无实际变化时不发通知；信号更新沿用既有物理/信号时序和原子结果发布。
保留静态时刻表编辑保护与运行中资源占用保护。已知降级定义仍属于路线编辑依赖，不能因暂不申请 token 而允许随意编辑。
持续限速随原有路线绑定替换、折返或移除；不另建每列车区间管理器。

## 6. 拒绝与安全行为

非法字段类型、越界或不连续路径、revision 未提高、过期拓扑和受保护编辑继续使用原有失败结果。
原路径不能通过既有物理连接验证时拒绝整份候选，保留原存档和发布结果。
已配置信号但尚无有效结果时，两端入口都产生 0 限速；资源拒绝不能扩大授权。

有效单向闭塞的反向资源申请沿用 contributor 拒绝路径，在新增资源预留和设备准备之前失败；
不能返回空资源集当作成功。正常可释放的旧队列仍可独立推进，不承诺拒绝会冻结既有释放流程。
可证明的方向失配产生配置限速；相关轨道缺失、拓扑不可信、观测不可用、插件故障或结果过期仍按既有 0 限制处理。
速度范围必须满足 `0 <= start <= end <= routeLength`，速度必须有限且为正；非法配置拒绝启动，不能静默采用任意值。

## 7. 性能

设全部闭塞总 traversal 数为 T，反向准备增加 O(T) 时间和空间。占用监测和规则节点数量不增加。
一次路线匹配仍为 O(R + K log K + I log I)，双向候选最多增加一遍方向匹配；不增加全世界扫描或逐 tick 路线投影。
保护区域后继查找继续使用已排序路线窗口，编辑影响按入口轨道索引最多加入两个入口，而不是扫描全部区域×全部闭塞。

读取并核对一条闭塞路径为 O(T)，只复制所需 U 条轨道的方向，空间 O(U)。
一次方向变化使用反向索引定位相关闭塞，只核对相关路径，不使其他世界或无关路线失效。
控制状态随占用/信号一起原子发布；低频 baseline 或相关方向变化时复制当前控制 map，另有 O(D) 成本，
D 为当前有特殊控制状态的闭塞数。普通物理更新复用同一个不可变 map，不重复复制。
持续限速只增加既有限制适配器对缓存范围的边界检查，成本 O(C)，C 为当前列车的缓存限制数；
声明 ID 的查询集合在绑定时构造一次，之后仅按实际失效 ID 查询；没有变化时不额外扫描范围列表。
不新增 `列车数 × 全部闭塞数` 的逐 tick 工作。定义候选编译仍在工作线程，最终编辑提交不重建全世界拓扑。

## 8. 具体情形

从两端申请：第一列车持有 block token，第二列车的原子申请被拒绝，不留下部分新增资源。
内部站台折返：token 保留，返程重置车尾坐标并使用同一 token 的新释放点；其他列车仍不能进入。
咽喉出口接反向入口：直接后继仍是这一个闭塞，授权下限延伸到返向路线中的闭塞出口或运营终点。

单向闭塞跨 A/B/C，只有 B 的运营方向失配，整个闭塞都降级，不只对 B 限速。
ATO 在其内部站台起步也保持配置上限；车头离开后此上限结束，但列车仍持有的资源等车尾离开才释放。
另一世界的轨道方向修改不触发这列车的规则重算。手动驾驶不接入上述 ATO 限速范围。

## 9. 必需验证

验证字段省略时仍为单向、方向一致时的正向申请、正反向多轨道混合 facing、完整/裁剪/内部起止及重复经过；
检查真正反向入口的 rail/facing 和触发位置。
验证两端读取同一信号结果、缺基线为 0、资源/监测区/规则数量不翻倍。
通过真实 Basic 申请与车尾释放，验证相向互斥、失败原子性、释放后重申请和停车折返保留 token。
验证反向保护区域后继及其编辑保护；固定缺字段 fixture 得到 false，true round-trip 保留，非法类型和未提高 revision 被拒绝。

方向修正必须验证每段方向集合精确相等、混合 AB/BA、中间一段失配、未设置方向、双向定义；
有效单向闭塞反向申请/时刻表应用拒绝，且未新增预留或触发设备准备；降级不新增 token/入口下限但保留旧 claim 和静态编辑依赖。
区间限速覆盖内部起步、正反向、重复经过、折返及车头退出；其结束不提前释放车身资源。
已知下游降级速度可用、未知状态仍为 0、无变化/无关编辑不唤醒相关规则、方向读取与结果发布一致。
配置默认/自定义/非法值、手动控制路径不变、Java API consumer 编译及插件 JAR 隔离必须通过。
未配置信号规则的资源型闭塞同样要验证：首个物理 baseline 前限速为 0，方向失配已知后才使用降级速度，
不能强迫它配置灯色规则才能低速行驶。资源生命周期使用真实 Basic 类组合验证；这不等于完整回库任务、
真实 Folia/客户端画面或大规模延迟基准，后三者尚未验证。最新门禁命令与数量记录在任务实施记录中。

## 10. 存档与后续边界

默认值明确的新增字段仍使用 schema 1，不新增旧格式适配、别名、迁移器或中间版本。
不得把同一闭塞拆成两个方向资源，也不得为支持两个入口引入第二套释放队列或信号循环求解。
两端独立输出不是当前共享显示关系的强制限制；如以后需要，再单独设计方向规则。
单线多闭塞的整段方向协调仍在 TODO 中，本批不开设整段独占资源或方向锁。

本修正不升级世界定义 schema，不兼容旧开发草稿，不增加手动或 ATS 接口。
不能用“入口处要求 20 km/h”替代整个区间的持续限速，也不能因为匹配器跳过反向列车就声称反向申请被拒绝。
应分别表达几何经过、有效申请方向和已知降级限速，复用原有授权与释放流程。
本批没有增加单线多闭塞调度、两端独立规则、Wand、测距或可视化；它们仍按原计划分别讨论与实现。
