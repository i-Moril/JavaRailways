# 固定闭塞的两端入口与轨道方向

## 1. 状态、范围与所有权

CURRENT。固定闭塞没有独立的单向／双向权限类型。SimpleSignals 负责一条连续物理路径的占用保护、两端入口、信号规则及附加资源；SimpleATO 根据 Basic 的公共方向配置验证实际运营路径、车身相关路径和停车余量，并收紧自动运行约束。

本轮移除旧 `bidirectional` 字段和整块方向一致检查。Basic/Core 的运行接口、物理准入、资源仲裁、换向交接和车尾释放不变。单线多个连续闭塞之间的方向协调仍在 TODO，不在本合同中实现；手动驾驶不增加方向强制或 ATS。

## 2. 一列车如何通过

玩家按几何划出闭塞，两端被识别为作者路径的 FORWARD／REVERSE 入口。ATO 规划运营路径并完成停车余量与方向验证；SimpleSignals 对已选路径匹配闭塞窗口，产生真实入口声明、完整出口请求下界及 `simplesignals:fixed-block` 附加资源。

Basic 将闭塞资源与实际轨道、道岔等物理资源原子申请。两个方向使用同一个 block ID，共享一份占用几何；两个入口可以分别有自己的信号规则。停在内部、换向或回程 pending 时不先释放再争抢；车尾释放仍由 Basic 现有队列执行。

完整物理授权与实际运营终点的关系由 [ATO 终点分离契约](../../javarailways/simpleato/terminal-route-completion.md)拥有。闭塞只补全包含运营终点的当前路径，不递归取得后继区间、不重新寻路、不猜道岔分支。

## 3. 路径反转、窗口和保护后缀

定义保存作者的完整有序 traversal。反向路径由倒序并取反各段 facing 得到，canonical AB 上下界不变，例如 `A AB → B BA` 反向为 `B AB → A BA`。路径顺序不随运营方向编辑翻转，避免既有信号交换入口。

两个方向始终参与几何匹配，没有权限过滤开关。matcher 使用 rail→block 索引并计算各次经过的窗口；起终点可以在闭塞内部，中途离开路径仍拒绝。同一冻结路线可重复经过同一 block，但资源身份不重复；本次已申请窗口按 block ID 合并，释放位置取最后已申请出口，未申请的未来经过不延长持有。

从内部起步只产生中立 authority floor，不虚构已在车后的入口信号。终端补全裁剪已编译路径到本次方向的真实出口；不能为了满足余量跨入下一闭塞或未选保护进路。

保护后缀可能包含本次不能实际驶入的方向。它用于占用和物理资源保护，不是自动运行许可；SimpleATO 独立限制合法行驶范围，不能只因保护后缀很长就忽略停车余量方向失败。

## 4. 数据与接口

`FixedBlockDefinition` 只保存稳定 namespaced blockId、非负 revision 和非空 traversals；不保存 `bidirectional` 或换名后的等价权限。`reverseTraversals`、`entryTraversals`、长度和占用是拓扑下的派生值，两端始终参与编辑影响计算。

`FixedBlockEntryDirection { FORWARD, REVERSE }` 相对作者完整路径，与某一轨道的 AB/BA 不同。入口身份为 `(blockId, entryDirection)`，每个实际绑定入口最多一台主信号；未绑定设备不虚构入口。

固定闭塞声明 ID 仍为 `simplesignals:fixed-block/forward/<namespace>/<path>` 或 `simplesignals:fixed-block/reverse/<namespace>/<path>`，资源 ID 仍为 block ID。声明方向放在 namespace/path 前，避免作者 ID 自带 reverse 后缀时冲突。

Basic 公共方向读取保持原合同：完整请求子集中的 null 表示允许两向，AB/BA 表示对应单向；缺条目／过期读取不等于双向。本插件仅在保护进路发现等实际需要方向的功能中使用它，不再把混合方向解释成整个闭塞不可用。

## 5. 两端信号、生命周期和线程

两端主信号独立配置下游、输出、提前时间和模型，各自使用相应有向路径编译扫描；共享占用和资源，不共享输出。模型放置和旋转不能改变逻辑入口。两端都允许绑定，不因为轨道配置混合而拒绝反向入口。

ATO 按 window.reversed 选择本次入口，重复声明 ID 对应不同经过位置，前视只使用最近有效入口。无信号配置不增加灯色限速，但仍有资源与 ATO 方向限制；已配置却缺状态、缺 baseline 或规则异常时仍收紧为零速／不可用。

定义修改沿用 revision、候选编译和编辑许可；反向路径、索引和规则在低频准备，不在 physics tick 重建。卸载、重载、拓扑失效和缺基线仍严格拒绝，不能随删除旧方向 blockControls 一并删除真实故障门禁。相关方向变化由 ATO 沿原通知入口和 rail 索引立即失效既有自动运行结果；epoch 仅分发合并后的来源通知，不把所有闭塞或两端信号一律作废。

删除闭塞可按物品偏好保留两端主信号并显式解绑，附属显示继续引用其主信号；关闭保留才级联删除。操作仍通过同一原子 patch，不修改模型或规则身份作为隐式迁移。

## 6. 校验与失败行为

- 非连续路径、跨道岔、非法范围或定义引用失败：拒绝整份候选，保留旧磁盘和 publication。
- 混合单向／双向轨道：几何合法即可创建，不禁用整块资源。
- 实际自动运行路径、换向后的车身或停车余量违反轨道方向：由 ATO 拒绝候选／收紧方向边界，保留已有保护。
- 重复实际入口主信号、未知入口方向、缺 block/type 或异常规则：拒绝候选或沿既有故障语义停止放宽。
- 没有入口信号：不能跳过资源申请；已有配置缺结果不能借另一端的规则放行。

资源贡献回调描述几何与附加保护，不是独立运营规划 API。直接拿到物理资源不证明自动路线方向合法；正式 ATO 路径仍须通过自身方向验证。

## 7. 性能与退化

候选仍只按路线 rail ID 发现，不做 all blocks × route 或 all trains × blocks 扫描。反向路径在定义准备时派生，两方向匹配只增加常数因素。方向检查在 ATO 路线冻结／变更时计算，正常控制周期仅消费已编译限制；未知世界、轨道或来源保持拒绝，不以默认双向降级。

## 8. 正常与边界情形

A 仅向右，B 允许双向，两者普通连接组成一个闭塞。列车整列在 B 内向右停车，再换向返回 B 内车站，允许；闭塞资源持续保留。回程保护后缀可以覆盖 A，但 ATO 的方向边界位于 B/A 接头。

回程目标或所需停车余量越入 A 时拒绝；车头到 B 但换向后的车身仍涉及 A 时不能只检查车头。再次沿合法方向驶出后，真实车尾出清才释放，不能以停车、换向或车头过界替代。

## 9. 必需验证

混合方向创建、canonical AB/BA 组合、两端入口及编辑影响、内部起止、重复经过和反向几何；两端独立扫描、无信号和配置缺状态的区别；真实 Basic 相向资源冲突、停车换向保持 grant／claim、车尾释放；ATO 非法运营方向／车身／余量拒绝、保护后缀与控制边界分离、无外部信号 source 的方向失效。固定 current fixture 保留两端入口，严格未知字段／版本与备份恢复保持。

本地单测、真实 Core/Basic/Dispatcher 离线执行和游戏内验收分别记录，不因旧全双向 fixture 通过就宣称混合方向回归已验证。

## 10. 存档、迁移与待实现事项

SimpleSignals 为未发布 sidecar schema 1。本次直接修正当前模型与 fixture，删除闭塞权限字段，保持版本 1；不添加开发代际、runtime alias、unknown-key 放行或旧 reader。版本决定先遵守[发布基线门槛](../../javarailways/shared/versioning.md)。须保留的旧开发文件在部署前使用有 dry-run、明确 diff 和不可覆盖恢复点的一次性转换，不能自动重建闭塞或交换两端信号。

应避免：把方向交集重新保存为一个权限开关，或因补全到闭塞出口就允许逆行。
正确做法：几何闭塞共享一个资源，方向由实际自动路线及其控制限制判断。

单线多闭塞整段方向协调另行设计，必须同时考虑相向堵塞、同向跟车和原子准入；本批不预建方向锁或占位存档字段。
