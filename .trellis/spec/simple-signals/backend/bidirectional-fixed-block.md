# 固定闭塞的双向进入与运营方向

## 1. 状态与所有权

SimpleSignals 负责闭塞路径、入口声明和方向校验；Basic 保存公共运营方向并管理唯一的资源授权与车尾释放。
当前支持一个物理闭塞从两端进入，使用一份资源和占用监测区。
两端独立规则已实现（`CURRENT`）：每个入口可有自己的主信号，按本次经过方向选择；单线多闭塞协调不在本批。
本轮建造工具批次按用户决定删除旧低速降级：方向失配的区间不可用，明确拒绝 ATO 进入。
历史低速测试不再是当前契约；当前验证记录见任务 `implement.md`。

## 2. 一列车如何通过

闭塞保存一条从首端到末端的完整有向路径。列车的冻结路线与它匹配后，SimpleSignals 检查沿途每条轨道的运营方向。
一致时为真实入口产生检查声明、提前申请时间和授权终点下限，并提交 `simplesignals:fixed-block` 资源。
Basic 把它与物理轨道、道岔等资源一起原子申请。相向列车申请同一个闭塞 ID，不会各自取得不同方向的资源。
车尾离开后由原队列释放；停在内部或折返都不会先释放再争抢。

### 完整物理授权与内部运营停车（CURRENT，2026-10-14）

运营停车点不能截短信号允许通过的整个固定闭塞物理授权。本批通过现有inspection source提供中立的终端后续路径，接线及任务坐标/后缀复用归[终点分离契约](../../javarailways/simpleato/terminal-route-completion.md)。已通过真实Core/Basic的50ms离线返库与接续回归；未部署或完成游戏内验收，不证明停车精度缺陷已修复。

闭塞40～140米、停车点100米时，从snapshot的末端rail反向索引找到命中的有向闭塞窗口，按作者完整路径裁出100～140米；BA使用既有reverseTraversals及双向许可，不能按某条rail的AB/BA猜整个区间方向。只补全包含运营终点的当前闭塞，不递归进入下一个区间，不重新寻路。退出边界恰等于停车点则无后缀；未知/失效/方向非法或无法与原路径一致匹配时拒绝，不能退化成无附加要求。

在扩长后的真实冻结路线绑定中，入口的最小请求终点必须到真实出口；整个block token与覆盖剩余区间的Basic轨道资源在同一事务中取得。普通matcher仍可描述输入路线的局部相交窗口，但局部窗口不能被正式调度路径拿来把完整区间截到运营停车点。

宿主增加全局停车余量后，source同时接收原路线与移动余量候选：未接管返回null；固定闭塞真实出口返回明确空后缀，禁止宿主擅自延伸到下一区间。未接管时也检查新增候选不能进入新闭塞。保护区域独立校验原路线与候选，不能用余量补全掩盖原来位于区域内部的非法停车。完整签名、多个source冲突与余量不足的拒绝语义仍归上述终点分离契约。

从区间内部起步时，当前区间出口通过中立请求下界表达，保留已有token/物理资源生命周期；不创建已经位于车后的入口信号声明。停车换向先rebase原claim，再用新方向完整剩余路径申请；整个过程中不得暂时释放后抢回token。

候选匹配使用同一不可变定义publication，后续路径也加入原有静态时刻表与动态冻结路线编辑依赖；源丢失/异常沿用既有fail-closed生命周期。额外成本只在新候选/静态应用中按命中区间路径线性处理，不增加逐tick扫描或资源队列。验收须实际观察100米停车目标未改、forward轨道claim到140米，以及相同token在反向真实车尾清除后释放。

## 3. 路径反转与匹配方法

反向路径在准备阶段由原路径倒序、每段 facing 取反得到，canonical AB 上下界不变。
例如 `A AB → B BA` 反向成为 `B AB → A BA`。反向路径也用于识别非法逆行，不代表单向闭塞允许反向申请。
匹配仍使用 rail→block 索引，把冻结路线与闭塞路径相交，得到各次经过的入口、出口和路线坐标。
路线起终点可在闭塞内部，中途偏离则拒绝；同一冻结路线可以重复完整经过，不能因此创建多个资源身份。
只有真实入口生成信号声明，内部起步不虚构车后入口。

资源申请按 block ID 合并本次已申请的窗口，释放位置取这些窗口的最后出口；未申请的未来经过不能提前延长持有范围。
双向检查声明取本次进入方向的首段轨道与朝向。重复经过同一方向仍使用同一声明 ID 加不同触发位置，
列车前视只使用最近一次有效入口，不把一次已通过的信号永久留在列车前面。

### 两个入口共用占用，但不共用规则

定义发布时，用 `(blockId, entryDirection)` 索引每个已配置的主信号；两条规则都引用同一个区间占用。
每条规则使用其入口方向的完整有向路径，独立编译出口后的依赖、限速档位和模型配置。
占用变化会唤醒两端规则，下游变化只沿已有单向依赖图唤醒实际消费者；输出不变仍停止传播。
同一区间允许多个规则 binding，不再用 section ID 唯一确定信号输出；显示和下游依赖按 signal ID 查找。

ATO 的检查绑定复用已有路线窗口，从 `window.reversed` 选择对应入口的状态和提前时间：

```text
entryDirection = window.reversed ? REVERSE : FORWARD
declaration = fixedBlockSignalDeclarationId(blockId, entryDirection)
保留真实入口声明、区间出口 floor 和同一 block 资源
若该入口未配置规则：不额外生成速度限制
若已配置但状态缺失、不可用或观测无效：入口速度限制为 0
否则：在本次入口位置投影该入口的有效限速
```

未配置的一端不能借用另一端的规则或模型；这种资源型入口仍受完整资源授权和方向有效性约束。
模型摆放仍显式配置，改变显示位置或 AB/BA 朝向不能改变信号所控制的逻辑入口。附属设备直接引用所选主信号 ID。

## 4. 数据与接口

`FixedBlockDefinition.bidirectional: Boolean = false` 表示是否允许双向进入；默认单向。
`CompiledFixedBlock.reverseTraversals` 是可丢弃派生路径；`FixedBlockRouteWindow.reversed` 只表示本次经过方向，不写盘。
定义包含 `FixedBlockEntryDirection { FORWARD, REVERSE }`，
`FixedBlockSignalDefinition.entryDirection: FixedBlockEntryDirection = FORWARD`。
私有键 `FixedBlockSignalEntry(blockId: String, direction: FixedBlockEntryDirection)` 用于提前时间与配置存在性查表。
共享规则运行时以 `signalIdForDeclaration(declarationId)` 定位确定的规则，区间运行时以 `fixedBlockSignal(entry)`
先检查整个闭塞的控制有效性、再读取该入口输出；不再提供无方向的“区间唯一信号”查询。
FORWARD 指作者路径的首端入口，REVERSE 指其反向路径首端入口，不等同于某条轨道的 AB/BA。
每个 `(controlledBlockId, entryDirection)` 最多一个主信号；REVERSE 仅允许绑定双向闭塞。
固定闭塞声明 ID 使用 `simplesignals:fixed-block/forward/<namespace>/<path>` 或
`simplesignals:fixed-block/reverse/<namespace>/<path>`，资源 ID 仍是原 block ID。
方向放在 namespace/path 之前，避免合法作者 ID `test:x/reverse` 与其他反向声明撞名。
`InfrastructureResourceService.operatingDirections(worldId, topology, railIds)` 返回与所捕获拓扑相配的方向子集：
map 每个请求轨道都有条目，null 表示允许两向，AB/BA 表示只允许对应方向。缺少条目不能当作允许双向。

单向闭塞要求每段仅允许该段实际行驶方向；双向闭塞要求每段都允许两向。
这不是要求所有轨道都写 AB：`A AB → B BA` 配合 A=AB、B=BA 是一致的单向路径。
只要一段方向集合不一致，整个闭塞不可用。

## 5. 更新、线程与生命周期

闭塞定义修改沿用 revision、候选编译和编辑许可。反向路径、几何和索引在 worker 准备，不在物理 tick 重建。
Basic 方向变化只通知相关轨道；SimpleSignals 通过反向索引重新核对相关闭塞，并与同周期信号结果一起发布不可用状态。
没有变化时不重复读取全世界方向。既有静态时刻表依赖和动态占用继续禁止相关编辑。
规则状态仍与占用一起原子发布；区间控制失效同时使两端声明失效，不能只通知任意一个主信号。
编辑某端规则时从该 signal ID 收集结构消费者；区间几何变化则以区间为起点收集两端及其消费者。
删除闭塞沿用原有连带删除，移除两端主信号及它们的全部附属显示。新增或移除某端规则复用 source 替换和缺基线收紧。
手动驾驶不受新增信号强制制动；此功能不添加 ATS，也不删除原有手动安全行为。

## 6. 不可用与拒绝

有效单向闭塞的反向申请明确拒绝。方向失配的闭塞无论有无信号规则，都拒绝资源贡献、检查绑定和时刻表静态路线校验。
不能用“不生成 token/声明”表示拒绝，那会被调用者理解为无需任何附加限制。
信号阶段把失配发布为 `SectionSignalState.Unavailable`，有效限速为 0，下游不能把它解释为可低速通过。
设备保留配置，使用自己的模型 `default`。修正方向后重新计算，满足规则才恢复；旧 claim 不因失效被清除。

未知物理基线、过期拓扑或插件故障仍禁止放行。非法字段、非连续路径、重复身份及 revision 错误仍拒绝候选。
正式闭塞定义禁止穿过道岔，包括直向；保护进路的占用几何复用不受这一作者规则限制。
重复同入口主信号、单向闭塞绑定 REVERSE、未知方向值均拒绝整份候选，磁盘/source/publication 不变。
取消双向时必须同时删除反向规则，不能静默迁到正向。下游引用仍按原编译合同处理：
暂时缺失目标的既有规则保持不可用，非法路径/循环等仍拒绝；本批不改写区域修复和删除后的失效策略。

## 7. 性能

原路径总片段数 T，反向准备增加 O(T) 时间和空间，不增加占用监测区或资源数。
路线匹配仍为 `O(R + K log K + I log I)`：R 为路线片段数，K 为命中闭塞数，I 为同轨道候选交集数。
方向子集复制为 O(U)，逐段一致性检查为 O(T)，仅低频绑定/申请或相关方向变化执行。
没有新增逐 tick 路线扫描、方向轮询或第二套释放队列。已删除仅服务旧低速模式的持续限速生成和判断分支。
入口索引按规则数线性准备，按方向选择状态是期望 O(1) 查表；不增加监测几何或每列车规则图。
最多每个闭塞两条规则；实际规则计算仍只访问被唤醒节点及其已编译依赖。
变化回调中既有不可变信号快照的复制/排序成本仍存在，不能声称整个回调恒为 O(1)。

## 8. 具体情形

两端申请：第一列车持有同一 block token 后，第二列车申请失败，不留下部分新增资源。
内部折返：原 token 保留，新路线更新释放位置，车尾离开后才释放。
多轨道方向失配：A/B/C 中只有 B 被设置成另一方向，也禁止整个闭塞的 ATO 进入，而不是只限制 B。
从咽喉出口直接进入双向闭塞的反向入口：仍匹配同一物理区间，授权下限延伸到本次方向的出口或运营终点。
两端不同下游：正向可因前方信号收紧而停车，反向仍按自己的后续线路输出；共同占用会同时收紧两端。
只配置反向规则：反向缺基线保持 0，正向没有额外信号限速，但不能绕过资源或区间失效。

## 10. 存档和待实现项

版本决策首先遵守[版本号与发布基线](../../javarailways/shared/versioning.md)，不能仅凭删除字段或语义改变升版。
`bidirectional` 有明确默认值，其引入本身不要求升版。此前 sidecar 因删除默认进路字段被升为 schema 2，再因一规则两端控制改为入口独立被升为 3；两次决定均未确认发布/冻结基线，已撤销其升版依据。
当前文件已按用户要求恢复为 schema 1，writer 只写1，reader拒绝所有非1版本（包括误升的2/3）。保留两端独立字段和现有功能，不恢复旧的一规则两端语义或默认进路，也不新增兼容 reader。
Core/Basic/SimpleATO 世界、模型包格式、revision 和 epoch 不随本次规则变化升级。
不加旧规则自动复制、运行时别名或兼容 reader；需保留旧开发服数据时另做有恢复点的单向一次性迁移。
当前未提供该迁移工具，不自动修改服务器旧文件。
旧配置 `disabled-block-speed-kmh` 和低速策略删除，不保留兼容开关。检查 API 中通用的限速范围能力不因此删除。
两个入口的显示主从关系不能替代资源互斥；单线多闭塞协调仍列 TODO，不能先用整段独占资源阻止所有同向跟车。
建造工具见[闭塞与保护区域工具](section-authoring-wands.md)；真实 Folia 显示与大规模性能基准另行验证。
应避免按某条 rail 的 AB/BA 选规则，或把两个入口拆为两个资源；正确做法是按作者整条路径的 FORWARD/REVERSE 选规则，保持一份物理闭塞身份。
