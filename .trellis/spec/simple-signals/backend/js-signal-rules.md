# JS 信号规则：输入、执行与输出草案

## 1. 状态与负责范围

这是 **TARGET／待审查草案**，不是已经可用的脚本 API。2026-10-06 用户确认距离敏感规则使用 JS，
不再扩展 Kotlin 的距离条件配置表。本批只写契约、伪代码与测试要求；审查通过后分批实现。

SimpleSignals 拥有脚本加载、受限执行及信号策略；Basic 仍负责物理观测、资源校验与仲裁，SimpleATO
仍负责一次前视、资源申请、动态制动与最严格约束合成。脚本不接管这些机制，也不改变手动驾驶。
当前已有的规则边界见[后端索引](index.md#已评审的响应式方向与已完成前置观测)，源码映射见
[本批研究](../../../tasks/09-18-signal-addon-implementation/research/js-rule-runtime-source-map.md)。

## 2. 一次规则执行如何完成

1. 在加载／编辑 worker 读取脚本并编译，校验绑定、扫描距离、模型外观及依赖图，构造完整候选。
2. 沿用已有定义事务、编辑许可及原子 source 替换安装候选；失败保留旧定义，不能边加载边放行。
3. 同一物理观测周期发生区间占用、进路准备、道岔选择或下游输出变化时，现有依赖图调度受影响规则。
4. Kotlin 适配器把已知且有效的区间与下游值投影为只读 JS 数据，并为此次调用创建空输出槽。
5. 脚本调用两个 setter。正常同步结束、预算未超限且两个值均有效，才生成现有 `SectionSignalOutput`。
6. 同一 wave 完成后，沿用区间／信号快照的原子发布。SimpleATO 读取入口限速，显示器读取外观；
   附属信号机只复用主信号结果，不再次执行脚本。

## 3. 输入准备与关键内部机制

已有 `SectionSignalRuleInput` 提供自己区间的占用／长度、下游信号入口距离／限速，以及已选保护进路。
当前下游依赖由作者显式指定；**声明最远扫描距离后自动形成前视列表尚未实现**，不是增加 JS adapter 就能得到。

目标采用声明距离而非声明“查看几个区间”：加载／编辑阶段从该有向入口编译距离范围内的候选及路径条件，
缓存真实沿轨弧长和依赖；运行时只按同周期进路／道岔条件筛选已编译记录。查询不能触发寻路、轨道遍历、
世界占用扫描或文件读取。扫描距离只是准备输入的范围，不自动选择灯色、限速或制动策略。

- 固定闭塞按本次入口方向读取同一份区间占用和长度；反向入口不借用正向信号输出。
- 保护区域按所选完整进路提供占用和实际进路长度，而不是整座咽喉的总长度／整区占用。
  普通脚本不按区间种类特判；入口无有效请求、授权不足、设备不正确或车尾净空未成立时，
  沿用现有选择器的停车输出，不允许脚本自行选路或放行。
- 前视跨保护区域时，只能使用已有合法进路及其对应出口；不存在确定通路时不得猜直向或最短路。
  具体候选编译及分支规则是实现前必须补齐的审查点，不承诺本草案已有自动发现算法。
- 保留完整输出依赖 DAG：定义准备时检查所有候选边，包括当前未激活分支；自依赖／循环拒绝。
  调用时不能任意按 ID 添加未注册依赖。物理轨道成环与输出依赖成环不同，JS 不解决完整环线预告。

## 4. JS 接口草图与单位

以下名称与形状是供审查的草图，不是已经冻结的公共签名或磁盘字段；不增加 API 版本号。

```ts
type SignalInput = {
  readonly self: {
    readonly occupied: boolean;
    readonly lengthMeters: number;
  };
  readonly forwardSignals: ReadonlyArray<{
    readonly distanceMeters: number;
    readonly speedLimitMetersPerSecond: number;
  }>;
};

type SignalOutput = {
  setSpeedLimit(metersPerSecond: number): void;
  setModelVariant(name: string): void;
};

// 插件提供的同步入口；返回值不是信号结果。
function evaluate(input: SignalInput, output: SignalOutput): void;
```

`occupied` 只代表该区间／所选进路确有占用，不把未知观测伪装为空闲。长度为完整有向区间／进路的米数。
前视记录按入口距离非递减排列；距离从本逻辑信号控制入口起算，而非模型位置或玩家视线。
同一物理位置有多条候选时先按合法方向／进路消歧，不能让 JS 自行从混合分支挑许可结果。

两个 setter 每次必须各调用一次；重复、缺失、非法类型、非有限／负速度或空外观均为错误，
不能继承上次值、以最后一次写入掩盖冲突或根据外观名称反查速度。输出槽只在本次调用有效，
脚本不能保存 setter 后延迟写入。动态外观不能沿用当前只枚举静态 clear levels 的校验假设：
有成功解析的主／附属模型绑定时，在准备阶段派生其可共同使用的外观名称集合，调用结束后校验名称，
不在执行期间展开模型树。已知不属于该集合的名称是规则配置错误，整次输出不可用；
纯后端设备仍只要求非空名称。模型包缺失、实体创建或实际显示故障保持现有显示错误边界，
不能把“暂时没有显示对象”当作非法规则输出；具体集合接线须在模型／脚本绑定批次审查。

第一版不暴露 `availability()`、`reservation()`、原始列车／世界对象、资源 registry 或可变进路表。
必要的可用性与放行前提由适配器及现有选择器先校验，JS 只处理规则数据。
下游有效红灯为已知速度 0；下游 `Unavailable` 不是普通红灯，沿用当前规则边界直接使消费者不可用。

`setSpeedLimit(0)` 设置的是**逻辑入口位置**的停车目标，不是要求列车此刻速度已经为零。
SimpleATO 仍按距离计算制动；JS 无权把入口移到模型位置或用此 setter 扩大授权。
扫描距离与既有 `inspectionLeadTimeSeconds` 也不同：前者限制规则输入范围，后者声明列车提前激活时间。

## 5. 发布、生命周期与隔离

数据来自同一已捕获的区间／信号周期。依赖值可以在未变化时复用，但不能混入未来周期、其他世界、
已失效绑定或已被相关轨道事务标记无效的数据；无关线路的拓扑版本增加不使整个世界失效。
一条规则读取的是本 wave 中已处理 provider 的值，最终一次发布完整结果，不读取半发布世界状态。

编译、文件读取及上下文准备不得在 Paper/Folia 实体所属线程或每次规则调用内进行。
执行只加入已有 signal epoch，不新增每信号定时任务、异步结果回填队列或第二个 epoch。
同一脚本用于多个设备时可共享编译产物，但调用数据、setter 和可变 JS 状态不得跨设备／调用串扰；
具体上下文复用方案必须用选定引擎验证，不能假定任意 JS 全局对象都是只读的。

不提供 Java 类加载／反射、宿主对象遍历、文件、网络、Bukkit、定时器、异步 Promise、动态导入或任意 I/O。
时间／随机等会使相同输入不确定的能力也不作为规则 API。限制必须由引擎与适配器实际执行，不能只靠作者约定。
世界卸载、定义替换及插件停用后，旧调用不能更新新绑定；沿用现有身份检查和清理边界。

本批不改变任何 schema、插件或模型包版本，不写派生输入、运行上下文或脚本执行结果到存档。
后续磁盘绑定只按[发布基线规则](../../javarailways/shared/versioning.md)处理；当前 SimpleSignals 保持 schema 1。

## 6. 校验与失败处理

- 脚本语法／入口／绑定非法、扫描距离非有限正数、依赖循环：候选拒绝，旧文件和 live publication 不变。
- 无物理 baseline、自己区间失效、下游缺失／不可用或没有合法活动路径：不执行 JS，沿用已知停车／Unavailable。
- 保护入口未 ready：保持现有零速输出及配置的停车外观；不能把空占用解释为准许进入。
- 调用抛错、超预算、异步返回或 setter 不满足合同：丢弃本次全部输出，该信号为 `Unavailable`、安全速度 0。
- 错误沿现有消费者链收紧，不保留该信号的旧许可；无关信号不因一条脚本失败全局停车。
  若现有 host source 本身整体失效，仍遵守其更保守的失败合同，不承诺屏蔽宿主故障。
- 模型显示／实体创建失败不撤销安全限制；模型使用现有 `default` 降级，不编造全国统一的红灯名称。
- 所有失败都不释放真实资源、不扩大授权，也不把损坏配置当作“未配置信号”。

诊断须定位信号、脚本与失败类别；对重复故障合并／限频，不能逐 tick 输出完整堆栈。

## 7. 性能、预算与退化

`forwardSignals[i]` 只访问已准备的数组；单次字段读取为 O(1)，扫描 k 条记录为 O(k)。它不是世界 lookup。
依赖候选准备成本按实际编译路径／记录规模计算，必须在算法确定后给出准确上界；不称为 O(1)。
首次 baseline 必须计算全部已配置规则，后续只由现有变化 wave 触发；输出不变则停止向上游传播。
一次 wave 每规则至多运行一次，无变化不调用脚本，不因显示器数或列车数增加共享规则执行次数。

现有 graph 的实际到达 A 个节点、D 条边传播成本为 O((A+D) log A)；规则输入投影与脚本遍历另计。
当前状态 map 复制／快照排序仍有全量 S 个信号的 O(S)／O(S log S) 部分，不能把整个 callback 声称为只与 A 有关。
首次加载和每次规则调用的引擎成本需实际测量，不用 Kotlin 单测耗时代替 JS 或 Folia 负载结果。

必须约束单次调用及整波总执行成本，并证明无穷循环／递归能停止。仅调用后检查耗时，或在 future 上
超时后留下后台脚本继续运行，均不满足合同。具体指令／资源预算、数值、失败隔离和引擎是待审查项；
不能用未经验证的“几毫秒超时”承诺强制中断。未完成预算验证前，不接入运行中的安全 epoch。
整波预算耗尽时，停止启动新的 JS 调用，把本波仍需重算的规则及其消费者标记不可用后完成发布，
不能让尚未执行的受影响规则保留旧许可；未受影响分支仍保持原状态。这个退化路径及其宿主预算也须实测。
不引入固定“最多几个区间”的作者参数；最远扫描距离负责输入范围，JS 负责实际判断。

## 8. 短区间示例与伪代码

下面只是说明数组及 setter 的用法，不是日本铁路规范或已批准的速度／距离配置。
假定示例作者采用 90m/200m 两个预告距离和 5/10/20 m/s 三档；这些值写在 JS 中，不由 Kotlin 解读灯色。

```js
function evaluate(input, output) {
  let speed = 20;
  let variant = "G";
  if (input.self.occupied) {
    speed = 0;
    variant = "R";
  } else {
    // 示例只判断扫描范围内已知的停车目标，不能用第一条 Y 提前结束。
    const stop = input.forwardSignals.find(s => s.speedLimitMetersPerSecond === 0);
    if (stop && stop.distanceMeters <= 90) {
      speed = 5;
      variant = "Y";
    } else if (stop && stop.distanceMeters <= 200) {
      speed = 10;
      variant = "YG";
    }
  }
  output.setSpeedLimit(speed);
  output.setModelVariant(variant);
}
```

同为 `S3(Y), S4(Y), S5(R)`，S5 距离不同即可使 S2 输出不同；自己区间长度也可用于作者其他策略。
模型名与速度分开提交，不能 `return "YG"`。示例不证明扫描范围足够，也不替代 ATO 对当前速度的制动计算。
没有前视记录只有在已确认的配置语义下才能视为末端，未知通路／缺数据不得伪装成空数组放行。

适配器执行伪代码：

## 9. 必需测试与断言点

- 真实规则适配验证米／m/s、正反入口、跨轨距离及所选保护进路长度；不返回整咽喉总长。
- 至少两个后继 Y 和更远 R，改变距离不改变速度输入时输出可以不同；连续短区间不被固定个数截断。
- 扫描范围与实际分支编译、无请求保护入口停车、合法进路切换、未知路径不作为末端；发现和读取不重复寻路。
- 物理环线与输出 DAG 分开；输出自环／完整环在候选准备阶段拒绝，磁盘／source／旧结果原子不变。
- 缺 baseline／失效／缺下游跳过脚本；异常、遗漏／重复 setter、非法数值、Promise 和超预算都发布 0。
- 使用真实选定引擎验证无穷循环、递归、越权 Java／文件／网络访问和跨调用状态泄漏；测试用替身不能证明沙箱。
- 单次超预算只收紧该规则消费者；整波超预算使未重算的受影响分支不可用，不能残留其旧许可或全世界无差别清零。
- 多 provider 同波只执行 consumer 一次；无相关依赖变化不执行 JS；被唤醒后输出未变不继续向消费者传播，
  外观未变不提交显示。道岔事件可能唤醒后实际输入仍相同，不额外承诺输入相等缓存；多个附属显示不增加执行次数。
- 动态名称按已解析主／附属模型的共同外观校验；未知名称收紧规则，缺包／创建／显示失败不误报安全规则失败。
- 修改脚本／扫描距离受原编辑许可保护；失败保留旧配置，旧调用不能覆盖替换或重载后的新绑定。
- 错误只收紧相关消费者，既有授权不扩大、claim 不释放；入口 0 由 ATO 制动而不是脚本直接制动。
- 记录首次编译、冷 baseline、局部变化和全图变化的实际调用数与延迟，再进行真实 Folia/client 验收。

## 10. 实施拆分与待审查项

实施前仍须评审：

1. JS 引擎、JAR 部署方式及可验证的执行／内存／整波预算，不能先选无法中断的执行器再补超时。
2. 脚本文件入口、绑定配置与参数形状；规则选择使用稳定 kind，不新增 ScriptV1/V2 或旧开发 reader。
3. 自动前视候选编译、分支与末端语义，以及由所有候选组成的 DAG 校验。不能以现有显式依赖冒充自动扫描。

下一批先实现最小加载／受限执行适配及其真实引擎测试，再独立接入距离范围候选；每批先确认合同，
提交后停下审查。保留现有配置规则不等于再做一套 ATO／资源系统，两种 provider 都必须进入同一规则执行边界。
如用户要替换而非并存现有 provider，需在绑定格式审查时明确，不无声删除已有配置。

应避免：在 setter 中操作世界；每次 JS 查找重新遍历轨道；失败沿用旧 G；按模型名反查速度；
把自动前视、完整环线预告、单线多闭塞方向协调一并塞进首个 JS 提交。
对应做法：已编译只读数据 + 调用局部输出槽 + 现有 DAG/epoch/约束发布；未确定的扩展保持明确边界。
