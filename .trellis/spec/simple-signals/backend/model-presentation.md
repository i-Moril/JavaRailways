# SimpleSignals 如何把信号状态显示成模型

## 1. 这份设计负责什么

本文描述已接入生产入口的信号状态到模型流程（`CURRENT`），包括包加载、两种摆放、设备存档、
显示变化和清理。离线测试验证公开服务调用与状态交接；真实 Folia 服务器和客户端画面尚未验证。
这里不重新定义进路、限速或资源管理。
其中 `default` 的名称、适用范围和选择规则，以及轨道附着/地面摆放、方向相关的偏移预设和可选跟随
轨道倾斜的行为已经确认；完整模型包格式见[已批准的模型包契约](model-packages.md)。
设备模型引用和摆放存档已实现；主信号的模型也已从统一 signal catalog 接入。
Signal Wand 已支持主信号及附属信号的轨道附着或方块面地面建造，并可用这两种摆放方式改位、换模型或删除既有进路表示器；
命名预设选择及表示器外观映射/入口编辑已接线，见[工具合同](section-authoring-wands.md#表示器映射作者与新建)；现有设备的位置、XYZ角度和轨道倾斜可通过[数值编辑](section-authoring-wands.md#实例参数数值编辑current)修改，拖拽和任意样式参数仍属后续范围。

SimpleSignals 负责模型包、摆放位置、外观映射，以及何时创建或关闭模型。
主插件提供通用的构造和显示能力，见[通用模型 API](../../bukkit-plugin/backend/model-presentation-api.md)。
轨道曲线查询、公开不可变模型定义、普通构造和完整场景应用由主插件提供；
公开模型服务负责跨线程调度。本模块加载模型包并把变化后的完整场景提交给该服务。
SimpleATOBukkit 不负责转发信号画面。

## 2. 从配置到显示的完整流程

1. 玩家为一个信号设备选择模型包，以及轨道附着或地面摆放方式；轨道附着使用有方向的轨道坐标和偏移，
   地面摆放直接使用世界位置和旋转。模型包提供不同外观对应的模型场景。
2. 加载或编辑配置时，SimpleSignals 检查引用，计算世界坐标和旋转，再取得操作模型的 `ModelHandle`。
3. 信号系统完成一次状态计算后，SimpleSignals 读取完整结果，找出外观确实变化的设备。
4. 对这些设备提交新的模型状态。主插件在正确的 Minecraft 线程上应用显示变化，不阻塞信号计算。
5. 设备删除、世界卸载或插件停用时，关闭相应模型。

信号控制的入口位置，不一定是模型实际摆放的位置。例如，进路预告机可以放在远处，
站台信号机可以放在轨道侧面。不能只根据逻辑入口就假定已经有了模型摆放配置。
本批把固定闭塞信号、保护区域信号和进路显示器统一为可选模型配置。控制的区间/入口绑定保持原样，
显示器原有的单独 `position` 不再作为第二份摆放坐标保留。

## 3. 哪些机制避免重复计算和错误显示

### 同一个模型支持两种摆放方式

轨道附着保存世界、轨道 UUID、从 A 端起算的弧长（米）和 AB/BA 方向。弧长不因方向改变而改成从
B 端起算；方向用于解释偏移的前后左右。模型可以提供若干命名的摆放预设，例如“轨道左侧”和
“轨道右侧”。Wand已支持数值编辑当前设备的偏移、旋转和倾斜；直接修改轨道坐标和方向仍属后续能力。
这些是摆放预设，不是信号规则输出的 `modelVariant`；改变灯色不能顺带改变模型位置。

模型可以声明是否跟随轨道坡度和超高，玩家可以为当前设备覆盖这个设置；两者均未指定时保持竖直。
玩家选择或主动重新应用摆放预设时，将当时选定的偏移、旋转和有效倾斜选项复制为设备自己的参数。
以后 Wand 修改的是这些实例参数；模型包修改预设不追溯修改已摆放设备，也不保存逐字段动态继承关系。
例如，预设的右侧偏移由 2 米改为 3 米后，已有设备仍用 2 米，重新选用该预设才改为 3 米。
这里复制的是参数值的语义，已不可变的值对象可以安全共享，不要求每次深拷贝整个模型定义。

不跟随时，使用有向切线的水平投影和世界竖直方向构成摆放参照；跟随时，使用有向切线和轨道法线。
SimpleSignals 将选中的偏移换算到这个参照中，得到最终世界位置与旋转。
例如，“右侧 2 米”指附着坐标所记录方向的右侧，而不是永远指 A→B 的右侧。

Wand 的两种编辑操作含义不同：改变轨道附着的 AB/BA 方向时，保留当前偏移值，按新方向重新计算
模型位置；只调整模型自身旋转时，保持摆放点不变，不旋转轨道偏移向量。例如，偏移为“右侧 2 米”
的设备从 AB 改成 BA 后会到轨道另一侧，而原地旋转模型不会。不要自动改变偏移符号来抵消方向编辑。
模型朝向在附着参照上叠加自身旋转，模型位置仍由轨道坐标与方向相关的偏移决定。

地面摆放直接保存世界位置和旋转，不要求轨道引用，也不应用任何轨道偏移预设或跟随倾斜设置。
模型本身的部件偏移仍然有效；忽略的是轨道摆放偏移，不是把部件树的变换清零。
两种摆放方式最终都交给主插件相同的 `ModelPose` 和模型显示接口，不增加第二套渲染器。
地面摆放只改变显示位置，不能取代信号逻辑所需的闭塞区间或保护区域绑定。

### 保留但未绑定的设备

设备逻辑绑定与模型摆放相互独立。固定闭塞主信号的`controlledBlockId`、保护主信号的`bindingId`、表示器的`entryBoundaryId`均可用显式null表达未绑定，不能以拼错/已删除的非空ID代替。未绑定仍保留signalType或model、设备ID/revision、placement及附属primary关系，不创建另一个“废弃设备”存档。

候选编译继续检查设备身份、catalog/model及真实摆放。固定闭塞未绑定设备不注册真实entry/观察根/inspection；主信号Unavailable，主模型及附属模型按原无效状态路径显示。表示器null入口必须配空映射，selection为空并使用自己的noRouteModelVariant；模型准备仍校验该外观。逻辑为空不等于隐藏设备，且不能伪造一个区间给规则计算。

runtime准备时按当前表示器定义建立不可变的无观测初始值：当前入口不可用、外观为明确noRoute，null入口的selection为null。普通定义编辑不继承旧物理baseline，尚无完成snapshot时表示器查询返回这些初始值；模型准备保存该设备自己的noSnapshotVariant，缺状态时也使用明确noRoute而非模型default。它不是伪造的epoch、occupancy或行车授权，不会把无观测解释为空闲。

已有publication交接只按当前表示器定义建立状态表：设备定义对象未变才可继承旧状态；变更/新设备复用上述初始值。删除的ID不进入新表，解绑不能沿用旧进路外观到下个baseline。即使删除最后设备后不再需要epoch source，也不能永久保留旧表示器状态；不为此新增轮询，收紧只发生在已有准备/交接步骤。真实manager回归须先产生带真实入口selection的旧baseline，再检查删除/解绑后的交接、模型及下一baseline；不把这种状态交接断言称为已验证真实放行资源申请。

current codec保持schema 1，writer对nullable绑定写明确null，reader不为缺失字段补猜测绑定，也不新增别名或旧开发reader。显式手动重绑通过同一事务提高原设备revision，只改目标绑定/必要表示器映射，不改变类型、模型或位置；目标存在相同ID不能自动恢复旧绑定。详细界面、旧/新编辑保护及无副作用拒绝见[工具合同](section-authoring-wands.md)。

必要回归为null绑定current round-trip、非空未知ID拒绝、无观察根仍保留主从显示、表示器无入口显示no-route、手动重绑和过期确认不改旧状态。解除绑定和模型变更沿用同一worker准备及原子publication，普通signal epoch只消费已准备输出，不新增每tick找目标或曲线定位。

### 显示绑定不在每 tick 重新定位

绑定准备取得不可变曲线后保存计算结果，信号状态更新只选择场景，不再次查曲线。
模型包修改摆放预设不使已有设备的位置缓存失效；玩家主动重新应用预设属于设备参数修改。
地面摆放不查询轨道曲线，轨道编辑也不改变其显示位置。两者都不需要每 tick 重定位。
定义提交后只替换逻辑绑定；模型操作对象由世界运行时持续持有，按设备差异更新。
模型引用、摆放参数及精确拓扑根都未变化时，复用已计算的姿态；
引用或摆放改变、或拓扑根替换时，在工作线程重新准备。全部可输出外观仍须校验，不能因为复用姿态就跳过。
presentation-only 设备保存选用的模型 ID 与实际摆放值；固定闭塞／保护主信号只保存
`signalType` 与实际摆放值，模型 ID 从 catalog signal 推导。两者都不保存曲线、最终计算坐标、模型树或预设名称。

### 设备模型引用与摆放存档（CURRENT）

附属信号和进路表示器使用显式 `model: DeviceModelDefinition?`：

```kotlin
DeviceModelDefinition(modelId: String, placement: ModelPlacement)
```

`modelId` 使用 model-only loader 的完整 `包名:模型名`，例如 `jr_four_light:head`；包名只含小写字母、数字、
点、下划线和连字符。模型名允许同样字符构成的包内 `/` 分隔路径，但每段不能为空或为 `.`/`..`。
这只是稳定引用，不是文件路径或 JVM 类名。`model=null` 表示不走显式模型路径。
定义构造校验引用语法；绑定准备另行检查已加载的包与全部可输出外观名，不在构造时读文件。

固定闭塞／保护主信号必须保存 namespaced `type`，可选 `placement` 只保存世界实例位置；模型和逻辑都从该
catalog signal type 解析。current schema 1 不接受主信号 `model`、provider union、规则表或 `packageSignalId`；
`placement` 即使为 null 也必须出现，避免旧的重复 modelId 形状被静默接受。

磁盘上的可选 `model` 位于每个设备内，只有 `modelId` 与 `placement`，摆放用稳定的 `kind` 区分：

```json
{
  "modelId": "jr_four_light:head",
  "placement": {
    "kind": "rail",
    "railId": "00000000-0000-0000-0000-000000000001",
    "arcLengthInAbMeters": 12.0,
    "facing": "BA",
    "adjustment": {
      "x": 0.0, "y": 0.0, "z": 2.0,
      "rotationX": 0.0, "rotationY": 0.0, "rotationZ": 0.0, "rotationW": 1.0
    },
    "followRailTilt": false
  }
}
```

`kind=rail` 的轨道、弧长和方向必填；省略 `adjustment` 使用单位姿态，省略 `followRailTilt` 使用
`false`。保存的是已经从预设复制/编辑出的值，不随模型包里的预设继续变化。
`adjustment` 的位置分量是局部米制偏移，旋转是局部单位四元数。
`kind=ground` 只有必填 `pose`，使用上述七个分量表示绝对世界位置/旋转；不接受 rail 字段或倾斜选项。
世界由外层 `worldId` 指定，两种摆放不另存世界 ID。姿态七个分量必填且有限，复用 `ModelPose` 的
四元数平方长度误差 `1e-9` 校验，不在解码时静默归一化。

一次配置编辑依次经过现有严格 JSON 解码、设备定义构造、完整候选编译、编辑许可、staged save 和
原子 publication 替换。解码拒绝未知字段、未知 kind、非法引用、非 canonical UUID 和非法数值；
候选编译对三类设备一致检查 rail 摆放的轨道存在及弧长在 `0..railLength` 内，不做曲线采样。
错误包含设备身份，拒绝整次候选，磁盘和旧运行定义不变。ground 与无模型设备不查轨道。
这一流程复用原有 patch/revision/许可，没有独立显示存档、模型 catalog 或额外写入事务。

编辑影响收集在旧、新 publication 都加入相关设备的 rail 附着轨道；从轨道 A 移到 B 时检查两者。
原有受控区间、入口进路及结构消费者范围仍受保护；地面摆放只是不新增显示附着轨道，不能绕过逻辑保护。
检查只在加载/异步编辑准备执行，按设备数线性遍历，并仅访问被引用轨道的 projection spans；
不扫描全世界轨道，不增添逐 tick 检查。JSON 开销与设备数线性，每台仅保存引用和一份摆放参数，
不复制模型部件树。

固定 current JSON fixture 必须覆盖三类设备、AB/BA、ground 和无模型缺省；再验证实际 encode/decode
保留姿态及已确定的倾斜值。负向测试覆盖非法数值/kind/字段、缺轨道/越界，以及三类设备修改模型后
仍需提高自己的 revision。实际 manager/edit-permit 测试须证明旧、新附着轨道均被保护、ground 保持
逻辑进路保护、无关轨道不进入许可，以及失败不改变磁盘/publication/source。

模型存档最初由用户明确批准直接修正尚未发布的 schema 1 草稿，删除旧显示器的顶层 `railId`/`facing`/
`arcLengthInAbMeters`，不增加虚构中间版本、旧字段别名或 runtime upcaster。这不同于承诺读取已发布存档；
如需保留真实旧开发服文件，应先另行确认一次性转换，不能自动猜测模型。
柱高等任意模型实例参数推迟设计；以后用独立字段区分于灯色 `modelVariant`，当前不加空占位字段。

源码入口为 `presentation/DeviceModelDefinition.kt`、三类设备定义及原有
`SimpleSignalsWorldDefinitionsCodec`。两类信号编译器和显示器编译调用同一 `validatePlacement`；
它只在引用轨道的 projection spans 中取得长度，不查空间坐标。现有 `DeviceModelPersistenceTest`
读取固定 current JSON 验证格式和值；manager 回归连接真实 Basic registry，验证四种设备行为
（保护信号分别覆盖固定进路与当前入口），不把替身 source 或 Paper 环境当成实际客户端显示。

### 主信号与附属信号机

CURRENT。已实现后端主从关系及 Signal Wand 的 rail-attached／ground 新建、更新和删除；
不包含测距、样式编辑界面或轨道标记。普通信号和保护信号仍负责计算限速与外观；
附属信号机只读取指定主信号已经发布的外观结果。中继信号机使用同一关系，不新增规则、检查声明、区间资源或停车点。
附属显示本身不实现双向控制。用户随后批准的[双向单闭塞](bidirectional-fixed-block.md)由闭塞定义提供两个真实入口，
两端独立规则已实现：每端自己的主信号和附属设备分别读取其signal ID的输出，物理闭塞仍共享占用与资源。
多闭塞协调不在本批；显式模型摆放不改变逻辑入口。

新增私有定义与同一世界文档字段：

```kotlin
AttachedSignalDefinition(
    signalId: String,
    revision: Long,
    primarySignalId: String,
    model: DeviceModelDefinition
)
SimpleSignalsWorldDefinitions.attachedSignals: List<AttachedSignalDefinition> // 缺省为空
```

附属 ID、主信号引用采用现有 namespaced ID 校验，revision 沿用现有单调规则。附属设备必须有模型，
复用现有 rail/ground 摆放；主信号可以没有模型。直接引用当前世界的固定闭塞信号或保护信号，
不接受附属信号、进路显示器或不存在的 ID 作为主信号，因此无需引入主从图或循环求解器。
附属设备 ID 不得重复或与普通信号、保护信号、显示器 ID 冲突。
每个附属模型必须能够表达主信号配置的全部外观；场景映射属于该模型，可以与主模型不同。
初始缺结果和不可用状态仍使用各自模型的 `default`。

准备时建立“主信号 ID → 显示设备列表”，主信号自身有模型时也放入列表。加载/编辑按定义规模线性建立索引，
保存不可变列表；共享模型与规则结果，不复制模型树或执行第二次占用检查。变化通知只查发生变化的主信号对应列表，
因此一次更新成本取决于变化的主信号及其相关设备数量，不遍历无关信号。初始画面仍按模型数线性提交一次。

附属模型使用独立稳定显示身份 `attached-signal/<signalId>`，复用世界级 handle 保留和旧回调隔离机制。
移动、增删、换模型或改绑主信号都经过已有完整候选、编辑许可、save/source/publication 事务；
编辑影响包含旧、新模型附着轨道和旧、新主信号的逻辑控制范围。仅修改一个附属设备不重建其他模型，
主信号配置变化则重新校验其附属模型所需外观。删除仍被引用的主信号拒绝整份候选，
可在同一 patch 中删除其全部附属设备；失败不改磁盘、source 或当前模型。

附属设备只新增默认空的 `attachedSignals` 列表及上述四个字段；这是有明确默认值的新增能力，不单独升级版本。
统一文件仍为未发布schema 1；删除默认进路及两端独立规则不建立新代际，误升的2/3已恢复，见[双向闭塞合同](bidirectional-fixed-block.md)。
不增加旧开发格式 reader、alias 或中间版本。现有 export/validate/apply/diff/inspect 路径一并识别附属设备。
必需回归包括固定 JSON 缺省/round-trip、非法引用和重复 ID、无模型主信号带多台附属、
主信号变化/不可用/default 传播、外观不变不提交、主从设备数量不改变规则/检查/资源数量、
改绑/移动后的 handle 保留、旧新编辑保护、删除引用拒绝和同批删除成功，以及卸载/旧回调清理。
这些测试仍是离线服务与后端验证，不证明实际 Folia 客户端画面。

### 已实现的摆放计算边界

以下计算能力已经实现，不包含包加载器、存档字段或 Wand 命令。
SimpleSignals 内有两种互斥的摆放值，以及把选中预设转换成实例参数的操作：

- 轨道附着：轨道 ID、A 端起算的弧长、AB/BA 方向、三轴偏移、模型自身旋转、已经确定的倾斜选项。
- 地面摆放：绝对世界位置和旋转。所属世界由绑定上下文给出，不附加虚假的轨道坐标。
- 预设应用：替换实例的偏移、模型自身旋转和倾斜选项，保留轨道 ID、弧长及附着方向；
  不保存运行期继承或模型包变更订阅。

计算器接收已取得的不可变曲线与轨道附着参数，或直接接收地面姿态，输出既有 `ModelPose`。
世界查询、文件读取和实体调度留给后续绑定层，计算器不持有 Bukkit 世界、可变轨道或设备管理器。

列车、轨道与信号模型统一使用局部 +Z 为前方、+Y 为上方、+X 为横向（上方向 × 前方向），偏移单位为米。
将采样切线按 AB/BA 定向：不跟随倾斜时投影到水平面并归一化，以世界向上为参照；跟随时使用
定向切线和轨道法线。取横向量为“上参考 × 前向量”，归一化后以上向量 = 前向量 × 横向量重新正交化。
世界位置为采样点加三个轴向偏移，基础旋转将模型局部 X/Y/Z 对齐这三个轴，再叠加模型自身旋转。
模型自身旋转不参与偏移向量的计算。BA 同时反转前向与横向，保持上方向；地面 Wand 使用相同模型轴，玩家 yaw=0 时基础旋转为单位旋转。旋转在计算边界复用已有单位四元数表示；Wand使用与模型包相同的XYZ旋转度数，未修改角度时保留原四元数，不强制Euler往返重写。
输入仍由 `ModelPose` 校验单位旋转；计算得到的最终旋转乘积归一化，消除组合舍入误差，避免把原本
处于合法单位误差内的输入误报成非法输出。不会修改输入对象或接受原本不合法的旋转。
开发期旧轴数据不在 runtime 猜测或兼容。本次不改版本常量；世界定义沿用已明确未发布的 schema 1，其他边界没有发布/冻结证据时不得猜测升版。
需要保留旧设备时，先离线归档并 dry-run：旧附着位移 `(x,y,z)` 转为 `(-z,y,x)`。若模型树本身同时以
`C=Ry(-90°)` 改到新根坐标，附着实例/预设旋转需共轭为 `C * q * C⁻¹`，地面绝对旋转为 `q * C⁻¹`；
模型根变换及选择框也需同步转换。若保持原模型树，则附着旋转为 `C * q`、地面绝对旋转不变。
两种转换方案不能混用；Wand 已复制的预设、持久化模型快照与恢复数据必须按其所属方案一起审计。
本次只同步仓库当前配置/fixture，不自动改服务器世界、旧 ZIP 或历史快照。
前后偏移是采样点处的局部直线位移；需要沿弯曲轨道挪动附着点时修改弧长，不把偏移当作另一次曲线采样。

曲线缺失、弧长越界、非有限参数或无法形成有效参照方向时返回明确的摆放错误，不产生 NaN 姿态。
该错误只属于显示摆放，不修改逻辑信号、资源或轨道。方向计算为常数次向量运算，曲线采样沿用已有二分查询。
计算器本身不建立位置缓存、编辑事务或显示任务队列；绑定层保存其计算结果并复用既有生命周期。

计算代码位于 SimpleSignals 私有的 `presentation` 包，不是新增的宿主公开 API。当前实现中的输入输出为：

```kotlin
ModelPlacement.RailAttached(
    position: RailPositionSnapshot,
    adjustment: ModelPose = ModelPose.IDENTITY,
    followRailTilt: Boolean = false
)
ModelPlacement.Ground(pose: ModelPose)
RailPlacementPreset(adjustment: ModelPose, followRailTilt: Boolean? = null)

RailAttached.applyPreset(preset, playerFollowRailTilt: Boolean? = null): RailAttached
ModelPlacementCalculator.calculate(placement: Ground): ModelPose
ModelPlacementCalculator.calculate(placement: RailAttached, curve: Curve?): ModelPose
```

这里 `adjustment` 复用已有不可变 `ModelPose`：位置三分量表示局部偏移，旋转四分量表示模型自身旋转。
它不包含另一份绝对世界位置。`applyPreset` 返回新的实例值，保留原轨道坐标；倾斜选项在这里按玩家、
预设默认、`false` 的顺序确定，计算时不再查找预设。地面重载没有曲线参数，也不接受轨道偏移。

轨道重载要求调用方提供该轨道的 canonical AB 曲线；计算器无法从不带轨道 ID 的曲线反查其归属，
也不额外建立匹配 registry。缺曲线、越界或无效参照抛出带轨道/位置上下文的 `IllegalArgumentException`，
数值类型继续复用 `RailPositionSnapshot` 的有限非负弧长校验及 `ModelPose` 的有限值/单位四元数校验。
用于归一化的向量要求平方长度大于 `1e-12`；这是拒绝退化方向的数值门槛，不是轨道位置的米制容差。

### 外观名由信号插件解释

规则输出的 `modelVariant` 是外观名称。SimpleSignals 将它映射为完整的“动画名 → 场景名”选择，
例如 `lamp -> green`。主插件不理解 G/YG/Y/R 的铁路含义，也不根据模型场景反推限速。

模型包解析后交给主插件的是已经展开的普通部件树，不是列车定义，也不是让显示线程继续读取文件的回调。
树、帧、变换、物品资源和复位行为由[主插件模型契约](../../bukkit-plugin/backend/model-presentation-api.md#4-公开接口与数据)
统一描述；SimpleSignals 不再维护一套相同的通用定义。
外观映射必须是完整场景选择。比如旧外观选择了 `lamp`，新外观没有再为这个部件选择任何动画，主插件应恢复其基础外观，
而不是让旧灯色残留。固定零插值只影响画面过渡，不改变信号计算或列车制动。

### 使用完整状态，而不是一半新、一半旧的结果

`SectionOccupancyRuntime` 先把区间占用、信号输出、进路选择和显示器状态一起替换为新的完整结果，
然后才发出显示通知。这就是这里所说的“发布”：新结果成为读者当前可见的结果，不是网络发送。
显示侧不能提前读取部分新结果，也不能在信号计算回调中操作 Bukkit 实体。

### 只检查受影响的设备

普通信号使用已有的变化 ID 列表。进路显示器使用已有的“入口 → 相关显示器”索引查找候选。
再比较这些设备的实际外观、位置和旋转；只改限速或进路附带信息而画面不变时，不提交显示更新。
因此不需要每次遍历全部设备。

配置增删改、初始加载和世界重载也要触发显示处理，不能只等待列车进入或离开区间。
配置替换只使旧逻辑绑定失效，不关闭未变化设备的模型。旧、新绑定共用世界内短提交锁，
旧回调在锁内确认自己仍有效后才可提交；旧绑定失效后，即使回调稍后完成，也不能覆盖新画面。

## 4. 内部处理步骤和数据约定

下面是生产绑定的处理合同，不是新增的存档结构。

### 生产接线与编辑边界

插件启动时除后端能力外，还取得 `RailTargetService`、`ModelPresentationService` 和编辑叠加使用的 `EditorTextService`；全部必需服务清单归模块索引。
后端世界安装不等待显示包；Paper 工作线程同时准备统一 `signal-packs/` catalog 和
`dataFolder/models` 的 model-only 直接子目录，各目录有
`manifest.yml`。根目录不存在表示空模型表；缺文件、包名冲突或包内容错误给出明确诊断，不猜模型或造占位。
整次发现结果只在启用时安装一次，不做 ZIP、热重载、定时扫描或独立模型存档。

世界模型准备接收当前完整定义、model-only 表和可选的同一不可变 signal catalog：显式设备解析 `modelId`；
主信号从 `signalType` 同时取得 catalog model/logic。准备阶段校验可确定的全部可能输出
外观；JS 输出还在同 epoch 求值后对该 catalog model 的 variant 表检查。随后计算轨道附着姿态，
保存共享模型及其场景表。地面摆放不查曲线。这一步不调用
`ModelPresentationService.create`；纯 validate 因此不会登记任何模型对象。
模型表尚未准备好或加载失败时，带模型的候选给出相应诊断；没有模型的后端配置仍可使用。

正式编辑仍只有原来的 save/source/publication 提交点。模型准备失败时保留旧配置、存档和模型；
提交成功时替换包含显示绑定的同一个 runtime state，并使旧绑定失效。模型对象与这次配置替换的生命周期分开：

- 设备仍使用同一份已捕获模型对象时，保留 handle、显示序号和上次提交的场景/姿态。仅 modelId 或结构值相等
  不足以跨另一 catalog/materialization 复用 handle；规则编辑在捕获模型身份未变时不重新创建模型；
  位置或旋转变化时，向现有 handle 提交新姿态。
- 新增模型配置时创建该设备；删除设备或移除其模型配置时，只关闭对应 handle。
- 同一设备换模型时，先关闭其旧 handle，再以原稳定 `objectId` 创建替代对象，不能同时登记两个同身份模型。

世界内沿用既有工作线程生命周期锁串行对照实际 handle 集合与当前配置；不能假定连续编辑的工作线程
按提交顺序运行，也不能让旧任务关闭已经保留或新建给当前配置的对象。创建/关闭在提交锁外执行，
manager 提交锁和物理线程不等待模型树构造或实体清理。
差异遍历、保留集合和新增集合的合并均在工作线程、短提交锁外完成；锁内只复核当前绑定并交换集合引用。
显示创建故障只清理本次新建部分，保留无关的既有模型，不反向回滚已生效的安全定义。
创建期间被更新配置或卸载取代属于正常取消：同样只清理本次新建部分，不记录为显示故障。

初始异步安装须重新核对 runtime 对象与当前 publication。准备期间发生编辑则重新为当前值准备，
不能仅丢掉旧候选就永久失去显示。相同 UUID 的新 runtime 不接收旧世界的排队工作；卸载后不再创建模型。
局部拓扑重验提交新的 exact topology root 后，复用同一模型 worker 为当前 publication 重新准备轨道附着姿态；
安装仍复核 runtime、publication、topology、旧绑定和 catalog 身份。地面摆放可复用姿态，但不能借此跳过整份绑定身份检查。

### 初始画面与后续变化

`SectionOccupancyRuntime` 先替换其已有完整 `PublishedState`，再通知它自己的显示绑定。
不另建信号事件队列，也不复制全部状态作为显示载荷。普通信号使用 `changedSignalIds`，进路显示器
从已变化入口的 `indicatorsByEntry` 取得候选。绑定只查这些设备，比较完整场景并调用公开 `submit`。
世界内 `SignalModelHandles` 保存实际 handle、上次场景/姿态和显示序号；
每次配置的 `SignalModelBinding` 只保存该配置的设备选择、准备好的姿态和回调有效性。
提交序号跟随实际 handle 递增，保留 handle 时不能因配置替换从零重来；不写磁盘、不用来区分世界或配置。

模型尚未创建时跳过通知；创建完毕后读取一次最新完整状态补初始画面。
旧、新绑定共用这份短提交锁。配置交换先等待已经开始的公开提交完成，再使旧绑定失效和安装新绑定；
之后旧回调不能访问保留的模型。这里等待的不是实体操作，公开 `submit` 本身按宿主合同非阻塞。
补画面与后续回调通过该锁及既有 `physicsEpoch` 排序：较早捕获的初始结果不能覆盖
已提交的较新结果。首个被接受的状态为所有模型初始化场景，此后才只处理变化 ID；
否则一个较新的局部变化抢先提交，会让其他模型永久漏掉初始画面。
不存在状态时选 `default`；有状态则按下面的明确外观规则选择。
此锁内不读取文件、不采样曲线、不构造模型树、不创建实体，也不同步写日志；显示故障在退出锁后报告。

删除设备只关闭其对应 handle；世界卸载使旧绑定立即失效，然后在提交锁外关闭世界内全部 handles。插件停用不等待正在创建模型的
工作线程；异步收尾先关闭这些 handles，再合并观察主插件模型与编辑文字服务各自 `closeOwner` 的完成结果。记录完成或失败，
不能把“已请求清理”报告为“实体已删完”。不新增另一套资源卸载门禁。

实际私有入口是 `SimpleSignalsModelPackages.load(Path): Map<String, LoadedPackageModel>`、
`SignalPackLoader.load(Path): SignalPackCatalog`、
`PreparedSignalModels.prepare(definitions, models, rails, topology, previous, signalPacks)` 和 `SignalModelBinding`。
插件提供 `fun modelCleanupCompletion(): CompletionStage<Void>`，供停用流程观察异步清理；
它不是阻塞卸载命令，也不表示列车资源已释放。调用方不能在区域线程上等待这个结果。

```text
准备模型绑定：
    检查摆放方式、模型引用和外观映射
    若为轨道附着：
        检查轨道位置，按世界 UUID 和轨道 UUID 取得曲线
        按 A 端起算的弧长取得轨道上的点
        按记录的方向和实例已经保存的偏移、旋转及倾斜选项计算世界位置与旋转
    若为地面摆放：
        使用保存的世界位置与旋转，不读取曲线或应用轨道偏移
    保存解析后的绑定、模型定义和位置结果
    读取当前已发布结果；尚无结果时选择模型包的 default
    提交初始完整显示状态

信号系统发布完整结果后：
    遍历本次可能受影响且已配置模型的设备
    读取设备的新状态
    若为 Unavailable，选择模型包的 default
    否则按明确的 modelVariant 查找场景；找不到则报告配置错误，不使用 default 兜底
    若场景、位置和旋转与上次提交相同，跳过
    否则增加该模型的显示序号，提交位置、旋转和场景

设备删除或世界卸载：
    关闭该设备的模型操作对象
```

### 已确认的默认显示规则

只有 **SimpleSignals 模型包**必须显式提供 `default`。它是一份完整的“动画名 → 场景名”选择，
不是主插件通用 `ModelDefinition` 的必填字段，也不要求列车、轨道或其他附属插件采用相同规则。
主插件只接收最终的场景选择，不知道它来自普通外观还是 `default`。

- 初始绑定尚无已发布信号结果，或已有结果为 `SectionSignalState.Unavailable` 时，选择 `default`。
- 有效结果明确给出 `modelVariant` 时，只使用该名称对应的完整场景选择。
  名称没有对应映射属于配置错误，不允许静默回退到 `default`。
- `default` 的内容由包作者决定，可以是红灯、熄灯或其他故障外观；代码不固定灯色或场景名。
  它必须存在且是有效映射；显式空映射 `{}` 表示恢复全部部件的基础外观，不等于缺少配置。
- 内部的 `Unavailable` 状态不改名；它仍表示没有有效信号输出并保持既有 0 限速。
  `default` 只决定画面，不能改变这个安全结果，也不能默认保留上一幅放行画面。
- 正常的 0 速度输出和进路显示器已有的 `noRouteModelVariant` 都是明确的外观选择，
  不能仅因“红灯”或“没有进路”就跳到 `default`。
  表示器逐进路映射可以缺项；缺项进路被选中时同样使用这个明确的无进路外观，不是模型默认场景，也不把空场景声称为不可见。当前校验/投影见[表示器作者合同](section-authoring-wands.md#表示器映射作者与新建)。
- 设备已删除、世界已卸载或插件停用时关闭模型，而不是把失效绑定永久保留为默认显示。

### 外观映射配置

以下只展示外观映射；要加载一个模型，还需完整包入口与部件定义，见已实现的[模型包格式](model-packages.md)。
示例假设部件树已经定义动画 `lamp` 及其 `dark`、`red`、`green` 场景：

```yaml
default:
  lamp: dark
variants:
  stop:
    lamp: red
  proceed:
    lamp: green
```

这里的 `stop`、`proceed`、`lamp` 和场景名都只是作者选择的名称，没有内置语义。
初始无结果时显示 `lamp: dark`；正常结果为 `proceed` 时显示 `lamp: green`；之后状态变为
`Unavailable` 时重新提交完整的 `lamp: dark`。正常结果若为没有配置的 `proceeed`，则报告名称错误，
不能把拼写错误伪装成正常默认显示。`default` 也不是在缺失普通场景条目时逐项合并的补丁：
每次仅选择一个完整映射，未命中的部件按主插件契约恢复基础状态。

模型绑定是可选的：没有配置模型的信号仍能执行后端规则。但如果配置了模型，引用缺失时必须明确报错，
不能静默替换成占位模型并声称配置成功。

## 5. 线程和清理规则

显示不改变行车授权，也不能阻塞信号计算周期。模型加载和解析在工作线程上完成；结果安装前
还要确认对应的配置和世界仍有效，避免把编辑前的结果装回去。
模型内部的显示序号只用于舍弃旧画面，不写存档，也不是资源的身份。

插件正常停用时，先经过 Basic 既有的资源占用检查，允许停用后再清理显示。
强制停用仍按已有安全规则处理。删除模型实体与释放列车资源是两个不同操作，不能用前者代替后者。
停用 JavaRailways 主插件前，必须先停用 SimpleSignals 等附属插件并完成其显示清理。
区域线程删除模型可能晚于 `onDisable` 返回；应使用主插件显示服务的清理完成结果确认，
不能在物理或区域线程上阻塞等待。完整规则由上述主插件模型契约维护。

## 6. 配置或显示失败时怎么办

轨道附着找不到轨道或位置超出轨道长度时，应拒绝这次模型绑定并记录具体原因。
选择或重新应用预设时检查预设存在性；已有设备使用自己的参数，不能因原预设被删除就拒绝恢复它。
地面摆放不做轨道存在性检查。两种方式都检查位置和旋转的有效性、模型存在性以及正常外观映射。
这些错误不能改变既有行车授权，更不能让列车因此获得放行。

缺少 `default`、其值为 null、引用未知动画/场景或同一部件的场景选择冲突时，拒绝安装该模型绑定。
已知的正常外观映射同样在安装前检查；默认外观存在不能掩盖其他映射错误。
规则状态不可用时，选择上述 `default`。实体创建或线程调度失败时，报告显示故障并清理已创建部分，
不能把显示错误抛回信号计算回调。服务器也不能声称已经确认客户端资源包安装正确。

## 7. 性能开销在哪里

模型解析在准备阶段执行。轨道附着的定位进行一次轨道 ID 查询、一次 `O(log N)` 弧长采样和
常数次坐标变换，N 是轨道曲线的采样点数；地面摆放的定位直接读取姿态，成本为 `O(1)`。
这些都不是每 tick 执行的流程，也不因新增轨道摆放预设而每次遍历全部预设。

处理一次信号结果时，成本为 `O(C + M)`：C 是变化列表或入口索引找到的候选设备数，
M 是比较这些设备场景映射所需的总条目数。只有实际改变外观、位置或旋转的模型才产生实体更新。
主插件可以合并尚未显示的旧画面，但不能合并或丢弃信号系统必须处理的安全事件。
首次场景提交另需按已绑定设备数线性初始化。定义编辑仍按设备数线性校验引用和外观，并在工作线程
线性对照实际模型集合；未变摆放且精确拓扑根相同时不重复采样。只有新增或更换模型的设备承担
模型树构造/索引成本，删除只关闭对应模型；修改规则不重建全世界的模型。
加载时保存经过校验的不可变 `default` 和外观映射；选默认值为 `O(1)`，按外观名称查表为期望 `O(1)`。
这些选择不扫描全部模型，也不在状态变化时重新解析 YAML；完整场景比较和实体更新仍有上述各自的成本。

显示慢只让画面暂时落后，不让物理等待。大量加载或建造时的实际成本仍要测试，
不能因为更新队列有上限就声称所有操作都不会卡顿。

## 8. 具体使用情形

- **进路变化：** 规则给出新的外观名称，SimpleSignals 选择模型包中的对应场景，更新真实的多部件模型。
  进路预告机可以读取同一个逻辑源，但独立配置摆放位置。
- **只有限速变化：** 列车控制读取新限制；如果模型外观没变，不更新实体。
- **只修改规则：** 保留全部模型操作对象；新信号结果按原显示序号提交，外观不变则跳过。
- **只调整位置或旋转：** 保留该设备的模型，提交新姿态，不删除实体树。
- **新增、删除或更换模型：** 只创建/关闭对应设备。旧回调不能覆盖保留对象或新对象的画面。

## 9. 实现时必须验证什么

当前 `ModelPlacementTest` 与 `ModelPlacementCalculatorTest` 已覆盖下列摆放、预设和几何断言，
使用真实 `PrimeCurve` 及独立推导的位置/轴向期望；包括组合坡度、超高、局部旋转和合法单位误差边界。
生产绑定回归还需检查实际服务调用、完整状态交接和生命周期；真实实体和客户端的断言不能用记录式服务代替。

- 初始显示、外观变化、不可用状态，以及增删改模型绑定，都得到配置要求的结果。
- 验证无初始结果 → 普通外观 → `Unavailable` → 恢复普通外观的完整选择序列；没有额外信号事件时也能提交初始默认画面。
- 缺少/null/非法 `default` 拒绝绑定，显式 `{}` 恢复基础外观；未知普通外观名称报错，不静默走默认值。
  正常 0 速度输出及进路显示器的明确无进路外观仍按自己的映射显示；不向主插件通用模型增加此必填约束。
- 只改速度或显示器附带信息，而外观不变时，不产生实体更新。
- 用至少两台设备验证规则编辑、位置/旋转编辑、增删及换模型的 create/close 次数和 handle 身份；
  未变化设备保留对象及显示序号，位置变化提交新姿态但不重建模型。
- 复用姿态仍校验全部外观；候选失败不改磁盘、source 或既有模型。部分创建失败只清理本次新增对象，
  不关闭无关的保留对象；旧回调与新配置交错时不能回写新画面或关闭保留对象。
- 旧回调、世界卸载/重载和插件停用不会留下或重新创建旧模型。
- 初始画面与较新局部变化交错时，所有设备都完成初始化；连续编辑的创建次序颠倒时，
  按实际 handle 集合对照当前配置，不出现稳定身份重复，也不关闭更新配置保留的对象。
- 显示失败不影响信号安全输出；AB/BA 摆放与外观映射通过不依赖实体的计算测试。
- 轨道附着的左右偏移随保存的 AB/BA 方向解释；方向不改变弧长从 A 端起算的约定。
  摆放预设与信号外观独立，灯色切换不改变摆放位置；Wand 编辑实例不修改模型包的共享预设。
- 对有非零侧向偏移的设备，翻转附着方向保留偏移数值并移动到新方向对应的一侧；只修改模型旋转
  不改变摆放点，不能把这两种操作实现为同一个自动保持世界位置的编辑命令。
- 选择预设后修改或删除包内预设，不改变已有实例参数；主动重新应用才采用新值。改变一个实例
  不影响同预设创建的另一个实例，且不需要复制整份模型部件定义。
- 在有坡度和超高的轨道上，模型与玩家均未指定跟随且无额外旋转时，模型保持世界竖直；模型可以
  默认跟随，玩家也可以显式覆盖为不跟随。改变模型摆放不改变逻辑入口、停车位置或行车限制。
- 地面摆放无需轨道，忽略轨道预设但保留部件变换；附近轨道编辑不移动模型，两种方式使用同一显示服务。
- 用独立 Java 调用示例验证公开接口，另在实际 Folia 服务器中检查模型和资源包的显示效果。

生产接线回归使用真实目录加载器、曲线、world runtime、信号 epoch 和定义提交，
显示端使用记录式公开服务。`SignalModelBindingTest` 和 `SimpleSignalsWorldRuntimeManagerTest`
覆盖首画面竞争、连续编辑反序启动、保护信号/显示器、纯验证、失败保留旧状态、
卸载/停用中途取消及清理完成失败。模型保留回归记录真实 create/close 调用、对象身份、姿态和显示序号；
分别暂停旧信号计算和已经开始的公开 submit，验证新配置接管后旧画面不能回写。
manager 流程还验证完整编辑事务、位置缓存的精确拓扑根边界及缓存复用时的外观校验。
每批检查命令和实际数量记录在任务 implement.md，不把离线数量当成客户端验证。
这些证据不证明真实 Folia 实体、玩家可见画面或客户端资源包已正确安装。

## 10. 已确定的边界与后续工作

模型存档沿用同一个未发布世界定义文件；直接修正范围见上文，当前文件版本为schema 1，模型包版本不变。
不因为分批实现就连续升级版本，也不为开发中的接口草稿增加旧格式兼容代码。
`default`、两种摆放方式、方向相关的轨道偏移预设，以及模型默认/玩家可覆盖的倾斜选择已确认。
Wand 修改附着方向时保留偏移值重新定位，原地转动只修改模型旋转；预设采用选择时复制、实例独立保存，
不建立动态继承。上述首批计算范围及 X 横向/Y 上/Z 前的约定已实现并通过离线测试。
包目录、加载和度制角度字段已确认并实现，见模型包契约；只给新的独立包入口一个格式号。
设备摆放序列化和生产绑定按本合同实现；Wand已提供rail/ground两步摆放、命名轨道预设选择及既有实例参数数值编辑，具体交互与物品偏好归[建造工具契约](section-authoring-wands.md#实例参数数值编辑current)。本批不修改持久化形状，不因分批开发增加临时版本或兼容代码。
柱高等模型实例参数以后单独设计，首批使用预先配置的不同模型 ID；不能把柱高编码成灯色外观，
也不能声称当前静态加载器已经支持任意参数替换。

实现中不要每 tick 扫描全世界信号，不要在通用模型代码里写死灯色，也不要通过 SimpleATOBukkit 转发显示。
由 SimpleSignals 解释外观映射、提交变化后的模型数据，主插件只负责普通模型的构造与线程调度。
用一个普通物品充当单灯占位，不能算完成了这里要求的模型系统。

### 当前显示问题

模型分配或提交失败通过对象ID加入宿主当前世界Issue列表，保留既有模块错误日志。
后续有效显示提交解除该对象的显示错误；显示准备失败记录受整批准备阻断的已摆放设备，准备成功解除。
定义删除时清除对应设备问题，旧binding或旧world runtime的迟到结果不得重新加入。该回调复用已有变更提交，不新增逐tick扫描。
