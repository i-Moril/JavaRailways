# 轨道编辑后的区间局部重验

## 负责什么

SimpleSignals 负责判断轨道编辑后，哪些固定闭塞、保护区域、进路和信号仍可使用。
Core 只报告一次成功轨道事务改变了哪些轨道；Basic 保留通用占用与资源职责，不认识这些信号领域对象。
运行时不再用“世界拓扑版本变了”判定所有区间过期。版本仍标识快照，编辑候选仍须防止覆盖并发修改。
当前批次的测试结果见任务 `implement.md`；离线测试不等于真实服务器压力测试。

## 一次轨道编辑如何处理

1. 原有编辑许可先检查时刻表引用和列车持有的资源；相关运营线路仍不能修改。
2. Core 验证成功事务的物理结果，在新拓扑对运营可见前发布 `RailTopologyChange`。
3. SimpleSignals 按受影响 rail UUID 查反向索引，将命中的区间和依赖它们的信号标记为暂不可用。
   此时旧结果不能继续放行，但不删除定义、进路、信号设备或 Basic 已持有的资源。
4. worker 在不可变新拓扑上重验命中的对象。闭塞检查有向路径、连续性及禁止经过道岔；
   保护区域沿玩家边界做有距离上限的完整性搜索，再检查区域重叠和保留进路。
5. worker 通过原有原子 source 替换入口一起发布区间几何、占用来源和信号规则。
   通过检查的部分恢复；不通过的保留配置和禁行范围，等待后续修复。

无关区间不重算几何，也不因世界版本增加而丢失占用、信号显示或列车检查绑定。
Core 通知和 Basic/SimpleATO 的局部有效性合同分别见
[物理拓扑](../../javarailways/core/versioned-operational-topology.md)、
[监测区占用](../../javarailways/basic/railway-area-occupancy.md)和
[信号周期](../../javarailways/simpleato/reactive-signal-epochs.md)。

## 如何找到相关对象

`SectionTopologyIndex` 保存 rail UUID 到区间、进路信号的反向关联，以及信号提供者到消费者的依赖。
区间自身路径、保护边界、已解析内部和信号下游检查经过的轨道都进入关联。
失效对象继续保留旧范围和此次发现的新轨道，不能从索引中消失，否则修复轨道时找不到它。
若新增连接使两个区域重叠，双方都保留导致重叠的轨道依赖；拆掉该连接时必须能重新检查双方，
不能让没有直接编辑边界的另一方永久留在不可用状态。

一次事务可能同时改两处不相连的线路。每个对象只吸收与自己相连的那部分事务影响，
不能把整份事务轨道集合分配给每个区域。新侧线未封口时，它和旧区域一起被禁止用于 ATO；
不能只在原入口拦截而让列车从新支线直接申请进入。

禁行范围按 rail 建立索引，选路限制与直接资源申请共用这份结果。
直接申请只检查本次授权距离内的实际交集；尚未请求的远方区间不提前阻断此前可用范围。
信号依赖失效按既有单向依赖关系传播，不引入新的循环求解器。

## 发布、线程与恢复

`SectionTopologyGuard` 是 runtime 内的局部有效性状态，不是新的资源管理器或存档。
Core 通知中只查关联、标记状态和安排 worker；允许在本次事务影响的轨道集合内判断连接归属，
不能在此搜索整个区间或路网、编译区域几何、读写文件或等待平台线程。
图搜索、规则编译和候选构造在 worker。提交只交换准备好的状态；原有模型对象继续保留。
监听注册属于确切 world runtime，卸载时关闭，相同 world UUID 重载不复活旧回调。

worker 记住开始时的定义对象和待处理依赖集合。相关依赖再次改变，旧结果不得发布；
只有无关线路改变时，仍可提交已有计算结果，不因世界 root 不同而作废。
同一 runtime 合并待处理工作，不为每次事件新建一条长期事件记录。
世界关闭、定义被替换或 worker 出错时不能复活旧结果；失败范围保持不可用并记录错误。

不可用监测区保留“最后已知有谁占用”的信息，另用可用性明确表示几何不能再作为放行证明。
不能把没有有效观测误报成空区间，也不能伪造列车离开事件来清空资源。
恢复依赖新的合法几何和后续物理观测，不由信号插件主动释放 Basic 的 claim。
仍有作者定义但暂时无法编译的保护进路，同样保留最后已知占用并标记不可用；不能只为固定闭塞保留这项信息。

后台准备不能冻结运行中的信号结果。准备开始后，旧来源仍可能完成更新：例如无关闭塞从空闲变为占用。
新的区间 runtime 在建立首个物理观测前，借助既有 `EpochContinuity` 的单个可见引用，
读取最后实际完成周期的未变信号；受影响信号仍保持不可用。逐信号查询为常数时间，
不复制一条历史 runtime 链，也不在提交时等待物理线程。新来源第一次处理周期时接续最新占用与清除记录。
若首次新观测到来前连续替换两次，新来源必须继承前一次尚待观测的对象集合；
第二次无关编辑不能让第一次编辑影响的信号提前恢复放行。
禁止在后台复制旧“空闲”结果，稍后用该副本覆盖已经到达的“占用”结果。

## 成本与边界

设事务影响 `A` 根轨道，反向索引命中 `H` 个对象，依赖传播访问 `D` 条关系，
候选发现成本随 `A + H + D` 增长，而不是逐个重验世界所有区间。
目前通知阶段还会扫描尚未完成重验的依赖集合，并浅复制待处理/禁行索引的映射；
这部分随当前待处理和不可用范围规模增长，但不重新遍历所有历史失效对象的几何。
不能把整个通知回调宣称为严格 `O(A + H + D)`。
保护区域搜索仍受 `protection-region-max-distance-meters` 限制；局部搜索约为 `O((V + E) log V)`。
完整候选构造、反向索引构造及宿主占用来源替换仍可能随已配置对象总量增长，但在 worker 完成；
不能把本实现描述为所有工作均为 `O(受影响对象)` 或完全没有发布成本。
正常物理周期不新增图搜索、全世界区间重验或按列车重复执行共享信号规则。

## 具体情形与必须验证的行为

- 闭塞内新建道岔：仅相关闭塞不可用；移除道岔、恢复合法路径后可重验恢复。
- 咽喉增加未封口侧线：区域停用，原进路和设备保留；补上玩家边界后重验，不能从侧线绕过禁行。
- 删除区间引用轨道：通过旧索引仍能命中对象，配置不被自动删除。
- 同一事务编辑两处不相连线路：两处影响分别归属，不互相扩大禁行范围。
- worker 运行时编辑无关线路：原计算可提交；再次修改相关线路或卸载世界：旧计算不得提交。
- 新监测区来源准备时发生轨道事务：宿主当前与候选来源都收到必要失效，不丢事件。
- 准备后旧来源又处理了列车进入：提交后、首个新来源周期前，无关信号仍读取最新占用限制，不倒退为空闲。
- 两次不相交编辑均在下一次观测前发布：两次影响的信号都等待新基线，未编辑信号继续读取最后完成的周期。
- 两区域因新连接重叠后拆除连接：双方都能恢复；失效保护进路的非空占用记录保留且不可用。
- 无关列车保持同一冻结路线和 grant，设备准备、继续申请及车尾释放继续；相关编辑仍受原许可阻止。

测试入口为 `SectionTopologyRevalidationTest`、`SimpleSignalsWorldRuntimeManagerTest`、
`SignalEpochRuntimeTest`、`RailwayAreaOccupancyTrackerTest` 和 `RouteResourceAdmissionEngineTest`。

## 存档与未完成事项

派生索引、可用性和事务通知不写入定义存档；本批不改格式、不加旧开发数据兼容。
尚无把信号坐标自动迁移到分割/合并后新 rail UUID 的机制。遇到这种引用变更，保留配置并禁止相关区域用于 ATO，
不能猜测位置、偷偷删除定义或声称已经完成自动坐标迁移。模型重定位、可视化和工具交互优化不属于本机制。
本合同处理已安装 runtime 的在线轨道事务。启动时存档已引用无效轨道，仍按现有世界安装失败处理；
不把它称为已实现逐对象启动恢复。附着模型引用的轨道缺失时，完整作者编辑仍可能被模型校验拒绝，
需修正对应摆放引用；后台拓扑重验本身不删除已有设备。

### 当前问题列表

SimpleSignals通过宿主`WorldIssueService`按世界汇总已发布的不可用区间、保护区域和未绑定/无可用进路信号；
安装、作者定义提交、后台拓扑重验成功后从既有不可用索引更新，不增加tick全世界扫描。
重验异常记录命中的对象及原异常，后续重验成功解除。规则求值只在既有dirty求值状态变化时报告真正错误，
正常停车、红灯、无进路等待不作为求值异常；成功求值解除对应错误。设备删除清除其旧规则问题。
世界卸载与插件停用清空本插件来源，不能删除其他生产者的问题。旧runtime/旧publication的迟到回调不能复活问题。
