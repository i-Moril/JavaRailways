# 轨道编辑事务触发区间重验

## 用户已确认的流程

轨道编辑事务 → 受影响轨道 → 关联闭塞／保护区域去重 → 新拓扑上的规则检查 → 更新可用状态。
新增道岔、删除轨道、追加侧线等是这条流程的测试情形，不分别建立操作监听器。
本批实现状态和实际验证结果以任务 implement.md 为准；本文不表示功能已经完成。

## 实施边界

- 复用已有轨道事务和编辑保护，不增加另一套资源授权或保存事务。
- 事务影响包含旧、新轨道及连接变化的既有轨道。删除轨道通过编辑前关联找到区间。
- SimpleSignals 拥有轨道到区间的关联和区间规则；Core／Basic 不认识闭塞或保护区域。
- 相关旧检查结果须在新拓扑开始用于运营前停止放行；重算在 worker，无关区间继续使用。
- 创建和重验遵循相同完整性规则；保护区域搜索保留既有距离上限，不能无界遍历路网。
- 无效对象保留定义、进路、设备及修复依赖；新增侧线不能绕过禁行。修复事务自动重验。
- 既有占用仍由 Basic 管理，手动驾驶不加入 ATS。
- 不做模型、可视化、预设、测距、格式升级或旧开发数据兼容。
- 普通分割／合并若有等价坐标换算，应沿用已有替换机制；不将轨道 ID 改变本身当作安全证明，
  也不能未经讨论静默删掉信号配置。需要扩大范围时先说明。

## 必须验证的情形

- 闭塞内部出现道岔：保留配置但不放行；恢复合法路径后重验成功。
- 保护区域新增未封口侧线：仅关联区域停用；补边界后恢复，原设备和有效进路保留。
- 删除轨道、改变连接、相关邻轨变化不会漏掉旧区间；无关区域不重算、不停用。
- 不可用对象继续被修复编辑找到；新支路直接资源申请不能绕过禁止驶入。
- 被编辑保护拒绝、无变化或提交失败的事务不能被当作成功拓扑修改。
- worker 完成前不使用相关旧结果；连续编辑、世界关闭或重载不允许旧结果重新生效。
- 没有新增逐 tick 图搜索或全世界区间轮询。

## 接入检查发现的前置问题与已批准修正

Core prepared 轨道事务有明确提交点和 delta，但目前没有附属插件可订阅的事务通知。
仅在 SimpleSignals 增加关联区间重验不足以保证其他线路继续工作：

- `Basic/observation/RailwayAreaOccupancyTracker.validateStamp` 要求每个已注册占用区域的拓扑版本等于新观测；
  无关轨道修改也会使旧区域不再满足此条件。
- `SimpleATO/signal/SignalEpochRuntime.process` 在区间 source 更新前先处理占用观测，
  不能寄希望于异步 source 更新在下一次 epoch 前恰好完成。
- `SimpleATO/timetable/TimetableDispatcher.routeAdmissionCandidate` 对已冻结路线检查世界拓扑版本，
  不相等就进入 `REPLAN_REQUIRED`，未区分事务是否修改该路线。

用户已明确批准替换这些运行时全局版本校验：世界拓扑版本仅标识快照和用于诊断，
不能继续作为所有运行对象是否有效的共同条件。Core 的轨道编辑事务报告影响集合；
依赖相交者停用／重验，未相交者保留占用状态、冻结路线和已有授权，不要求重新寻路或重新申请。
既有时刻表与运行资源的防编辑保护保留；世界、列车、路线身份及物理 epoch 顺序检查保留。
编辑候选提交的 exact root 检查仍防止覆盖并发编辑，但失败只拒绝本次编辑，不能使无关行车失效。
不增加逐轨道或逐区域的另一套版本计数，也不能仅删除断言而让真正受影响的数据继续放行。
异步重验结果只因其依赖范围又被改变而过期，其他线路施工不应打断它。

本批实施覆盖 Core／Basic 的中立事务影响通知和占用／资源有效性、SimpleATO／宿主的运行接入，
以及 SimpleSignals 的关联区域重验。实现和测试未完成前，不声明无关列车连续运行已经验证。
