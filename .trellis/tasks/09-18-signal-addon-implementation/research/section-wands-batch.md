# 闭塞与保护区域工具：本批实施边界

## 用户授权与目的

接续已提交的独立道岔工具，实施已经讨论确定的闭塞和保护区域建造交互。
不先做进路录制，不设计信号规则预设，也不要求再次确认已有交互决定。

目前缺口不仅是点击界面：现有正式定义事务只接受完整区域，不能表达玩家正在补边界的过程。
本批把工具接到原有定义事务，同时补齐必要的作者数据和局部不可用状态；不另建保存、锁定或列车资源体系。

## 实施范围

- SimpleSignals 自有两个工具：闭塞建造/删除，保护区域有向边界建造/删除。
- 闭塞两点建造、选择旧分界点接续、自动推导全路径运营方向、禁止经过道岔；不询问名称、方向或确认。
- 有向保护边界放置后自动尝试补全，未标记尽头不闭合；搜索距离为沿轨道到最远位置，受配置上限约束。
- 同轨道坐标吸附；边界位置共享不合并删除职责，重合处必须先删闭塞。
- 闭塞删除连带清理其逻辑信号及附属显示。保护区域缺口保留区域身份与配置，不可用于 ATO 放行，补齐后重新校验。
- 方向失配取消旧低速策略，明确拒绝 ATO 进入；手动驾驶不变。
- 路径搜索、候选编译与文件保存均在 worker；复用 expected revision/runtime 身份和现有编辑许可。

## 不做

独立信号机放置工具、测距、进路录制与通路预览、规则预设/模板、完整 TextDisplay 可视化、
生存物品消耗、单线多闭塞协调、存档迁移和兼容适配。已有模型显示能力不重新设计。

## 所有权与验证

领域与持久化归 SimpleSignals，宿主只消费既有公开 API。不让 SimpleSignals 导入宿主 AbstractWand。
平台层只捕获玩家动作/视线和调度，领域层提供可测试的选点、路径、删除和补全操作。
改动集中在 SimpleSignals 的 authoring、region、block、runtime、persistence 和插件接线；任务/spec/docs 由主 agent 维护。

测试覆盖完整和失败交互、端点接续、跨轨道方向、直向道岔拒绝、范围上限、缺口保留/修复、重合删除次序、
无内部重叠、防编辑许可和保存原子性；平台测试验证权限、world/玩家失效、异步及重复点击处理。
离线门禁使用 SimpleSignals check、公共 Java consumer 编译与插件打包；不能把替身调度测试称为真实 Folia 验证。
