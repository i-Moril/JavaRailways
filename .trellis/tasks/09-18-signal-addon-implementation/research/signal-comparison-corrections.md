# 信号对照审查后的修正批次

## 用户决定（2026-10-05）

- 保护区域放行前，应利用列车长度确认列车可以完整驶出，而非仅获得到出口的授权。
- 取消默认进路，不保留无列车请求时按默认道岔状态放行的规则。
- 修复源码审查确认的其他问题，不把参考对话的全部建议都当作已证实缺陷。

## 当前进度（2026-10-06）

有效请求放行、出口整列车净空、双向闭塞两入口独立规则均已实现并独立检查，完成记录见[实施清单](../implement.md)。
未发布文件误升版已按用户要求恢复为schema 1；版本决定先遵守[发布基线门槛](../../../spec/javarailways/shared/versioning.md)。
已有距离输入和循环信号依赖的[有界方案评审](distance-and-cycle-rule-review.md)也已完成，三项已批准修复及本轮评审均有完成记录。
用户随后已选择JS处理距离敏感逻辑，不扩展距离条件配置表；目前只编写[JS目标契约](../../../spec/simple-signals/backend/js-signal-rules.md)，
引擎与自动前视等实施细节仍待审查。JS和循环策略均未实现，Stage 2其余工具与实机验证不因此标为完成。

## 批次一：仅由有效列车请求开放保护信号

本批只修改 SimpleSignals 的进路表、选择器、设备准备判断、current-model定义文件及相关测试。
不修改 Basic 资源仲裁、ATO 寻路、物理线程或模型接口。

- 删除 `defaultRouteIds`、默认进路专用索引/资源冲突检查和 `DEFAULT` 选择来源。
- 没有有效请求时，当前入口返回 NONE；当前信号为配置的零速度输出，显示器为无进路外观。
- 固定进路信号不得在没有匹配当前请求时因道岔摆对而放行。
- 有匹配请求时，保留现有区域完整授权和实际道岔状态检查；继续申请远方资源不撤销已完整授权的本区域。
- 不用逐 tick 全图/全列车扫描替代已有事件索引，也不新建资源或卸载机制。
- 删除持久化字段直接修正尚未发布的 SimpleSignals 定义 sidecar，保持schema 1；原先要求升至2的决定已撤销。
  不添加 runtime alias/upcaster或误升版兼容分支，不覆盖现有开发文件；若用户需要保留旧定义，另行提供一次性转换。
- 复用已有编辑许可、候选编译、原子保存和 source 替换，保持设备身份及非默认配置不变。

必需回归：无请求但道岔正确仍停车；匹配准备中停车、完整授权后开放；申请其他进路不放行固定信号；
请求结束/真实车尾离开后无进路；申请远方后缀保留当前有效状态；重复经过/折返/替换接续不回退；
current-format fixture保存恢复及旧字段拒绝；真实 controller handoff；JAR隔离与Java consumer。

## 随后批次：出口净空与其他已确认限制

出口检查不能仅提高资源申请下限：资源授权不等于可越过其中的红灯。
需要同时考虑出口后至少一列车长度的空间、运营终点和前方强制停车位置，并避免入口自己的红灯造成准备死锁。
优先复用已有冻结路线、inspection、同周期列车几何与授权；不建立第二套扫描或净空资源管理器。
这部分由有界源码研究确定最小接口，再写精确合同。

双向闭塞应保留一个资源身份，但允许两入口有独立规则及下游依赖；这是另一个完整批次。
距离已经存在于规则输入，不能重复创建距离模型。具体距离规则和消除环线输出依赖需要区分新策略与实现缺陷，
不得为了笼统的“修复其他问题”写死国家灯色、速度或新增固定点求解器。

每批实现、独立检查、同步owner规范后单独提交并停下供用户审查。Stage 2 仍在进行中。
