# B3 stage 2 — concrete admission/aggregate contract

Status: implementation contract against the current `RouteResourceAdmissionEngine`; stage 1 is already tested. The output of stage 1 is `OUTPUTS_HELD`, never an active movement grant. No Core claim owner is transferred.

## Contact authority

`requestCouplingApproach(handle, intent)` is an authenticated sibling of ordinary `request`, not an occupancy-exclusion flag on `RouteResourceIntent`. It requires a sealed exact Couple intent, a current host proof, unchanged target car geometry/head/tail/direction, and a stopped source before first grant. The route prefix through desired authority must exactly cover current approaching tail-to-head body followed by the proof's ordered head traversal; authority equals the solved contact head. Extra/future traversal beyond that boundary is not admitted. Original source grants stay frozen.

Core's solved contact head lies before the partner body. Ordinary occupancy queries do not treat collision-only connector support as occupied block intervals. Therefore **keep ordinary occupancy checks unchanged**: an overlapping partner body, a third party, an occupied turnout/diamond anchor or any unexplained overlap rejects. There is no partner-ID exception. This can safely reject contact geometries whose conservative body/anchor intervals overlap rather than bypassing safety.

The full physical floor and all registered contributions are compiled and validated as usual. Source/partner resources are inherited coverage only if their exact retained claims cover them; genuinely missing rail/stable resources are acquired under the approaching owner. Partial overlap of a mandatory rail interval is split into uncovered representable intervals, retaining its covered portion under its original owner. Adjacent closed intervals use `nextUp/nextDown` when subtracting an inherited boundary, with tests proving every representable requested point remains covered. New preparation goes through `withClaim` and the existing actuator/tickets. Reusing a retained preparation requires the same contributed descriptor or same physical turnout port pair; an inherited claim never authorizes changing device configuration.

Provider policy must see an immutable host-created formation context on contribution collection. Generic resource existence/preparation validation is not explicit permission for a contact movement. The platform must affirm that all installed contributors support this fixed-event context; unsupported policy explicitly rejects. Basic must not manufacture an approval from the target holding a block. A world with no contributors still follows the complete Basic physical floor.

An accepted approach grant carries the finite positive speed ceiling. The actual SimpleATO restriction/trajectory path must enforce it; DTO presence or a late collision veto is not evidence of enforcement. The collision adapter checks exact ends, original target geometry, accepted path/boundary and actual pre-contact speeds again before requesting Core's output fence and selected survivor/direction. Authority and claim state remain retained through asynchronous provider preparation and every abort/uncertain result.

## Aggregate original holds and output binding

Original source route states remain the owner of their real registry claims, are visible in requester/provider activity, and never consume the retired source train's tail. The prepared event owns a finite list of `(original owner, exact held resource, per-output clearance proof)` entries. Physical resource identity is not renamed or copied. No original registry claim is dropped when the operational ledger commits.

After a coherent `OUTPUTS_HELD` snapshot the Dispatcher commits its exact staged unit/rolling-stock mapping. It then calls `bindFormationOutputs(handle, outputBodyIntents)` with one exact body binding for **every** output, including safe-held outputs. Each binding selects a frozen route, new movement owner and an authority identifying the observed head; it does not release the Core fence. Basic validates all bindings, bodies, contributions and inherited preparation before publishing any. Any unsupported/missing provider clearance remains held, not guessed clear.

For each original rail interval and each output, compile clearance against the output's complete selected frozen route, not only its current body prefix. Otherwise a long original interval could release while a short split child still occupies its forward part. Already-disjoint bodies with a route proven not to reenter the interval can be marked clear; unknown projection retains it. Original custom stable resources require explicit provider clearance/not-needed evidence for each output, or stay held. Missing train, decreasing epoch, invalid topology, unexpected car membership or route mismatch retains all affected entries and fails closed.

Only when **all** required output clearances prove one original resource clear may Basic call `shrinkClaimWithEvidence` for that exact original owner/resource. The local aggregate entry changes only after the exact successful registry mutation. New output resources remain ordinary exclusive output-owner claims and use existing tail release. This prevents two outputs from silently sharing a newly acquired block or opposing turnout selection.

Output route states begin with inherited body coverage and an empty *own* release queue. This requires a small explicit empty-own-claim lifecycle in `LiveClaimTailRelease`; ordinary nonempty queue validation remains intact. Normal extensions compile the physical floor, subtract aggregate inherited coverage, and acquire only truly missing resources. An extension entirely covered by inheritance can update authority after real validation without inventing a registry mutation. Pending readiness checks still validate occupancy and the latest coherent frame. Aggregate clearance proofs are extended before a newly admitted route can revisit an inherited resource.

`resumeFormationOutput(handle, outputGrantId)` requires the committed operating mapping acknowledgement, exact unchanged output composition, complete READY body/route binding and current coherent observation. It releases only that output's exact Core formation fence; configuration quarantine remains independent. A safe-held output has no resume call. To keep the first implementation narrow, at most one output may consume inherited shared movement resources at a time; subsequent outputs may resume after the previous moving output's inherited clearance is proved, while resources needed by stationary children remain held. A partial ledger/Basics publication failure keeps all outputs fenced and enters recovery.

## Tests required for this stage

- Exact proof route/contact boundary accepted, altered prefix/end/target pose and ordinary partner/third-party body overlap rejected with no partial claim.
- Pending, denied and failed provider work; explicit unsupported contributor; retained descriptor/turnout mismatch; both source owners preserved throughout.
- Real slow ATO contact under the published speed cap, exact survivor and one movement owner, ledger commit only after held output observation.
- Real split with both output bindings; the forward output leaving cannot release resources needed by the stationary suffix. Missing output does not release anything.
- Partial inherited interval subtraction, already-covered extension with no new claim, later exclusive acquisition, full tail clearance and exact old-owner release.
- Resume before ledger/body readiness rejects; exact one-output fence release preserves config hold; recovery snapshots before/after physical publication retain current cars and unresolved ownership.
