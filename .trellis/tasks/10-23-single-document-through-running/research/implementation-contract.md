## Exact shared wire contract

- Each SavedTimetableService adds runSegments: [] by default.
- runSegment = {runId, lineId, startStepIndex, endStepIndexExclusive, diagramLineId?:string|null, lineDirection?:UP|DOWN|null, calls:[]}. Bounds are actual top-level step indices, nonempty/nonoverlap. TimetableRunSegment domain uses LineId and LineDirection. Strict direct RUN scopes; no nested scopes.
- compiled call = {id, stationId, destinationId, status:ORIGIN|STOP|PASS|TERMINAL, arrivalTick?:number|null, departureTick?:number|null}. These are read-only planned facts, not control instructions. Call destinationId comes from authoring call.targetId. Actual movements/options remain execution authority. Origin/terminal boundaries stop in this first release. No through boundary.
- DSL service builder runSegment(options, callback), options {runId,lineId,diagramLineId?,lineDirection?,calls}. It captures exact compiled indices including scoped origin actions, does not parse origin strings. Segment definitions immutable; all addressed children inherit top-level membership.
- Timetable adds operationalTrips: [] by default. trip = {id, defaults: JSON object, segments:[{serviceId,runId,unitSlots:[positive 1-based integers]}]}. A slot denotes one complete registered EMU unit counted from actual operating HEAD at that run segment. No phantom units for unregistered formations. These are selection positions per leg, not permanent unit identity. Resolve to actual stable unitId at runtime; preserve context by unitId across split/couple/reversal. Different legs can select different positions for the same unit. Duplicate assignments to same (serviceId,runId,unitSlot) across trips reject. Trip definitions stay immutable. Physical unit membership/duty output must be validated; a trip cannot silently jump from one physical unit to another across an authored continuous path.
- Display program/native actions SET_DISPLAY and RESET_DISPLAY. Shared action fields unitSlots: positive distinct integer[], displayValues: JSON object (SET only), removeDisplayKeys: string[] (SET only, default[]). Domain SetDisplay(unitSlots,values,removeKeys), ResetDisplay(unitSlots). SET atomically removes requested keys then overlays supplied values. RESET restores current trip.defaults for selected actual units. They operate only on units with active trip context; no physical side effects; allow normal timed program/conditional use. Expose host DSL setDisplay(unitSlots,values,removeKeys?) and resetDisplay(unitSlots), including timed builder counterparts. Program AST steps use SET_DISPLAY {unitSlots: StationProgramValue<number[]>,values:StationProgramValue<JSON object>,removeKeys?:StationProgramValue<string[]>}; RESET_DISPLAY {unitSlots:...}. Parameter type UNIT_SLOTS with default/arguments validation; existing JSON and ID_LIST parameters can carry values/removeKeys. This is a native bounded operation, not unrestricted JS.
- Runtime per-unit display context identity = timetable + execution cycle + operationalTrip.id + actual stable unitId. Crossing runs/formation events keeps values; next trip for only that unit replaces them with new defaults. Later cycle resets defaults even same tripId. No mutable global trainId bag or mutation of library definitions. On definitive stop/end retire current ownership while retaining diagnostics according to existing lifecycle; never leak state into detached simulation.
- Snapshot projections expose currentRunId/currentLineId and unitDisplays (actual unitId, operationalTripId, cycleIndex, values, planned ordered stops, actual completed/remaining progress where proven). Read-only immutable. Core train/car geometry remains sole physical owner; no second scheduling service per unit.

## Pre-run display initialization

BEGIN_OPERATIONAL_TRIP is an execution boundary independent of physical RUN scope. Domain BeginOperationalTrip(tripId,runId,unitSlots); wire operationalTripId/runId/unitSlots. It targets a declared upcoming leg in the same service and rejects membership/orientation changes before that RUN. It resets only the selected physical unit on a new trip/cycle; same-trip entry preserves prior display mutations. It does not switch line/cap/currentRun.

ScriptWorker injects this boundary before the first SET_DISPLAY/RESET_DISPLAY (including conditional display steps) in the pre-RUN gap after the last acquisition/couple/split/reverse. The step tick and compilation origins remain exact; subsequent ranges/trace indices shift together. No display step means normal RUN entry initializes defaults. Display mutations before a structural step address the prior context; they cannot refer to a not-yet-acquired unit. Explicit JS beginOperationalTrip is also available outside run scopes/conditions.

Public per-unit snapshots include active (false after retirement) and unresolvedRuns rather than pretending unknown future membership yields a complete stop list. Historical diagnostics remain readable; setters require an active context.
