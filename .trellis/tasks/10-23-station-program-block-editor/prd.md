# 站内程序与到站动作积木编辑

## 目标

解决共享站内程序库难以编辑的问题，以 Scratch 式积木表达顺序、分支和参数，并使其与到站动作的编辑方式一致。承接已完成的线路限速和文档重开修复，基线为 `cee24662`。

## 已确认事实

- 用户已授权继续第2项，并允许复杂时创建 Trellis 任务；任务已创建；用户在 Blockly 选型后明确授权执行。
- `WebUI/frontend/src/StationProgramLibrary.tsx:45` 使用 `ProgramDefinitionEditor`；`ProgramFields.tsx:22` 是递归表单和步骤列表，非积木画布。
- `WebUI/frontend/src/RunRouteEditor.tsx:76` 的到站动作仅为占位内容；`i18n.tsx:337` 明确显示“到站动作编辑暂未开放”。不存在可直接复用的到站动作积木实现。
- `authoring.ts:5` 的 `AuthoringRunCallV1` 尚无到站程序字段；当前 run 生成仅输出停靠目的地和时间，接入到站程序会涉及编辑文档、生成及执行契约。
- 共享站内程序已有参数、顺序步骤、扩展动作、分支和重联/解编等语义，编辑器替换不得静默删减这些能力。库 revision、归档和时刻表绑定快照语义继续保留。

## 需求

- R1：共享程序使用实际积木编辑，支持创建、连接/插入、重排、删除、嵌套分支和参数编辑；不是仅给现有表单增加积木外观。
- R2：保留已保存程序定义、稳定步骤 ID、来源定位和现有校验语义，保存与重新打开后不丢失内容。
- R3：遵循现有 Ant Design 页面、中英文和明暗主题，提供非拖拽的可操作入口。
- R4：用户已确认本次同时开放到站动作，必须与库共享积木编辑核心，并接入保存、生成及真实执行边界。

## 验收

- 能在程序库通过积木完成包含顺序、参数和分支的真实程序，并保存、重新打开、绑定到时刻表后编译。
- 已有全部程序步骤可无损打开；非法结构不能保存或编译为伪成功。
- 库版本冲突、归档和显式采用更新保持原行为。
- 线路限速和已保存文档重开回归不受影响。
- 针对积木转换和编辑事务的自动测试、前端测试/构建及真实浏览器编辑验证通过。

## 当前非目标

- 本次不部署、不推送；不修改已完成的前两项提交。
- 不新增任意 JavaScript 反向解析、动态代码执行或旧开发格式永久兼容链。

## 选型研究

已完成 [编辑器方案比较](research/editor-selection.md)。推荐 Blockly + Zelos + 铁路领域自定义积木。尚未安装依赖或修改产品代码；后续设计须明确到站动作的触发/完成边界、未完成画布草稿保护和历史事务。

## 到站执行范围

内联到站程序在实际停车且完成开门后执行（无门则停车后），完成前阻止发车，同时遵守最小停站和发车时刻。支持显示、等待、条件分支和扩展；改变路线、方向或编组的操作保留在交路程序中，到站编辑明确禁用。到站定义无参数；共享库保留全部现有参数与动作。编译、保存、恢复须覆盖新字段，未配置时保持原停站行为。
