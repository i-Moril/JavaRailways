# 时刻表站点程序、交路积木与确定性寻路

## 目标与用户价值

玩家以同一套积木表达共享站点作业和交路流程；时刻表负责编辑时可确定的计划，运行时车辆适配由外部插件负责。运行线按明确 waypoint 序列得到唯一的合法路径，图上可编排独立定时事件。

本需求已收敛为明确的到达后/发车准备两个入口，替代中间讨论的单入口及逐停站内联方案。保留原任务目录名以维持记录连续性，用户于 2026-10-25 在确认双入口及职责总结后明确授权执行重构。

## 确认需求

### R1 共享站点程序、两个入口与完整编辑（2026-10-25 最终讨论方向）

同一时刻表在同站实际停车的所有列车使用同一站点程序，暂不提供逐运行线停站覆盖。通过站不触发站点程序，通过时显示、广播等行为属于其他插件。每次执行的任务状态独立。

用户确认两个入口替代先前的单入口方案：

- 到达后：运行线完成到站停车后启动。默认阻塞执行开门。
- 发车准备：按计划出发时间提前调度。提前量属于入口设置，不提供倒流时间的“X 秒前执行”积木。默认阻塞执行关门；默认准备提前量可取预计关门耗时，自定义程序的实际耗时不能自动可靠反推。
- 中途停车站执行两者；始发站只执行发车准备；终到站只执行到达后；通过站均不执行。默认程序无需 if/else 判断始发/终到。
- 发车准备必须等待到达后主分支结束，但不等待到达后产生的非阻塞任务。准备时刻未到则等待，已过则在前置条件满足后立即执行。始发没有到达后分支，不等待虚构的到达事件。
- 玩家可以完全编辑两个入口的程序。寻路、行驶与到站停车属于运行线，站点程序不承担到达过程或直接移动。

### R2 执行顺序和子任务

动作默认等待完成，只暂停当前程序分支；非阻塞容器执行到时立即启动内部程序，父分支继续，子分支内部仍默认顺序执行。提供等待具体任务完成。实际发车（终到则为完成本站并交回交路）前等待两个入口及其全部子任务/后代任务完成；两个入口之间的衔接只等待到达后主分支，不等待其非阻塞任务。不支持跨站遗留任务或正常离站时自动取消。无需玩家操作 Mutex。失败、取消不能当作成功放行；异常及服务停止时仍须安全清理。

### R3 站点动作边界与结束

允许换向，不允许站点程序直接开动列车。必须有【结束】动作：普通停站结束后交还运行线继续行驶，终到站结束后完成当前运行线，不擅自开始下一条。结束需要满足子任务完成和对应安全条件。结束的各分支可达性、重复执行及并行中使用的约束待设计。

### R3a 终到站可选时间与无发车准备

保留终到站可指定出发时间、作为当前运行线后续交路动作的开始时间约束的要求。未指定则在本站作业全部完成后立即衔接后续动作。终到站不执行发车准备，因此可选出发时间不再隐含关门；这替代此前“有出发时间就默认关门”的候选规则。终到站默认仅执行到达后开门，允许保持开门交接；后续作业若要求关门，须由后续程序处理，不能绕过实际移动的安全约束。

### R4 编辑期可确定的条件

时刻表上的条件不得依赖编辑时无法为某条运行线确定的量，包括实际编组节数、具体车型。动态选站台、按实际编组决定停车位置等运行时适配交由其他插件；不能以模拟参考车辆的参数把这些条件伪装成运行线可确定属性。现有条件 provider 与相关积木须逐项审计，替换此前允许动态选站的范围设想。

### R5 显式经停 waypoint

允许在下一站 waypoint 之前插入有序的经停 waypoint，用于消除路径歧义。经停不等于新增停车作业；具体编辑、方向及寻路拼接契约待设计。共享站点程序不通过移动动作承担这项职责。

### R6 路径唯一性与查询策略

时刻表 waypoint 之间必须检查合法路径唯一性，包括保护区域内部多条物理路径；选择最短路径不是唯一性证据。站点间查询不隐式穿越未指定的 waypoint：遇到非本段目标 waypoint 就剪枝。剪枝应作为寻路功能的显式查询参数，不能全局改变其他调用者。添加经停点后按明确的相邻端点查询；同位置端点、路径身份、环路及保护区压缩图的处理须研究。

### R7 运行图独立单点事件

提供不属于上行或下行的单点，包含一个车站、一个时刻，并可带标记。用于交路按时间指定事件，例如出库、折返。需明确图上点、事件身份与交路动作的引用关系，避免多份时间独立漂移。

### R8 交路积木、定时执行与参考车辆

交路改为积木编排，例如自定义出库程序 → 运行线1 → 自定义折返程序 → 设置显示 → 运行线2。交路需指定参考车辆，供模拟运行参数使用；参考车辆不是运行时实际车型条件来源。提供表达动作何时触发的时间功能，和 R7 的定时事件共同设计。包含后续运行线、折返及其他作业的串行依赖；晚点时刻语义待确认。

### R9 时间积木（2026-10-25 用户确认）

同时支持“等待到指定时刻”和“等待一段时长”。指定时刻可直接填写，也可引用运行图的单点事件；引用使用事件身份关联，不复制独立时间值。相对等待从该动作实际开始执行起计时。绝对时刻所属周期、跨日以及已过时刻的推进语义需在设计中与现有时刻表时基一致，不以机器墙钟替代时刻表时间。

## 验收方向

- R1/R4：同表同站停车共享定义；中途两入口、始发仅准备、终到仅到达、通过均不执行，默认无需站别条件。到达主分支未结束不能开始准备，非阻塞子任务可与准备重叠；实际发车/终到交接必须汇合全部任务。通过时副作用交由其他插件。条件只使用运行线编辑期可确定的信息。
- R2/R3：顺序/并行/显式等待均符合语义；结束等待全部后代任务；换向可执行；站点不能发起移动；普通站与终到站的结束行为不同且安全。
- R5/R6：两条不同长度合法路径也报告歧义，覆盖保护区内部多路径；插入正确经停点后各段可唯一确定；启用剪枝后不穿越未指定 waypoint，其他查询策略不被改变。
- R7/R8/R9：无方向事件点的时间/标记可编辑与保存，交路引用并按明确时间规则执行；两种等待和事件引用可保存重载，修改事件时间同步影响引用者；模拟使用交路参考车辆，不隐式绑定实际列车。
- 所有持久化内容保存重载、生成/编译/实际执行契约一致；HTTP 实际浏览器验证编辑入口。
- 覆盖有门/无门、始发/中途/终到/通过、准点/晚点、空程序、失败/取消及任务等待。最终矩阵待全部产品决策收敛后补齐。
