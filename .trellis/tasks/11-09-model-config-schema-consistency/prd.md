# 统一模型包配置的同类结构表达

## 目标与范围

父任务：`11-08-simpledisplays-train-integration`。用户要求将已有配置格式的一致性调整作为独立Trellis子任务，排在SimpleDisplays其他工作完成之后、最终验收之前。本任务只登记和规划，尚未开始实现。

重点处理两项作者侧写法：

1. 内联部件继承所属配置文档的版本，不在每个内联定义重复要求config-version；独立部件文件继续声明自己的版本。
2. 部件上的命名动画定义按名称组织为map，避免与actions.yml命名定义使用两套身份声明方式。动作中的animations/sounds执行步骤、parts/body-parts/wheel-parts安装树和composition仍然是有序、可重复的list。

公共内容结构由schema $defs复用，内联/独立入口只保留各自包装。独立文件的name和命名集合的key是同一身份在不同容器中的表达，不要求所有文件外形完全相同。不得以一致性为由新增全局资源框架或改变现有命名空间/单位。

设计依据：[父任务共同规范草案](../11-08-simpledisplays-train-integration/research/config-schema-conventions.md)。其中displays.yml属于新增显示模板配置，可以继续在父任务按共同原则设计/实现；本子任务延期的是已有格式调整，不阻塞SimpleDisplays其余功能。

## 排序和启动条件

- 状态保持planning，不切换当前活动任务。
- 在父任务其余SimpleDisplays功能工作完成之后启动，包括已确认的模板加载、样式选择、渲染接线、数据和可视范围等工作。
- 父任务最终综合验收必须等待本子任务完成；最终验收使用调整后的格式、样例和产物。
- 单项开发过程中的测试/审查可以照常进行，不必等到本任务；“验收前”指父任务最终综合验收门槛。
- 开始实施时重新核对实际配置、消费者及发布/冻结基线，再完成详细design/implement和所需上下文。此登记不授权顺带修改其他配置格式。

## 约束

- 修改前阅读版本号与持久化schema规则。不能仅因内部重排就猜测升版；没有发布/冻结证据时先确认，不添加任意旧开发数据runtime兼容路径。
- 同步官方JSON Schema、解析器、内联/独立入口、样例、模型包分发内容、快照和所有实际消费者。
- 动画定义的重复名称、原列表顺序和引用语义必须先盘点；不能在list转map时覆盖同名项或无声改变行为。
- 如实际已有开发数据需要保留，按仓库政策独立设计可审计、可dry-run、有恢复点的一次性迁移，不自行部署或转换存档。
- 保留独立定义身份、已有安装树、动作步骤、部件import和快照来源合同。不调整Minecraft资源key格式或SimpleDisplays XML/JS语法。

## 验收标准

- [ ] 独立文件与内联部件的版本包装明确，内联内容复用同一份定义schema和解析规则。
- [ ] 命名动画map与动作执行list在schema、解析、引用及文档中一致；名称不会丢失/重复覆盖。
- [ ] import、重复安装、有序composition和动作执行顺序保持语义不变。
- [ ] 相关schema/解析器/样例/分发模型包/快照消费者全部同步，并通过有代表性的正反fixture及模型/动画回归。
- [ ] 记录每个持久化边界的版本决策与实际发布基线，不增加未经授权的兼容路径。
- [ ] 单独审查和提交；父任务随后使用最终格式进行综合验收。

## 非目标

本任务不实现显示模板加载、渲染后端、PAPI、列车运营数据或视距命令；这些仍由父任务完成。也不做全仓配置改名或无关schema漂移修复。
