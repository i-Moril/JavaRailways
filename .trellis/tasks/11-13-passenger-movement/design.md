# platform 乘客移动验证：技术设计

## 目标与改动边界

将当前用于碰撞实体预激活的 platform 几何接入真正的乘客会话。每位乘客持有一个承载实体与一份局部位置；相邻平台交接只更换坐标系。WASD 相对于玩家视角，固定步速，禁用主动 Shift 下车与跳跃，越界恢复普通运动。

范围限于 BukkitPlugin 的平台几何、乘客会话、列车快照发布和生命周期接入；复用已有座位 packet/authority 后端。Core 物理、模型 YAML、存档、WebUI、运营逻辑均不需要改动。不添加防坠落、车门规则、完整行走碰撞、跨空隙桥接或跨列车交接。

## 现有证据与复用

- `PlatformModel` 已有网格和部件变换，但 `containsPlayer` 使用宽于实际平台的预激活范围。
- `SeatModel` 已配置不可见、无碰撞的真实 ArmorStand；`PacketEntityMotion.registerSeatCarrier`、`renderSeatCarrier`、`syncSeatAuthority` 已维护服务端乘坐与客户端虚拟挂载。
- `SeatAuthorityMover` 已移动服务端承载实体并同步乘客位置；无需另建每 tick 传送玩家的实现。
- `CarExtension.applyPublishedFrame` 接收有 stream/revision 的不可变车厢帧；`WorldManager.scheduleTrainFrame` 将整列车厢分为 region 批次并提供整次完成边界。
- 静止列车可没有新的 Core render 通知，因此乘客行走必须有独立于列车移动通知的输入积分时钟。

## 数据与 owner

新增内部 `PassengerMovementManager`，集中维护按玩家 UUID 索引的会话和按 world/train runtime 身份索引的平台场景。避免各 `PlatformModel` 分别抢占或反复挂载同一玩家。

平台记录使用车厢身份、模型实例内的部件身份和模型生命周期来源标识。跨线程只发布复制后的几何、位置、旋转、来源及修订，不传 `ModelState` 或其可变 JOML 引用。平台被销毁或模型重建后，旧回调不能继续驱动会话。

每个乘客会话保存：当前平台身份、局部脚底位置、最新输入、独立承载实体及运行状态。已挂载后的积分与真实实体更新归承载实体 owner；事件和清理通过 `PlatformDispatcher` 交给该 owner。挂载前检查玩家与承载实体的 owner，复用已有座位的实际所有权边界，不在 global/physics worker 上访问 Bukkit entity。

初次接管复用 `CarExtension.refreshFor` 的附近玩家路径，并在玩家/平台姿态变更后检测真正的脚底接触区域。已在现有座位/驾驶席或其他坐骑上的玩家不被自动抢占；乘客会话不注册为驾驶席。

## 同一列车的平台快照

`CarExtension` 在拥有模型状态的线程上复制已应用部件的姿态与几何。`WorldManager` 沿既有整列帧分区完成边界汇合本次结果，原子替换同一 runtime stream/revision 的完整平台集合，包含当前已构建且参与乘客判定的平台。

待处理新帧、失败或未完成的分区不能逐车覆盖交接场景；保持上一完整场景。模型集合增删/重建时更新成员身份，不能将旧模型快照与新成员混装。初次构建时使用已捕获的车厢帧完成姿态发布，不为此唤醒 Core stationary physics publication，也不轮询所有玩家或列车。

静止时，乘客每 tick 使用最后完整场景积分输入。不同车厢先后完成 region 更新不影响交接使用的一致来源。客户端仍可能受插值和 region 调度延迟影响；这里保证判定数据的一致性，不承诺跨实体像素级同步。

## 平台与输入几何

平台水平外缘沿用当前网格定义：以行列中心偏移加半个碰撞单元宽度得到局部 X/Z 范围，使用部件既有平移和旋转语义，不新增 scale 解释或配置字段。乘客实际脚底支撑高度根据现有实体碰撞面与挂载高度核对，不能以预激活的上下范围代替地板。

WASD 先组合为二维输入并归一化，避免斜向加速；用玩家当前 yaw 得到世界水平移动方向，不使用 pitch 产生飞行分量。将该方向投影到当前平台支撑面、归一化，再按固定步速和 tick 步长积分。初版速度取单一代码常量 `4.3 m/s`，不是新增可配置或持久化字段；疾跑、潜行输入不改变该速度，跳跃不产生竖直速度。

没有输入时保留局部位置，只应用当前平台变换。转头后下一次积分使用新的 yaw，不依赖按键变化事件重新触发。列车静止时依然能行走。

## 跨平台交接算法

1. 从当前平台 A 的完整场景姿态和乘客局部脚底位置，得到该 tick 的世界起点；按当前输入得到目标步长。
2. 沿本次位移找当前平台的首个离开边界。目标仍在 A 内时保持 A；重叠区也保持当前 owner，避免每 tick 在 A/B 间摆动。
3. 到达边界时，在同一场景中查找同列车的连续相接/重叠平台 B，检查本次运动确实进入其可行走区域及支撑高度。采用稳定顺序消除多个有效目标时的歧义，不选世界范围最近的平台。
4. 用该交接世界点转换到 B 的局部坐标，延续尚未消费的行走距离。转弯/坡道时按 B 的支撑面计算后续方向与脚底高度，保持玩家视角语义；不复位到 B 中心或丢弃剩余步长。不同支撑面的真实高度变化不伪装成绝对连续。
5. 会话只更新 `currentPlatform` 与局部位置。真实承载实体、客户端虚拟挂载 ID、乘坐关系、输入状态保持不变，不发送一次下车再上车来完成交接。
6. 若位移离开整片连续可达区域，就提交区域外的位置并结束会话，恢复普通运动；不夹回平台边缘、不吸附到附近列车、不添加全局重上车冷却。

用于数值边界比较的误差范围仅解决浮点判等，不能扩大成可跨越真实空隙的吸附范围。判断要覆盖本次运动路径，不能只因步长末端落在另一平台上就越过中间空隙。当前不创建动态连接面。

## 挂载、Shift 与退出

初次接管创建并配置真实承载实体，注册既有虚拟座位后建立乘坐关系；共用的实体配置若需抽取，只从现有 `SeatModel` 做最小复用，不复制完整座位管理。

Shift 限制只取消本功能会话的主动 dismount，并尊重事件可取消性。关闭会话前先进入退出状态，让边界离开、死亡、外部传送、世界变更和销毁能正常卸载。跳跃输入被忽略，不改玩家全局跳跃/速度属性。

越界结束不复用固定座位的延迟回位逻辑。释放位置使用本次运动产生的区域外世界脚底位置，保留玩家 yaw/pitch；乘坐解除完成后再销毁 carrier。外部传送优先结束会话，不被旧运动回调拉回。模型/列车移除、换编组导致 runtime 来源改变时释放会话，本轮不保证跨编组操作继续骑乘。

## 生命周期与失败处理

`BukkitPlugin` 负责创建/启动会话管理器，在世界/模型、packet runtime 销毁前结束相关会话。所有实体删除和跨 owner 清理提供可等待的真实完成通知，沿用现有 `DestructionSteps` / `PlatformCleanup`；Folia 整服停止遵守现有跳过 owner 动作的合同。

使用已有 seat authority 失败报告，不增加第二套吞错或兜底移动协议。挂载失败只清理本次已创建的资源；正常已坐座位不受影响。终止后的排队回调不得恢复输入、平台归属或实体。

## 验证与剩余技术风险

- 纯几何：视角基准、斜向速度、旋转/坡度、A/B 局部与世界换算、重叠保留 owner、连续交接与真实空隙释放、剩余步长守恒。
- 会话：静止车厢持续行走、两名乘客独立、Shift/跳跃、边界退出、外部传送优先、销毁与迟到回调、既有驾驶席不受抢占。
- 发布：乱序分区、失败分区、同 revision 的静止场景及模型重建，均不产生混合场景。
- 现有 seat/packet/authority 测试保持通过；若提取共享 carrier 配置，证明固定座位配置和行为不变。
- 实机：S100 直线与曲线跨车厢往返、坡道、多玩家视角、第一人称平滑与挂载高度、Paper/Folia owner 检查和异常清理。

真实挂载高度、客户端插值、弯道连接处的实际几何覆盖尚未经过游戏验收。若模型存在真实空隙，本轮记录并按区域外处理；不因测试失败擅自添加桥接或防坠落。

## 回退

会话数据全部为临时运行态，不写入存档或配置。实现提交按依赖顺序组织；停用并完成会话清理后可回退代码恢复原平台碰撞/固定座位行为，无格式迁移。
