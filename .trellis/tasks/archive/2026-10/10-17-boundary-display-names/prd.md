# 边界命名与进路辨识

## 目标与用户价值
玩家能够给现场边界设置允许重复的名称，并在配置进路表示器时，根据“入口 → 出口”及现场标记辨认进路，而非猜测自动 ID 的列表序号。

## 已确认范围与产品决策
- R1：覆盖保护区域正式边界、修复草稿边界、待完成切口和普通闭塞的两端。名称可重复，不作为绑定键。
- R2：同一物理边界被相邻区间共用时，共用名称；改名对两侧同步。只按同轨道弧长或真实普通端点连接判同，不合并空间靠近或交叉的轨道。
- R3：区间工具 Shift+右键设置 → “命名边界” → 点击已有边界 → 文本输入并保存。留空清除；完成/取消后退出这次命名，不进入连续改名。原有创建、删除、F 切模式和清理手势保留。
- R4：名称显示在边界现场标记、相关入口选择和进路映射/预览选择中。进路行显示“入口名称 → 出口名称”，回调仍按 routeId 精确操作；不根据名称、顺序或数字推断路线。
- R5：未命名时使用本地化“未命名边界”并附位置；重名时补充位置。同端点多路径仍是不同记录，保留行序号以区分，不宣称名称能唯一描述路径。
- R6：改名、清名在原定义事务中提交并持久化，取消/失效/失败不改盘、不发布半成品。重命名不改边界/进路 ID、路径、方向、主信号绑定或表示器映射。

## 输入与生命周期合同
- 普通文本，去除两端空白；全空白等同清除。最多 64 个 Unicode 码点，拒绝换行与控制字符；中文可用，不解析颜色/富文本/命令。
- 同一物理边界仍被任一存活区间/草稿/待完成切口引用时保留名称；最后引用被明确删除时清理，不留供未来新边界意外继承的孤儿名称。
- 同一位置边界由待完成切口转正式区间、修复草稿转正式区间，名称保留。移到不同物理位置视为另一个边界，不因近似位置猜测迁移。
- 命名会话在切换工具/模式、跨世界、离线、权限失效或定义/拓扑快照过期时失效。
- 后续轨道连接把两个不同名字的边界合并时，显示名称冲突，不自动覆盖；玩家显式改名/清名后全组统一。分开连接时各存活作者锚点保留此前共享名字。

## 验收标准
- AC1（R1/R2）：上述所有边界均可命名；共用边界从任一侧命名后，两侧及相关进路行显示相同名称；不连通但重合的轨道不互相改名。
- AC2（R3）：设置中可进入一次命名，命中边界后可输入、保存、取消或清除；误点内部不创建/删除边界。
- AC3（R4/R5）：名称重复合法；界面显示两端及位置辅助信息，选中同名行仍操作正确 routeId。
- AC4（R6）：名称保存恢复成功；固定旧 JSON 缺失新增字段按空名称读取，schema 不变；原 ID/路径/方向/设备绑定/映射逐项保持。
- AC5：待完成→普通闭塞/保护区域、草稿修复与共享边界删除一侧保留名称，最后一侧删除清理；无关边界不受影响。
- AC6：过期会话、重复提交、权限变更、跨世界、保存失败均不发生错误提交；原有工具操作回归通过。
- AC7：本地模型/文本与定义测试、SimpleSignals 全套及模块边界/JAR 检查通过；离线验证与真实客户端验收分别记录。

- 不凭名称解决同一入口/出口间多路径的完整几何辨识，后续可另做预览入口。
