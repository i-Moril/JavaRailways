# 修复运行线模拟一致性与澄清停站时间语义

## Goal

让用于排图的运行线模拟反映真实执行环境，避免其生成的运行时刻在无其他列车干扰时仍系统性偏短；恢复编辑器约定的最短停站语义，使排图、站点程序和实际执行一致，不另建不必要的时间规则。

## Confirmed evidence

- 102P 四段计划运行时间1525/1363/1552/1098 tick，与相同路线、S100车辆和整体最高速度的运行线预览逐项相同；全局回放实际为1603/1563/1900/1240 tick。
- 运行线入口 `BukkitPlugin/.../http/TimetableHttpBridge.kt:907` 将路线压缩成长度、平均坡度与终点停车标记；`SimpleATO/.../simulation/DetailedTrainTravelSimulator.kt:95` 构造终点约束，没有使用完整路线沿途限速、信号与资源准入环境。共用车辆控制算法不代表执行条件相同。
- 五交路原阈值1200回放在10026结束，延误1226；只保留交路2仍延误1217。其他列车交互不是主要原因。
- `WebUI/frontend/src/authoring.ts:269` 按到站时刻加 fixedDwellTicks 安排发车；`StationStopProgramRuntime.kt:214` 当前把最小停站截止时间延至开门完成加 minimumDwellTicks。本例中三个中间站实际停站到发车各430 tick，计划400 tick。
- 本例终到计划8738、折返8800只隔62 tick，生成脚本错误地给终到注入最少停站400。实际9597到站、10026开始折返；另一次放宽阈值的短诊断回放中10028完成折返，并非卡住。按用户明确合同，62 tick间隔本身不违反全局最短停站，不能继续称其为用户排图冲突；实际车门/任务耗时仍须正常完成。
- 上述是当前实现和输入事实，不证明当前停站计时方式就是正确需求；不得先入为主将不一致归咎于用户排图。

## Requirements

- R1：运行线模拟用于生成排图时刻时，应按相同基础设施、车辆及实际运行约束计算；不得以理想化区间求时冒充实际执行结果。
- R2：全局最短停站按正常到站至关门完成的全过程安排，包括开门和关门；晚到同样从实际到站起算一次，不另加开门时间。自定义程序允许提前关门，但最早发车仍受实际到站+D约束，不对任意CloseDoors增加完成下限保护。只适用于营运运行线的中间STOP；ORIGIN/TERMINAL不添加，PASS及DEADHEAD继续不适用。不能跨运行线或后续交路动作暗中恢复终到最短停站约束。
- R3：以同输入的运行线模拟和单交路全局回放作可重复对照；需要区分真实多车交互延误与模拟器自身差异。
- R4：不通过放宽ATP、忽略红灯、调高延误阈值或人为增加排图余量掩盖模拟差异；保留原任务位置语义修复。
- R5：区分语义错误的额外计时与真正执行约束。保留显式站点程序及子任务完成、真实关门完成、操作冲突/失败处理和行车授权；不因“简化”而让列车开门行车或取消用户明确写入的等待动作。
- R6：模拟重置使用的fixedDwellTicks与全局minimumDwellTicks是独立输入。前者安排中间站计划间隔，后者约束适用停站的最短间隔，不能合并或互换参数。
- R7：Reset保留首站指定时刻；fixedDwell低于minimum或不能容纳真实站点程序/门作业时明确报告不可实现，不自动延长用户输入、不返回可回填的部分成功。发车目标之后真实信号/资源等待计入至下一站时间，不因采用驶离站台/开始运动作计时起点而被扣掉。

## Acceptance criteria

- [x] 沿途局部限速等真实约束进入运行线模拟，并有回归验证对运行时间的影响。
- [x] 在固定车辆、路线与环境下，运行线返回的整数tick到发时刻可被单交路完整执行复现，按同一事件严格比较；覆盖PASS、重复站点、offset、初始方向与真实信号/资源等待，不额外引入tick容差。
- [x] 中间STOP正常程序以到站至关门完成的全过程安排最短停站，不从开门结束重新起算；自定义提前关门不增加额外保护，但仍禁止提前发车。ORIGIN/TERMINAL、相邻RUN及终到后的交路动作不受该全局最短停站限制。
- [x] 晚到用真实到站事件而非晚一tick的程序创建事件起算；关门准备与最终时间门使用一致依据，不出现默认程序刚开门就关门、关门后再补整段最短停站的行为。覆盖早到、准点、晚到、不同计时epoch、自定义准备提前量、长/失败门动作。
- [x] 生成脚本、编辑校验和运行时符合上述范围；有时刻的终到、用户显式等待、任务完成和真实车门安全检查仍按各自原有明确语义工作。
- [x] 输出能用于排图的时间；原阈值回放如仍失败，准确报告剩余原因，不能将退出码或放宽阈值视为成功。
- [x] 停站输入不可实现、缺失profile/feature、失败/超时/部分事件等情况不修改用户运行线；成功Reset一次更新，支持undo和过期请求保护。

逐项证据及验收边界见[验收审计](research/acceptance-audit.md)。用户批准的必要补测已通过：初始真实换向、真实Core资源等待与严格重放、缺profile拒绝、实际Reset旧响应保护；最终后端7项、挂载编辑器4项及前端类型检查通过。既有模型禁止重复station，验收是已有LineStoreTest明确拒绝及有序身份不混淆，不代表新增重复站线路支持；实际中间2m停车偏移接续失败现有专项断言，不能将底层Mission问题包装成成功。超时的不回填由真实UI处理受控504与服务端失败路径审查分层验证，不声称已跑完整HTTP超时端到端。技术验收已满足，提交/归档尚未执行；五交路另有路线故障继续单列，不声称全局所有问题已修复。

## Scope boundaries

最终提案是直接复用既有完整隔离模拟执行链，只放入目标运行线和所选车辆，再采集到发事件；设计与实施次序已记录在design.md和implement.md，等待用户最终审核，不是本轮实施授权。不新建另一套信号、资源或简化求时兜底。
本轮不改持久化版本、不迁移或重排用户时刻表、不部署、不推送。“首个延误来源”因果归因改进是关联问题，是否纳入须另行确认。
