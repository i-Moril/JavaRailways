# SimpleSignals

独立的信号插件，依赖 JavaRailways。Basic 管理物理资源和实际授权，SimpleATO 消费行车限制；
SimpleSignals 定义保护区域、固定进路、固定闭塞及其信号规则。信号显示允许不等于已经获得资源授权。

SimpleSignals 使用自己的 `plugin.yml` 和普通 `SimpleSignals-*.jar` 独立安装；JavaRailways 主插件不会把它
嵌入自己的 JAR。Core、Basic、SimpleATO 和 BukkitPlugin 只作为编译期宿主依赖，运行时由
`depend: [JavaRailways]` 提供。仓库的 `./gradlew verifySignalModuleBoundaries` 同时检查声明依赖和实际 JAR：
SimpleSignals 不携带宿主类，SimpleATOBukkit 不产生第二个 Bukkit 生命周期而由主插件嵌入，并阻止已声明的
main配置直接反向依赖。语义ownership和公开API使用仍由代码审查负责。

## 目前能做什么

后端已支持三种保护区域设备：

- **固定进路信号**：绑定一条固定进路；只有匹配的列车请求已取得完整授权、道岔正确且整列车净空就绪时，才检查这条路径的占用和下游信号，不跟着其他进路切换。
- **当前信号**：绑定有向入口，显示列车正在请求的进路；没有请求时限速为0，不根据道岔朝向选择进路。
- **进路显示器**：显示该入口当前选择的进路，不产生限速。放到远处、换用另一模型即可作为进路预告机，不需要另一套后端类型。

列车请求尚未完整授权或设备未准备好时，当前信号仍显示请求的进路身份，但保持0限速。
默认进路已取消。没有匹配请求时，两类保护信号都保持停车，显示器显示无进路；不会自动扳动道岔。
进入保护区域前还检查出口后的空间：车头至少能到达“区域出口＋当前完整车身长度”，授权需包含既有安全距离。
后继闭塞太短、运营终点太近，或前方红灯/停车点/前车使空间不足，都保持入口停车；取得闭塞资源不代表净空足够。
这只检查入场时的当前条件。入场后若发生紧急停车或故障，仍保持资源直到真实车尾清除，不提前释放。

主信号通过 `type`（Kotlin 属性 `signalType`）引用统一信号包中的类型。包使用 `pack.yml` 保存元数据，
`model/` 定义模型、`logic/` 保存配对的 YAML／JS、`signal/` 声明玩家可选的模型与逻辑组合；类型可以引用其他包的模型或逻辑。
灯色名称、模型 variant 和具体速度由 JS 决定，不存在另一套 Kotlin 阈值规则。每次求值必须在`setSpeedLimit(...)`与`clearSpeedLimit()`中恰好选择一个，并调用一次`setModelVariant(...)`。
`clearSpeedLimit()`明确不附加本信号限速；它不授予资源，不取消线路、车辆或其他限制。漏调用、脚本异常或不可用状态仍按0限制处理，不能默认解释为不限速。

逻辑YAML可填写固定的`scan-distance-metres`，或改填`reference-deceleration-metres-per-second-squared`，必须二选一且为有限正数，减速度没有默认值。计算模式在准备时读取整个受控区间各轨道的CURVE/SUBGRADE有效限速，再取其中最高值，按`D = v² / (2a)`计算扫描范围；不能只取较低的入口速度，也不使用后继区间、模型位置、列车实时速度或时刻表Line。固定闭塞两向使用同一区间最高值；保护区域按所选进路对应的区间取值。受控区间任一轨道缺少有限速度时准备失败，不猜测默认最高速度或距离。

插件按准备好的扫描范围预编译树形观察，运行时填入同 epoch 的区间长度、占用、分支选择及可用的下游信号限速。
JS输入顶层提供`scanDistanceMeters`；计算模式另提供`referenceSpeedMetersPerSecond`和`referenceDecelerationMetersPerSecondSquared`。这些标量随计划缓存，不在tick读取宿主或metadata；轨道编辑沿已有重准备流程，不新增速度事件或轮询。扫描范围不自动决定灯色，仍由JS判断。
JS 可检查未选支路，不只观察当前路径。物理环只终止命中的分支，并以 `cycle` 告知 JS，其他分支继续；
循环段不暴露递归下游输出，实际信号输出依赖仍必须无环。这不是禁止环线，也不执行迭代求解。
包布局和身份见[统一信号包契约](../.trellis/spec/simple-signals/backend/model-packages.md)，
观察与同步执行见[JS规则契约](../.trellis/spec/simple-signals/backend/js-signal-rules.md)。

## 一次更新怎样工作

1. 加载或编辑定义时编译轨道几何、固定进路、设备绑定、树形观察计划和无环输出依赖图；正常信号求值不重新寻路。
2. Basic 提供同一物理周期的列车占用、实际道岔方向和准入请求变化。
3. 列车控制器复用一次前方扫描和已有约束检查净空；结果变化交给串行信号周期。
   一个信号回调合并净空、准入和道岔变化，先更新入口选路，再更新占用，最后计算受影响的信号。
4. 在同一信号阶段按下游优先顺序同步执行 JS，每台逻辑设备至多求值一次；输出未变不重复提交显示，显示器仅在对应入口选择变化时更新。
5. 变化的限速标记对应 inspection 声明；列车控制器在下一次物理控制计算中，复用自己的前方感知，
   把最新限速放到信号入口位置，再计算牵引、制动。此步不等待 Dispatcher 或 Bukkit 主线程；显示器不参与。

Dispatcher 只负责绑定路线、编译声明及申请资源。各列车独自维护检查范围和激活状态，只有首次检查、
进入/离开范围或信号变化时才调用限制投影；共享信号规则仍在世界统一信号阶段执行，不按列车重复计算。

占用范围按进路分别计算，不能用“整个咽喉有车”代替。两条不相交路径独立；共享轨道的候选进路会各自观察到该处的列车。
没有首个观测结果、授权不足或观测失效时，限速设备保持0；这不阻止列车提前申请资源。

## 保存与编辑

定义保存在插件自己的 `worlds/<world UUID>-definitions.json`，当前 schema 为 `1`，其他版本（包括误升的 `2/3`）明确拒绝。
删除 `defaultRouteIds` 和两端独立规则均直接修正同一个未发布格式，不建立开发代际；当前字段和功能保留。
此次仅恢复本插件定义文件的版本号，其他模块的世界存档与模型包版本不变；不添加旧字段或误升版兼容分支。
旧开发文件不自动升级或覆盖；需要保留时另行一次性转换。
`protectionSignals`、`routeIndicators` 等列表仍缺省为空；新增默认字段本身不要求升版。
定义只保存作者输入；占用、入口选择、依赖索引和授权结果都不写入存档。

### 闭塞两端入口与轨道方向

固定闭塞按完整物理路径定义，没有独立的单向／双向开关。不要在 `fixedBlocks` 中添加 `bidirectional`：当前严格格式不接受该旧开发字段。
每个闭塞始终有两个几何方向；反向路径将轨道顺序倒过来并取反各段 AB/BA，坐标仍按 canonical AB 保存。
单向与双向轨道可以组成同一闭塞，不因配置混合而拒绝创建或禁用整个闭塞。

两个方向申请同一个闭塞资源，列车停在内部或换向时持续保留，真正车尾出清后才释放；回程不先释放再争抢。
两端可分别配置主信号：`entryDirection` 为 `FORWARD`（缺省）或 `REVERSE`，相对作者整条路径，每端最多一台。
两端独立选择类型、提前时间与模型摆放；移动模型或改变外观朝向不会改变逻辑入口。未配置某端信号时仍受资源与方向限制；有配置但缺有效状态时入口限速为 0。

轨道公共运行方向由 Basic 唯一保存。SimpleATO 按实际运营路径、整列车相关路径和停车安全余量验证方向，并沿现有控制约束限制可行驶范围。
例如正线 A 单向、折返段 B 双向，两者可属于同一闭塞；整列车在 B 内停车、换向并返回 B 内车站允许，实际逆向进入 A 或停车余量伸入 A 则拒绝。

完整闭塞保护后缀可以比本次合法行驶范围更长。取得整个闭塞资源不等于取得逆行权限，也不能因为保护后缀够长就忽略非法停车余量。
Basic 的实际物理授权边界如实保留，ATO 另有更严格的方向边界，两者共同收紧控制。

无关方向编辑不重算全世界；相关自动路线沿既有 rail 索引失效。拓扑失效、缺 baseline、规则异常等故障仍停止放宽，既有 claim 不因此清除。
手动驾驶不新增方向强制、自动制动或 ATS。单线多闭塞之间的方向协调仍为独立 TODO。

当前 sidecar schema 保持 1，不增加旧开发格式 reader。需要保留旧文件时，在部署前使用带 dry-run 和恢复点的一次性转换。
转换工具与停服要求见[一次性开发数据转换](../scripts/fixed-block-direction-migration/README.md)。
详细机制见[闭塞两端入口契约](../.trellis/spec/simple-signals/backend/bidirectional-fixed-block.md)和[ATO 方向限制](../.trellis/spec/javarailways/simpleato/operating-direction-enforcement.md)。

### 设备模型与摆放

固定闭塞和保护区域主信号保存必填 `type` 与可选 `placement`，模型由同一 catalog 类型解析；
不摆放模型时仍运行后端。进路显示器与附属信号等只显示设备使用显式 `model`，保存模型引用与摆放参数。
两种方式都不包含模型树，也不改变信号的逻辑入口。具体字段见[模型显示契约](../.trellis/spec/simple-signals/backend/model-presentation.md)。
设备存档由现有 export/validate/apply 工作流编辑。模型包准备完成后，加载已有定义或成功 apply
会创建模型，并随着信号结果更新显示；未配置模型的设备仍只运行后端。

例如，只显示设备使用 demo 灯头，在轨道 BA 方向的右侧 2 米摆放：

```json
"model": {
  "modelId": "jr_four_light:head",
  "placement": {
    "kind": "rail",
    "railId": "00000000-0000-0000-0000-000000000001",
    "arcLengthInAbMeters": 12.0,
    "facing": "BA",
    "adjustment": {
      "x": 0.0, "y": 0.0, "z": 2.0,
      "rotationX": 0.0, "rotationY": 0.0, "rotationZ": 0.0, "rotationW": 1.0
    },
    "followRailTilt": false
  }
}
```

这是设备内部字段片段，示例 UUID 必须换成该世界的真实轨道。弧长仍从 A 端起算；方向决定偏移的前后左右。
`adjustment` 可省略为零偏移/单位旋转，`followRailTilt` 可省略为 `false`。
地面摆放改为 `"placement": {"kind": "ground", "pose": {...}}`，`pose` 使用同样七个分量保存世界位置与旋转，
不接受轨道字段。世界取外层 `worldId`，旋转使用单位四元数，不是度制角度。

摆放存档保存已经选定的参数，不保存预设名称；修改包内预设不会追溯移动设备。
插件启动时在异步线程分别加载 `plugins/SimpleSignals/signal-packs/<包目录>/pack.yml` 统一信号包和
`plugins/SimpleSignals/models/<包目录>/manifest.yml` model-only 包，不在 tick 中读文件。
主信号依赖统一包中的类型；类型缺失或逻辑无效时保持不可用／0限速，不能当作单纯显示故障。
model-only 包供只显示设备选择，显示故障本身不撤销后端限制。
模型 ID、轨道引用/范围、模型包是否存在，以及设备可能输出的所有外观名都会被检查。
新增或改绑主信号类型、配置显式模型的草稿，需要对应 catalog 就绪后才能通过校验；不涉及这些绑定的编辑沿用现有事务规则。
显示器不保留旧开发草稿中的顶层轨道位置字段，也不保留别名或自动转换；当前存档版本见上文。
柱高等任意模型实例参数以后单独设计，不与灯色 `modelVariant` 混用；目前可用预先配置的不同模型 ID 区分。

在线编辑先完整验证候选，再用现有编辑许可检查轨道是否正在被运营路线或列车使用。
验证或保存失败保留原状态；成功时一起替换定义和运行时信号来源，不冻结其他世界。
许可范围从实际改变的定义出发，同时检查旧、新位置和可能受影响的上游信号；无依赖关系的其他运营线路不参与本次检查。
修改保护区域或进路表时仍保护整个相关区域，以及紧接出口的闭塞；不会把当前未开放的支路视为不受影响。

## 管理员编辑流程

### 闭塞与保护区域工具

权限为 `simplesignals.admin`（默认 OP）。使用以下命令领取独立工具；不指定最后一项时为创建工具：

```text
/simplesignals wand block create
/simplesignals wand block delete
/simplesignals wand region create
/simplesignals wand region delete
```

闭塞创建工具：右键轨道选择第一点，再右键下一点创建区间；左键已有分界点也能开始接续，
选取两个已有分界点会直接尝试连接。成功后第二点保留为下一段的起点，潜行点击取消选择。
无需填写名称或确认页面；方向由整条路径上的运营方向自动确定。
路径不能经过道岔，包括直向；不能覆盖已有闭塞或保护区域内部。不能唯一确定路径时说明原因，不任意选支路。

闭塞删除工具：左键分界点，删除两侧相接闭塞；右键区间内部，只删除该区间。
所属主信号、附属与中继设备及其模型随之删除。其他信号若依赖被删目标，保留配置但变为不可用，不自动删掉这项依赖后放行。

保护区域创建工具：朝向预期的区域内部观察轨道，右键放置有向边界。
视线几乎垂直于轨道时会要求调整观察方向，避免猜测哪侧是内部。
每次放置都尝试自动补全；未标记的轨道尽头不算边界，未闭合时只保存待补全点，不生成正式区域。
保护区域边界与闭塞分界点可以吸附到同一轨道位置；不会把旁边另一条轨道误当作同一点。

保护区域删除工具：点击边界删除。若同处还有闭塞分界点，须先用闭塞删除工具处理。
区域已经存在时，删除边界会保留其身份、原进路和设备，但禁止 ATO 进入；补齐后自动重新校验。
原位置附近补放可恢复原边界身份；修改后已经不适用的进路或设备绑定保留为不可用，供之后调整。
即使删除全部边界，配置也不会被当作孤立数据清掉。

保护区域搜索范围在 `plugins/SimpleSignals/config.yml` 中设置，启动时读取，单位为米：

```yaml
protection-region-max-distance-meters: 1000.0
```

范围是从新边界沿轨道到最远位置的距离，不是各支路总长度；环线按最短轨道距离计。
例如共用 200 米后分成两条各 300 米的支路，范围是 500 米。超限只保留待补全状态，不把搜索终点当成边界。
此配置不限制普通闭塞长度。

搜索、校验、保存均在异步线程。创建和删除仍受时刻表路线与列车占用保护，失败时原定义和存档不变。
主手持上述区间工具时，编辑者可看到附近64米内的边界点、方向箭头、区间覆盖及身份/状态文字。
文字的defined/draft/pending/unavailable描述作者定义，不表示列车已获放行；长区间中部也有身份提示。
离手、退出或切换世界后清理，其他玩家看不到这些编辑文字。分界点常驻地面模型及全轨道/车站统一显示不在此范围。

### 独立测距工具

使用`/simplesignals wand measure`领取测距工具，权限同上。主手持工具右键选择第一个轨道点，再右键第二点，
同时报告三维直线距离和沿轨物理最短距离（米）；左键或潜行点击清除选择。完成后下一次右键重新开始，不自动接续。
沿轨测量忽略运营方向、信号、列车占用及当前道岔选择，但不能经过物理上不存在的连接；测距不会扳岔或申请资源，
结果不是可驾驶的运营路线或授权。轨道不连通时仍显示直线距离，并明确沿轨不可达。
无需先创建信号/闭塞；选点期间拓扑变化会要求重新选择，离手、换世界或退出会清除选择。

### 当前通路预览

使用 `/simplesignals wand route` 领取预览工具，权限同上。左键保护区域边界选择入口，
Shift + 左键同一区域另一边界选择期望出口，右键确认保存或替换进路。
重新左键入口开始新的选择，退出工具清理预览。

预览沿道岔当前实际选择前进，不寻找其他可行路径，也不扳动道岔。
如果先到其他出口、轨道尽头、循环或未开放的道岔，显示已经走过的路径和实际停点，并说明原因。
预览本身只用于检查线路，不申请资源、不保存进路，也不表示列车已经可以放行；
成功预览后的显式右键确认才会保存或替换进路，详见下节。

路径成功时为绿色，失败前缀为橙色，白色箭头表示行进方向。
入口为青色、期望出口为黄色；实际终点成功时绿色、失败时红色。
相关道岔选择、轨道或区域定义变化后异步重新计算；编辑后尚无对应物理观测时先等待，不混用旧状态。

显示使用仅发给自己的粒子，每20 tick 刷新一次，每次最多512个粒子。
长路径循环分批显示，入口、出口和实际终点每批保留；完整逻辑路径不会被截短。
显示刷新只发送已经准备好的点，不重复查图或计算曲线。
取消、换工具、离线、换世界、世界卸载和插件停用都会关闭预览。

闭塞/保护区域工具的边界身份和状态文字叠加已接入，进路工具保持上述独立粒子预览；全轨道/车站的统一显示仍为后续范围。当前离线测试不代替真实 Folia 和客户端画面验证。

### 录制固定进路

左键选入口、Shift + 左键选出口，看到成功连通的当前通路后右键确认。
保存使用当前预览，不要求手填 ID 或执行录制命令；等待观测、通路不连通或选择已失效时不会保存。
成功后回复生成的进路 ID。重复录制同一入口、出口和完整路径会返回已有记录，不重复添加。
同一入口和出口经另一条支路连通时，确认会替换原进路的路径，保留进路 ID 和已有设备绑定。

新保护区域闭合时自动为各有向入口—出口组合记录沿轨道距离最短的合法进路，寻路只使用表内进路。
有多条通路的相关出入口显示琥珀色“！”及说明；警告不禁止采用已保存的最短路。
区域工具创建后会显示警告，左键已有区域的边界可查看其警告；进路工具也在相关出入口显示。
已有区域修复不覆盖玩家录制结果。既有无表区域第一次录制仍可建立表。
其他出入口组合的进路与已有设备绑定保持不变，保存路径不产生列车授权。
若通过 JSON 为同一组合配置了多条不同进路，工具不能任意挑选覆盖，会明确拒绝有歧义的替换。
路径在录制时固定下来，之后扳动道岔不会改写它。录制不申请资源，也不改变道岔当前选择。

保存复用原有异步定义事务，仍受时刻表路线和列车占用的防编辑保护。
校验、编辑许可或保存失败时原表与存档保持不变；取消只阻止未提交操作，不撤销已保存记录。
选中区域后Shift+右键打开已保存进路列表，选择并单独确认删除。删除保留相关设备及摆放，失效的固定进路绑定解除为未绑定，表示器仅移除该进路的映射；没有剩余进路时保留空表并禁止通行。Signal Wand设置页可显式重绑已有保护主信号，不移动模型。不再提供默认进路设置。

### 主信号与附属信号机

固定闭塞信号和保护区域信号负责计算限速及外观。额外放置的信号机、中继信号机可以直接绑定其中一个主信号，
复用其已经计算好的外观结果，分别使用自己的模型和位置。主信号没有模型也可以带多台附属设备。
附属设备不新增信号规则、检查声明、区间资源或停车点；改变它的显示朝向也不会自动增加反向入口控制。

在世界定义根对象的 `attachedSignals` 列表添加设备，例如：

```json
"attachedSignals": [
  {
    "signalId": "demo:repeater",
    "revision": 0,
    "primarySignalId": "demo:block-entry",
    "model": {
      "modelId": "jr_four_light:head",
      "placement": {
        "kind": "ground",
        "pose": {
          "x": 10.0, "y": 65.0, "z": 20.0,
          "rotationX": 0.0, "rotationY": 0.0, "rotationZ": 0.0, "rotationW": 1.0
        }
      }
    }
  }
]
```

这是字段片段：`primarySignalId` 必须换成该世界已存在的固定闭塞或保护信号 ID，模型必须覆盖它可能输出的全部外观名。
附属设备必须有模型，也可使用前述 rail 摆放。只能直接绑定主信号，不允许附属设备串联或绑定进路显示器。
`attachedSignals` 缺省为空，该字段不单独升版；使用上文所述 current schema，没有旧接口适配。

主信号变化时只更新它关联的显示设备；每台设备使用自己模型的外观映射和 `default`，不重新计算信号。
移动或改绑附属设备仍保留其模型操作对象，只提交新位置或新外观；换模型才替换对象。
删除主信号前，须在同一草稿中删除或改绑它的附属设备，否则验证拒绝；删除附属设备不删除主信号。
这些操作均通过下面的现有编辑流程，不另建一套存档或资源管理器。

### 导出、验证与应用

权限为 `simplesignals.admin`（默认 OP），玩家和控制台均可使用。world 参数是已加载世界的名称或 UUID。

```text
/simplesignals inspect world
/simplesignals export world station
/simplesignals validate world station
/simplesignals apply world station
```

`export` 写出 `plugins/SimpleSignals/drafts/station.json`，目标已存在时拒绝覆盖。
在导出后编辑这份草稿，再 `validate`，最后 `apply`；不要直接修改运行中的 `worlds/` 正式存档。
草稿是完整定义集合，删掉一个既有对象即申请删除它，不是只合并所写字段。

保留草稿的全局 `definitionRevision` 不变，它表示导出基线；修改既有对象时提高该对象自己的 `revision`。
修改区域后可以保留原进路表；引用旧区域版本的表会按当前边界与拓扑逐条重验，仅有效进路可运行。
新建或手动修改进路表应填写目标区域版本，不允许引用尚不存在的未来版本。对象身份、速度、模型 variant 与坐标格式沿用现有 JSON。
apply 成功后插件自动把全局 revision 增加 1；原草稿再次 apply 会因基线过期而被拒绝。

`validate` 检查定义、引用、拓扑、规则及模型配置，但不创建模型、不写正式文件、不占用资源，
也不保证 apply 时线路仍可编辑。
正式 apply 重新检查，并在被阻挡时显示 owner、revision 和冲突范围。编译、读写文件和正式应用都在异步线程执行。
无变化草稿不是 reload 命令；本批不提供损坏世界重置或强制覆盖。

无进路外观，逐进路映射允许暂缺并提示补配，未配置进路使用所选无进路外观，不猜测占位映射。模型显示仍需真实 Folia 服务器及客户端资源包验证。

### 模型包与默认显示

SimpleSignals 模型包需要显式提供 `default`，用于初始尚无信号结果或信号状态不可用时的显示。
这项要求不适用于主插件通用模型、列车模型或其他附属插件；内部 `Unavailable` 信号状态也不改名。
有正常结果时使用其 `modelVariant` 指定的外观，名称拼错或映射缺失应报错，不静默改用默认外观。

例如，模型已定义 `lamp` 及 `dark/red/green` 命名场景时，外观映射写为：

```yaml
default:
  lamp: dark
variants:
  stop:
    lamp: red
  proceed:
    lamp: green
```

这些名称没有内置灯色或速度含义。每个映射都是完整选择，不是叠加到 `default` 上的增量；
作者也可以用 `default: {}` 明确选择模型基础外观。
以上是外观映射片段；完整包还需入口和部件文件，见已实现的[模型包格式与加载](../.trellis/spec/simple-signals/backend/model-packages.md)。
加载器支持多个模型、包内共享/内联部件、命名静态场景、完整外观校验和左右摆放预设。
场景无需时间字段，导入参数沿用列车的合并语义。读取返回不可变结果，后续外观名称查询不访问文件。
完整示例位于 [demo_signals](src/test/resources/model-packages/demo_signals/manifest.yml)。设备摆放存档见上文。
完整行为及测试要求见[信号模型显示契约](../.trellis/spec/simple-signals/backend/model-presentation.md)。

另有包含实际网格、贴图及距离敏感JS规则的 [JR 四灯包](examples/jr-four-light/README.md)，
使用用户提供的灯头，分为完整服务器信号包和客户端资源包；不会替换普通纸张，也不包含立柱。
规则的参考减速度是包声明的0.6m/s²，G明确不附加限速；信号规则不授予资源或代替ATO实际制动。
复制完整`signal-packs/`内容后，Signal Wand可选择包中声明的类型，不需要另写规则或`signal/`文件。
客户端仍需单独安装匹配版本资源包。离线测试不等于真实客户端画面已验证，具体档位和步骤见包说明。

### 模型摆放

同一模型支持轨道附着和地面摆放。轨道附着保存从 A 端起算的距离及 AB/BA 方向，偏移的前后左右按
记录的方向解释；地面摆放直接使用世界位置和旋转，不应用轨道偏移。两者都不改变逻辑信号的控制位置。

模型可以提供“轨道左侧”“轨道右侧”等摆放预设，并声明是否跟随轨道坡度和超高。玩家选择预设时，
将有效偏移、旋转和倾斜选项复制到设备；玩家明确设置优先，否则用模型默认，均未指定时保持竖直。
以后修改模型包里的预设不会移动已有设备，只有主动重新应用预设才采用新值。

Signal Wand设置页选择预设名，创建时从实际选定的模型复制参数，模型没有该名字则明确拒绝。现场选中的设备可数值编辑位置、XYZ旋转及轨道倾斜；ground编辑绝对世界位置，rail编辑局部偏移，不改逻辑绑定、模型或轨道锚点。拖拽、直接修改附着轨道/方向及任意模型样式参数仍未提供。坐标约定中，改变附着方向会按原偏移重新定位；只旋转模型保持摆放点不变。摆放预设与表示灯色等外观的`modelVariant`无关，切换灯色不会改变位置。
目前已实现预设应用和纯位置/旋转计算，使用现有曲线及主插件的 `ModelPose`，并通过真实曲线测试。
位置在异步绑定准备时计算并保存，不随信号更新重新采样曲线。地面摆放不查轨道。
正常状态更新只处理变化设备，并跳过场景相同的提交；Minecraft 实体由主插件调度，不让物理等待显示。
定义编辑保留仍使用同一模型的设备；只改规则不重建模型，位置/旋转变化向原对象提交新姿态。
只有新增、删除或更换模型的设备执行创建/关闭，工作发生在提交锁外。显示序号跟随保留对象继续递增，
旧配置的回调失效后不能覆盖新画面。尚无新信号结果时仍按模型包的 `default` 显示，不沿用旧放行外观。
设备删除、世界卸载和插件停用会关闭模型。停用先失效绑定，再异步清理，完成结果可通过
`modelCleanupCompletion()` 观察；完成前不能停用 JavaRailways 主插件。

实现契约见[保护区域信号与进路显示合同](../.trellis/spec/simple-signals/backend/protection-region-signal-selection.md)。
在线编辑范围的计算见[定义编辑影响合同](../.trellis/spec/simple-signals/backend/definition-edit-impact.md)。
命令和草稿规则见[管理命令合同](../.trellis/spec/simple-signals/backend/authoring-commands.md)。
