# JR 四灯式信号包

这是用于正式游戏验收的统一信号包，不是 smoke 规则：`signal-packs/jr_four_light/` 包含元数据、
完整模型、JS 逻辑和玩家可选择的信号类型；`resourcepack/` 提供共用外壳、四种亮灯模型和共用贴图。
**只有灯头，没有立柱。**
来源是用户提供的独立模型工作区，其中的 `models/jr_four_light/pack/assets/jr/`；外部原文件未修改。

## 外观与客户端资源

模型 ID 是 `jr_four_light:head`，动画名为 `lamp`。四个外观 `stop`、`caution`、`slow`、`proceed`
分别引用同名场景和 `jr:four_light_signal_<名称>` 物品模型键；灯头显示红灯、黄灯、黄绿灯、绿灯。
每个键通过 `assets/jr/items/` 中的现代物品定义引用 `assets/jr/models/block/` 的模型，
再引用共用 `assets/jr/textures/block/four_light_signal.png`。
没有覆盖 `minecraft:paper`，没有 CustomModelData 别名。

灯头在共同父节点下分为两个可见部件：`jr:four_light_signal_housing` 保存外壳、遮檐及四个暗灯，
不覆盖自然光；另一个部件只显示当前点亮的灯面，基础外观及四个完整场景均设置
`brightness: {block: 15, sky: 15}`。YG 使用同一个亮灯部件显示黄、绿两片灯面。
修改亮度时应同时修改基础外观和各场景；场景外观是完整替换，不逐字段继承。
亮灯面向前错开0.05模型单位（3.125毫米），避免与暗灯共面。亮度只影响显示，不照亮世界。
这比整件灯头多一个显示部件，但仍只有一个设备和模型handle，不增加JS求值或区间扫描。

`default: {lamp: stop}` 是本示例作者选择的初始/不可用画面，不是通用加载器内置的红灯规则。
外观名对通用加载器没有限速含义；本包 JS 明确选择速度操作和外观，Basic/ATO 仍独立执行资源授权、
线路限速与车辆实际制动约束。显示 `proceed` 本身不授予列车行车资源。

## 本包规则

玩家可选择的 `signalType` 是 `jr_four_light:block`，引用 `modelId: jr_four_light:head` 和
`logicId: jr_four_light:block`。固定闭塞与保护区域入口共用它，不在 JS 中特判区间类别。

- R / `stop`：入口速度 0。
- Y / `caution`：入口速度不超过 45 km/h。
- YG / `slow`：入口速度不超过 65 km/h。
- G / `proceed`：调用 `clearSpeedLimit()`，不附加信号限速，不是给定一个很大的速度。

`logic/block.yml` 声明参考减速度 **0.6 m/s²**。宿主准备时取整个受控区间最高静态有效速度 `v`，
按 `v² / (2a)` 编译并缓存扫描距离。它是本包作者的简化设计参数，不是日本铁路通用标准，也不指令
ATO 以 0.6 实际制动。制动模型未包含坡度、制动建立或驾驶员反应时间，不能保证任意弱制动车辆的能力。

自身区间占用时立即输出 R。其余情况下，JS 用显式栈遍历已选或无需选择的前视分支；未选支路不参与。
在距当前入口 `d` 米处遇到目标速度 `vt` 时，按 `vt² + 2ad` 收紧入口允许速度平方，综合所有相关目标，
再向下选取上述固定档位：达到参考速度才 G，否则依次尝试 YG、Y，连 Y 都不满足时 R。
`distanceMeters` 已是从当前入口起算的绝对沿轨距离，兄弟分支的长度不相加。

前方区间占用、保护进路未 ready，均在其入口作为零速目标；前方信号有限限速同样参与。
明确不限速或没有信号对象不阻止继续查看更远的短区间。所有候选后继均未选中或没有任何已知后继/终止说明时，
在当前已知区间出口设置零速目标，不能猜测路线畅通。宿主已将保护区域本身的未授权/未就绪状态收紧，本包不申请或伪造进路。

`track-end`、`route-unresolved`、`topology-unavailable` 以及 `cycle` 按 `end.distanceMeters` 作为
零速目标；把环截断处视为停车目标只是本包的保守政策，不代表那里是物理尽头。`distance-limit` 只是扫描结束，
不额外制造停车边界。缺少必需的计算扫描参数、未知终止原因或 JS 异常由现有运行时拒绝，不保留上一轮许可。

四灯没有 YY，也不通过可变速度冒充固定 Y：**极短的空闲区间可能同样显示 R**，而且这个 R 可能向相邻短区间
传播。这是本包固定档位的表达能力限制，不是声称已经模拟日本所有线路的现示设计。需要低速通过这类布局时，
应另行设计有相应低速档位的信号包，或调整闭塞布局，不由通用 Kotlin 层偷偷放宽。

资源包只声明 Minecraft **1.21.11、资源格式 75.0**，使用 `min_format`/`max_format`。
版本来自本机缓存的该版本 `version.json`，不是原始资产目录的版本推断。

## 原始模型的适配与摆放

原始几何的 Y 为 0..42；Minecraft 1.21.11 的方块模型元素坐标要求
[-16,32]（[该版本的模型文档](https://docs.fabricmc.net/1.21.11/develop/blocks/block-models)）。
因此示例副本只把每个元素的 `from`、`to` 的 Y 减 16，使范围成为 -16..26。
除亮灯面的分层偏移外，形状、UV、材质、GUI 配置保持原样；PNG 逐字节复制。
灯头没有缩小；原完整网格已拆为共用外壳与亮灯层。

宿主物品显示采用 `NONE`，不使用原模型的 GUI 旋转/缩放。按方块模型的中心 (8,8,8)
和 16 模型单位/米换算，减 16 后灯头基底 Y 为 -1.5 米；共同父节点的 `offset.y: 1.5`
把基底恢复到附着点高度。保持单位缩放，因此灯头高 2.625 米、宽 1.25 米；这是资产的原始
比例，并非声称与实物尺寸一致。需要架高时由设备摆放偏移决定，本例不虚构立柱。

原始灯面朝 -Z，共同父节点使用 `rotation.y: -90`。客户端ItemDisplay绘制还会追加局部Y轴180°旋转，
所以实际顺序是“摆放姿态 × 部件姿态 × 客户端Y180° × 源灯面方向”，最终朝向摆放参照的-X（来车方向）。
此前+90°的适配及离线测试遗漏了客户端这一步，会将灯面反转；本包修正不改变其他模型的通用坐标算法。
轨道坐标的有向前方为 +X、上方为 +Y、右侧为 +Z。`left`/`right` 预设仅给出 -2/+2 米侧偏，
不再次旋转模型。AB/BA 附着方向改变时，左右与灯面一起跟随方向。默认不跟随轨道坡度/超高；
玩家将来可以覆盖。地面摆放也使用这份部件定义，但不应用轨道预设。

以上是现有模型与轨道姿态的离线推导和测试，**尚未由真实客户端画面验证**。
客户端额外旋转的直接依据为已核对的26.1.2客户端字节码，不以服务器测试依赖版本冒充客户端运行证据。
重新加载包后，所有引用该灯头的设备都使用修正后的朝向；若曾手工给实例加180°补偿，需要撤销该实例补偿。
本包不会猜测或自动改写已保存的方向/旋转；轨道摆放仍使用放置时所选方向，地面摆放仍使用其保存姿态。

## 文件放在哪里

将 `signal-packs/jr_four_light/` 整个目录复制到
`<SimpleSignals dataFolder>/signal-packs/jr_four_light/`，确保 `pack.yml` 位于该包根部。
本目录的 `pack.yml` 只保存元数据，`model/head.yml`、`logic/block.yml` 与配对的 `logic/block.js`、
`signal/block.yml` 分别定义模型、逻辑与可选择类型。不再同时安装旧的 model-only 灯头示例。
资源包则把 `resourcepack/` 本身放到客户端资源包目录，或将其内容打包，使 `pack.mcmeta`
位于资源包根部。资源包与服务器模型包是两个不同的目录，不可互相替代。

插件启用时异步发现这些目录；复制文件后需重新启用插件，当前没有包热重载。
在Signal Wand创建入口选择`JR 四灯式主信号`，也可在设置中将它设为可空的区间默认；保护入口仍每次选择用途和类型。
灯头声明了根局部选取盒，可右键模型进入编辑与只读诊断；选取盒不是客户端逐像素网格命中。
也可按手工两步流程绑定入口后摆放；
也可通过 `export → validate → apply` 应用草稿，逻辑设备的 `type` 为 `jr_four_light:block`，
不在设备中重复指定 model/logic。摆放格式见[插件说明](../../README.md#保存与编辑)。
单纯复制信号包不会自动创建区间或设备，也不会赋予行车授权。计算扫描要求受控区间每条轨道均有有限静态有效限速，
缺少速度时准备失败，不猜测线路速度或回退为固定距离。
客户端需单独安装资源包；没有自动 ZIP 安装或向玩家发送资源包。

## 验证范围

`JrFourLightDemoTest` 直接读取这里的示例，不复制另一套测试专用资产：

- 从同一份统一信号包加载完整模型、四个场景、默认外观、左右预设。
- 物品定义 → 方块模型 → PNG 引用完整，PNG 可以解码；真实 1.21.11 元数据 codec 接受包格式。
- 元素坐标在允许范围内，原始宽高与基底高度不变；两个部件共用轨道 AB/BA 姿态。
- 外壳与暗灯为自然光，只有当前亮灯获得15/15亮度；灯位、UV及前后分层对应。

姿态回归显式纳入客户端额外Y180°，检查AB/BA、左右侧偏及地面摆放的灯面方向；它仍不是实际客户端渲染测试。

`JrFourLightSignalPackTest` 直接加载本目录并在真实 GraalJS 中运行交付的 JS，验证四种输出、连续短区间、
选路/保护分支、明确不限速、环及其他终止原因、固定档位阈值和错误输入。输入使用公开的实际 JSON 形状；
这不是独立实现的一套测试规则。`SimpleSignalsWorldRuntimeManagerTest` 另以真实世界准备、区间观察和
同 epoch 下游输出运行本包，覆盖混合长度链的 G/YG/Y/R、极短区间的 R 传播及清空占用后的下一帧更新。
生产绑定测试另行验证公开显示服务的调用与卸载清理，使用记录式服务而非实际客户端。
这些回归仍不证明客户端已安装资源包，或完整的 Folia 显示生命周期和真实画面。
