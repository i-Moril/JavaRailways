# 笔记更新规则

## note 格式建议
- 每条 note 记录 `importance`、`L`、`D`。
- `L` 初始为 `1`，表示该 note 的累计帮助程度。
- `D` 使用 `ai_notes/today.txt` 中的当前 dev date。

## today.txt 规则
- 格式固定为 `YYYY-MM-DD N`。
- 如果今天晚于 `today.txt` 中记录的日期，则将日期更新为今天，并将 dev date 加一。

## 何时更新 L 和 D
- 某条 note 对当前任务有明显帮助：`L + 1`，并把 `D` 更新为当前 dev date。
- 某条 note 被使用但对任务没有帮助：不更新 `L` 和 `D`。

## 何时更新内容
- 只要发现 note 内容与当前代码或项目结构不符，就应当修正或删除。
- 如果只是修正过时内容，但该 note 对当前任务没有帮助，则不要顺便更新 `L` 和 `D`。

## 内容边界
- 记录稳定事实、索引、模块职责、协作规则。
- 不记录具体实现步骤、易变的代码细节、个人信息、运行环境信息。
- 简单阅读代码已足够时，可以只记录入口索引，避免冗长笔记。

## 初始化约定
- 新建 note 默认先写精简内容。
- 优先维护 `main.md`，保证后续 Agent 有单一入口可读。
