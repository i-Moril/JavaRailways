# 灯泡线的资源申请流程

这份说明只描述连续行驶、绕环后再次经过同一道岔的流程，不改变停车折返的处理。

## 如何工作

1. SimpleATO仍选择一条完整路线，但只申请前方一段资源。
2. 若这一段同时包含同一道岔的两次经过，或者下一次经过的道岔还被上一遍持有，Basic在取得资源、切换设备之前拒绝，并返回一个可先申请到的路线位置。
3. SimpleATO用已经编译的区间要求调整该位置：不能把申请截在保护区域内部，必要时退到入口外。然后至多立即重试一次。
4. 第一遍获得资源并完成道岔准备后，列车行驶；车尾通过释放位置，Basic按原有队列释放。
5. 回到同一道岔时，申请的是相同资源身份，但按第二遍所需状态重新准备。第一次仍持有时，可以先取得第二次使用之前的资源，不能取得第二次道岔使用；第二次准备完成以前，授权不会越过新边界。

Basic返回的位置是申请建议，不是行车授权。实际权限始终以成功提交的grant为准；没有改成“请求很长、宿主偷偷授予一小段”。

例如，50m长的列车在路线340m和约510.71m处两次经过同一道岔，第一次授权只到350m。
若请求到650m被无条件拒绝，列车最多走到350m，车尾只能到300m，永远无法释放340m处的第一次占用。
现在Basic给出第二次使用前的上限，约510.70m；若区间要求允许，ATO可以先申请这段，列车继续前进，让车尾清除340m处的占用，
然后再申请第二次道岔使用。期间道岔没有提前切换，第一次占用也没有提前释放。

## 保护区域如何分辨两次经过

同一保护区域在完整路线中有两组入口、出口路线位置。信号先参考最早尚未清除且已经申请的一次。
已有的区间观测会报告“该列车车尾从这个出口离开”的LEFT事件；据此完成第一次的信号关联，再处理第二次。
空区间快照不能代替这个事件，也不能用车头已经出去推断车尾已清除。

这不增加资源释放队列或每tick的信号脚本调用。真正释放仍由Basic唯一的车尾游标和队列负责。
在线编辑无关定义需要保留未受影响进路的经过记录。当前交接已实现，但审计复现了两个未解决问题：
交接期间旧观测仍可能推进记录，以及新观测首帧可能遗漏真实离开事件。这两个问题留待下一批修复，不能视为已完整验证。

## 边界与非目标

- 无状态菱形交叉可重复查询，并按同一个身份保留到本次申请范围的最后一次通过；它没有道岔选择状态。
- 太短的环线如果不能在第二次入口前让车尾清除第一次占用，不能通过提前释放或切换来强行放行。玩家需提供足够空间或改变线路/运营安排。
- 本批不改变闭塞存档、双向闭塞是否共享同一token的定义、灯色规则、渲染或脚本接口。
- 自动化测试和真实Minecraft/Folia运行验证是两件事；测试通过不表示已经完成实服验证。
