# Cabin route style

This independent style bundle exports `cabin-route.route` through `displays.yml`. Its XML is `displays/cabin-route.xml`; use a 4:1 physical screen. S100 references the bundle instead of embedding it. Extract `examples/models/cabin-route-style.zip` into `plugins/Decorations/styles/` (creating `styles/cabin-route/displays.yml`) and restart Decorations and include the accompanying JavaRailways display-geometry font in the client resource pack.

The fixed 800 × 200 canvas has a colored 336-pixel left information panel and a single white 464-pixel right route panel (42%/58%). Line/class share the first row; destination prefix/value share the second. The main station name uses a nominal 48-unit size (minimum 40), destination 32 (minimum 28), line 28 (minimum 24), class 22 (minimum 20), opening side 24 (minimum 22), and transfer caption 20. Principal fields stop shrinking at those minimums: long values are split into bounded pages, preferring whole English words, and advance every 60 source ticks (3 seconds). The first language cycle starts at the first page; values longer than five pages continue in subsequent cycles. All text remains available over time rather than becoming arbitrarily small. The old browser demo was taller in proportion; the 4:1 template compresses whitespace rather than stretching letters. Both languages use the same geometry and rotate every 300 source ticks (15 seconds at normal simulation speed), independent of player locale. The left shows line, class, destination, current/next station, effective opening side and transfer caption; unknown facts stay blank.

Metadata conventions:

- Current run `metadata.line.{zh,en}` may override the line name; otherwise use current infrastructure line `metadata.name.{zh,en}`. If both are missing, the line name is blank.
- Run `metadata.class.{zh,en}` supplies the translated class.
- `operational.values.destination` is a string or `{zh,en}`. An explicitly authored value takes precedence (including empty string or null). When the key is absent, the host supplies the actual current run's terminal station name, using station `metadata.name` when available. It never takes the final stop of a later run in the operational trip.
- Station names use `metadata.name` (a string or `{zh,en}`); an unnamed station has no text label. Optional `metadata.transfer.{zh,en}` supplies the left transfer caption.
- Station `metadata.transfers` is an array of infrastructure line IDs. Each is looked up in `ctx.data.lines`; line `metadata.badge` is a string or `{zh,en}` (compact logo text), falling back to line `metadata.name`, then the line ID. Line `metadata.themeColor` and `line.color` use `#RRGGBB`.
- Localized objects fall back from the active language to Chinese, then English. Unknown values do not manufacture names or destinations.

The route uses the full ordered `operational.stops`, authoritative `stationIndex` and `phase`; it never treats `completed` as physical departure. Up to two passed calls and eight total occurrences are shown, with no duplicate station-ID matching. Passed circles, labels and connections are gray; PASS calls have no center and gray labels. The next STOP/TERMINAL center alternates on/off every 10 source ticks by updating one stable span between the dot and empty text; it is not removed from the frame. Unknown/finished progress leaves the route blank. Short routes are centered. Omitted history/future produce continuation stubs; unresolved future also keeps a continuation stub without inventing calls. An at-station cursor remains current until the domain reports departure.

Station names run vertically below the line in up to two columns, centered together under the station marker. Each column holds four characters in both languages; names longer than eight characters end with an ellipsis. Chinese nominal size is 22; English is 20, keeping four rows inside the 92-unit name area. The 4-unit column gap keeps the complete block within the 48-unit station pitch. English currently uses upright characters, not the browser demo’s rotated Latin text runs: the library has no text rotation API in this slice. This is an explicit remaining difference, not a claim of identical browser/game layout. Transfer badges stack vertically above the line, up to three per call, followed by a `+` for further transfers. The left transfer caption can still describe the full set. Effective side comes only from `ctx.data.display.openingSide`, with translated this/opposite/both/none labels; missing installation/direction facts produce no side label.

Backgrounds, rails and badge fills use explicit `<rect>` geometry with independent left/top/width/height, rendered from a measured vanilla Minecraft solid glyph through the renderer’s transform. No tiled square backgrounds or custom rectangular font glyphs remain. Only circular E004 ring and E005 dot use `javarailways:display_geometry`; their measured one-native-font-pixel ink-center offset is compensated by `size / 9` in X. Text uses a conservative width estimate because SimpleDisplays has no text-metrics API or clipping. Per-character route names and bounded transfers remain below the 1,024 draw limit. Exact pixel fitting, resource-pack font loading, overlap depth and in-game legibility need unified game acceptance; the resource diagnostics do not establish client acceptance.

Drawables use semantic DOM IDs: named panels/labels, `(serviceId, runId, callId)` plus role for route calls, and stable character slots for vertical station text. Fixed CSS `z-index` layers are background0, rail10, ring/badge-background20, dot21 and text30. Host entity reuse is by key, and layer depths are independent of frame length or order. Requires the keyed-frame SimpleDisplays API together with the matching Decorations/JavaRailways versions.
